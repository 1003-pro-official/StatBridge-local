연도별로 다시 조회해 전 범위 검증을 통과한 자료로 CSV를 교체했다. 갱신 후 **820개 전체 관측치의 식별자·값·단위가 최초 전체 실조회와 일치**했다. 별도 `audit_values.py --live` 재실행에서도 기존 **45개 표본 모두 일치**, 원본 PDF 금리 표본 **10개 모두 일치**했다. 이 결과를 349개 전체 표의 전수 정합성으로 확대하지 않는다.

기존 CSV는 `.venv/cache/kosis-snapshots/<표ID>-<이전 SHA256>.csv`에 보존했다. 같은 폴더 JSON에는 교체 전후 해시, 변경 건수, 원천 최종변경일, 조회시각이 있다. 모두 Git 제외 대상이다. 백업을 다른 보관 위치로 이전하기 전 `.venv/cache`를 정리하면 과거 자료를 잃을 수 있다.

## 앱과 갱신 도구의 변경

> 범위: 이 디렉터리와 `tools/refresh_kosis_snapshot.py`만 포함한다. 앱 화면의 자료 버전 표시 변경은 별도 PR로 분리했다.

- 기존 실행 근거 화면에 **조회 출처, 조회 시각, 원천 최종변경일, 관측치 SHA-256**을 표시한다. 조회 시각은 읽은 시각이며, 원천 변경일과 다르다.
- 같은 통계표의 다른 계열을 합친 경우에도 각 계열의 버전을 각각 표시한다. 기존 저장 워크스페이스의 데이터 스냅샷 기능을 그대로 사용한다.
- KOSIS 키가 있으면 실시간 우선, 키가 없으면 로컬을 사용하는 기존 경로를 유지한다. 이번에 별도 최신 조회 버튼이나 다른 기관 자료를 추가하지 않았다.
- 갱신 도구는 모든 지정 표의 조회·검증을 마친 뒤 교체에 진입한다. 빈 응답, 중복, 식별자 차이, 관측치 누락·추가, 단위 변경, 비유한 수치는 거부한다. 교체 전 해시별 백업·복구 명세를 남기고 **파일별 원자교체**를 수행한다.
- 이 도구는 기존 관측 범위의 값 갱신용이다. 최신 월·신규 분류 추가는 자동 승인하지 않는다. 신규 관측치를 넣을 때는 기간·분류 메타데이터와 완전성 검증을 함께 확장해야 한다. 여러 파일에 대한 전원 장애 수준의 묶음 트랜잭션은 제공하지 않는다.

```bash
# 기존 환경의 Python 사용. --live는 실제 KOSIS 요청, --apply 없으면 검증만 수행.
python tools/refresh_kosis_snapshot.py DT_633Y002 DT_633Y004 --live
python tools/refresh_kosis_snapshot.py DT_633Y002 DT_633Y004 --live --apply

# 수집된 공식 원본을 비교 근거로 전체 범위 산출물 생성.
python research/kosis-bok-reproduction/pilots.py
```

`pilots.py`는 비교 기간·분류 코드·단위·필요 셀 수·계산식을 명세로 남긴다. `RATE-FULL`, `CREDIT-FULL` 산출물은 현재 이 스크립트로 생성한다. 자연어 한 문장으로 원본 템플릿을 자동 선택하는 앱 기능은 추가하지 않았다. 기존 질의집은 응용형이며 이 새 검증 결과를 그 질의의 자동 생성 능력으로 간주하면 안 된다.

## ESI의 과거 원본을 같게 만들려면

전체 기간·양 계열의 확보 문제와 공표 당시 수치의 확보 문제를 분리했다. 원본 2025년 12월 PDF 그림의 기준기간은 2003~2024년이며, 2026년 판본은 2003~2025년이다. 원본 ESI 설명에도 순환변동치의 전체 시계열을 매월 수정한다고 명시되어 있다. 따라서 현행 KOSIS의 값만으로 과거 보고서와 항상 같은 수치가 나올 수는 없다. 이번 14개 개별 불일치의 원인을 이 설명만으로 확정하지 않는다.

현행 자료만 쓰는 제약을 유지한다면 이 그림은 **현행 자료 기반 재작성**으로 제공해야 한다. 과거 원본과 같은 값을 요구하면 그 공표시점에 보관한 KOSIS 스냅샷이 추가로 필요하다. 앞으로는 주요 공표일에 조회한 응답을 시각·조건·해시와 함께 보관하고, 분석별로 그 자료 버전을 고정해야 한다. 지금 보존한 두 지급서비스 표의 이전 파일이 그 시작이며, 이미 놓친 ESI 과거 빈티지를 현재 조회만으로 복원하지는 않는다.
