# 조사·질의집 검증 기록

2026-10-19, ai-assisted. 현재 작업 트리 기준의 점검이며 사람이 승인한 평가 골드나 블라인드 성능이 아니다. 비공개 평가 자료와 holdout 정답은 사용하지 않았다.

## 1. 수집·선별·원본 연결

- 기간: 2023-10-01~2026-10-19.
- 게시판 3개 목록 1,021건 → 자료군·연도별 대표판 및 개편 자료 70건 → PDF 75개, XLSX 21개 수집. 수집 실패 게시물은 없었다.
- PDF 3,384페이지에서 규칙 기반 캡션 후보 917건. 후보가 발견된 판본은 65개이며, 자료군·캡션 문자열 중복을 제거하면 410개다. 문구가 같은 다른 그림이나 문구가 다른 같은 유형을 구별한 숫자는 아니다.
- 기존 4,027건을 모두 어휘 기반으로 선별: 통계표 후보가 있는 770건, 제목만으로 매핑 불가 3,257건. 원래 결과물ID를 유지했다.
- 36개 제작 대상의 원본 캡션·PDF 물리 페이지를 텍스트로 대조했다. 추가로 금리 PDF p.3, ESI PDF p.9, 가계신용 PDF p.7, 기업경영분석 책자 PDF p.12를 렌더링해 위치와 표·그림 구성을 확인했다. 전체 PDF 시각 검수 또는 사람 검수 완료가 아니다.
- 장문 기업경영분석 PDF의 추가 텍스트 추출에는 설치된 PDFium을 사용했다. 기존 캐시에 있는 텍스트는 재사용했으므로 pypdf·PDFium의 줄바꿈 차이로 재수집 시 캡션 후보 수가 달라질 수 있다. 원본 파일 해시를 함께 보존했다.

## 2. 실제 질의·조회·출력

로그인한 FastAPI TestClient에서 `/api/query` → 현재 MCP 공유 서비스의 로컬 CSV 조회 → `/api/output`의 빠른 출력 → `/api/table/export` XLSX를 실행했다. 전송된 요청의 실제 세션과 조회 계획을 확인했다. MCP wire 프로토콜이나 브라우저 UI의 클릭·렌더링을 검증한 것은 아니다.

| 항목 | 관측 결과 |
|---|---:|
| 제작 대상 | 36개 유형 |
| 입력 변형 | 업무형·표 ID 포함형 × 선그래프·표 = 144개 |
| 기대 계열·주기·기간·관측 수·렌더링·표·관측 요약·XLSX를 확인한 변형 | 96개 |
| 적어도 한 쌍의 그래프·표 입력을 확인한 유형 | 33개 |
| 기대 출력을 확인하지 못한 유형 | IIP-02, IIP-03, LOAN-01 |

성공 조건은 HTTP 200만이 아니다. 요청한 모든 계열을 한 번씩 선택했는지, 기대한 표·분류인지, 월/분기/연 주기와 시작·종료가 맞는지, 월 36·분기 12·연 3시점이 모두 있는지, 관측값이 숫자인지, 렌더링 계열별 점 개수가 맞는지, 그래프·표·요약이 있고 XLSX가 내려오는지를 확인했다. 잘못 선택된 계열은 출력 단계의 성공으로 합격시키지 않았다.

모델·벡터 검색·KOSIS 호출은 이 단계에서 비활성화했다. 따라서 CLOVA/OpenAI 모델을 사용하는 운영 환경의 성능으로 일반화하지 않는다. 모든 질의는 같은 프로세스에서 순차 실행했고, 마지막 `--verify`에서는 앞선 실행의 성공·실패 캐시를 재사용하지 않았다.

기본 빠른 출력의 관측 요약만 확인했다. 원본 문장의 원인·전망 해석, 별도 보고서 초안 모델, 참고 그림 첨부, 모든 차트 종류와 모든 내보내기 형식의 실제 질의를 검증했다고 주장하지 않는다. 이 질의집의 그래프 입력은 선그래프다.

초기 질의집의 원본 전체 재현 확인은 0건이다. 별도 후속 파일럿은 금리 78/78, 가계신용 260/260의 전체 수치 셀을 대조했다([해결 결과](해결결과.md)). 디자인까지 동일하다는 판정은 하지 않는다. 모든 질의집 사례는 계열 또는 기간을 선별한 응용형이며, 지수 수준과 증감률·일평균과 합계의 차이를 사례별로 기록했다.

대표 5개 유형(ESI-01, RATE-03, PRICE-02, CREDIT-02, PAY-03)은 별도로 실제 API 출력을 HTML·XLSX로 저장했다. 같은 세션에서 `set_table`로 소수점 1자리·최근 4시점·BOK-T01 양식을 적용하고 최신 revision으로 XLSX를 다시 내보내는 요청도 5개 모두 HTTP 200을 확인했다. HTML은 브라우저에서의 최종 시각 품질 검수까지 완료한 것은 아니다.

## 3. 실제 KOSIS 및 공식 PDF 수치 표본

`audit_values.py --live`는 기대 조건의 45개 계열에 대해 월 2025-12, 분기 2025-Q4, 연 2024의 한 시점씩 조회했다. 실제 응답의 출처 `kosis_api`와 비교 대상의 `local_csv`를 확인했다. 같은 시점·항목·분류·단위·수치의 일치를 대조했고 원자료 값은 공개 파일에 기록하지 않았다.

- KOSIS 응답 확인: 45개.
- 로컬 CSV 출처 확인: 45개.
- 초기 지정 시점 일치: 43개; 후속 갱신 후 새 실조회는 45개 모두 일치.
- 초기 불일치: PAY-01 전자지급결제대행 이용금액 합계, PAY-02 선불전자지급수단 이용금액의 2025-Q4.

불일치 2개는 시점·항목·분류·단위가 같고 숫자가 달랐다. 후속 전체 범위 대조에서 로컬 최종변경일 2026-09-13과 실시간 2026-10-18의 차이를 확인했다. 두 표를 해시별 백업 후 검증된 KOSIS 자료로 갱신했으며, 갱신 후 820개 전체 관측치가 실조회와 일치했다. 원천 기관의 개별 수정 사유는 확인하지 않았다. 이 표본 대조는 전체 기간·349개 전수 실조회가 아니다.

별도로 [2026년 8월 금융기관 가중평균금리](https://www.bok.or.kr/portal/bbs/B0000501/view.do?nttId=11065098&menuNo=201264)의 PDF 물리 p.3에서 2024-12·2025-12 두 열을 추출했다. 신규 저축성수신, 가계대출, 대기업·중소기업 대출, 잔액 총대출의 10개 셀은 로컬 CSV와 모두 일치했다. 두 자리 표시의 반올림 허용범위는 ±0.005%p였다. 다른 원본 그림의 모든 점을 수치 대조한 것은 아니다.

## 4. 저장소 필수 검증

원래 `.venv`는 Windows `Scripts/` 환경이며 `.venv/bin/python`이 없다. 기존 환경을 덮어쓰지 않고 `/tmp/statbridge-research-venv`에 Python 3.11.15 검증 환경을 준비했다. 주요 패키지는 프로젝트 지정 FastAPI 0.142.2, Pydantic 2.13.5, LangGraph 1.2.12, Plotly 6.9.0, MCP 2.2.0, Matplotlib 3.11.2를 사용했다. PDF 조사에는 별도 분석 패키지도 사용했으며 프로젝트 의존성 파일을 수정하지 않았다.

```bash
PYTHONPATH=src/backend:src/agent \
PYTHON_DOTENV_DISABLED=1 STATBRIDGE_HYBRID_RETRIEVAL=0 STATBRIDGE_JEV_ENABLED=0 \
MPLCONFIGDIR=/tmp/statbridge-mpl FONTCONFIG_FILE=/tmp/statbridge-fonts.conf \
timeout 900 /tmp/statbridge-research-venv/bin/python -m pytest -q tests eval/table-discovery/v4.1/tests

/tmp/statbridge-research-venv/bin/python eval/table-discovery/v4.1/scripts/validate_v41.py

/tmp/statbridge-research-venv/bin/python -m pytest -q research/kosis-bok-reproduction/test_reproduction.py
```

| 검증 | 결과 |
|---|---|
| 필수 Python 테스트 | 1,066 passed, 355 subtests passed, 경고 4개; 494.51초 |
| v4.1 검증기 | `VALIDATION OK`; 공개 holdout에 정답 유출 없음 |
| 조사 스크립트 회귀 테스트 | 7 passed |
| 프런트엔드 빌드 | 잠금 파일 기준 Linux 복사본에서 성공; 큰 청크 경고 |

초기 Python 수집은 MCP 의존성이 없어 실패했고, 다음 실행은 한글 폰트가 없어 인쇄 테스트가 실패했다. MCP와 공식 Noto CJK 폰트를 검증 환경에 준비한 뒤 위 전체 결과를 확인했다. 마지막 전체 테스트에는 일부 인쇄 경로의 한글 글리프 관련 경고 4개가 남았다. 샌드박스 안에서는 TestClient가 스레드 대기 상태로 멈춰 같은 검증을 샌드박스 밖에서 실행했다.

프로젝트에서 직접 실행한 `cd src/agent/frontend && pnpm build`는 Windows용 기존 `node_modules`에 Linux TypeScript 실행 파일이 없어 실패했다. 기존 설치를 유지하기 위해 소스·설정·잠금 파일을 `/tmp/statbridge-frontend-check`에 복사하고 그곳에서 아래 명령을 실행해 빌드 성공을 확인했다.

```bash
cd /tmp/statbridge-frontend-check
pnpm install --frozen-lockfile
pnpm build
```

## 5. 검토와 보관

별도 코드 리뷰에서 검증 결과의 무조건적 캐시 재사용, `prefer_local=True`의 원격 fallback 가능성, 렌더링 점 개수의 성공 판정 누락을 지적받아 수정했다. 수정 후 최종 144개 질의와 45개 실조회 표본을 새로 실행했다.

원본 PDF·XLSX, 원자료 관측값을 포함한 그래프·표, API의 실제 예측 계획·세션 결과, 테스트 로그는 공개 조사 명세와 분리해 `.venv/cache` 또는 `/tmp`에 보관했다. 공개 JSONL은 원본 위치와 기대 조건·질의만 담는다. 이 조사 결과를 기존 table-discovery/end-to-end 평가 점수와 합치지 않았다.

## 후속 해결 검증

지급서비스 갱신, 원본 전체 범위 파일럿 및 앱 자료 버전 표시는 [해결 결과](해결결과.md)를 따른다. 후속 전체 검증은 1,076개 및 355개 하위 테스트 통과, 최종 변경 범위/조사 검증은 22개 통과했다. 프런트 빌드와 v4.1 검증도 통과했다. 초기 144개 자연어 기능 점검과 전체 표 원본 수치 검증의 분모를 혼용하지 않는다.
