## 정확성과 실패 처리

- 원 관측값은 보존하며 표시 변환을 별도 상태에 저장한다. 데이터 fingerprint가 다른 명세는 복원하지 않는다.
- 기여도는 의미를 확인해야 한다. 누락을 0으로 채우지 않는다. 서로 다른 단위의 합산과 같은 축 표시는 거절한다.
- 전망 구간은 사용자가 지정한 제공 기간의 표시다. 미래값을 추정하지 않는다. 팬 차트는 공급된 하한·상한·수준·방법·출처가 있어야 한다.
- OLS는 같은 시점의 관측 쌍으로 절편을 포함해 계산한다. 회귀 관계를 인과관계로 설명하지 않는다.
- 범위로 잘린 값과 막대의 잘린 0 기준을 경고한다. 모델·JSON·입력 오류와 오래된 수정 버전은 기존 그래프를 유지한다.
- 연간 비교를 관측 행 12칸 이동으로 계산하던 오류를 수정했다. 월·분기·연의 실제 전년 동일 기간을 연결하며 누락과 0 분모를 제외한다.
- 실제 브라우저에서 숫자 형태 기간 코드가 첫 라벨로 반복되는 Plotly.js 현상을 확인했다. 렌더링용 비숫자 범주 키를 사용하고 원 기간 코드는 명세·표·hover에 보존한다.

## 폰트와 출력

PNG는 1200×720 논리 크기, 200DPI 기본 설정에서 2400×1440픽셀이다. 최대 출력은 32MP로 제한한다. SVG는 기본 윤곽선으로 다른 기기의 폰트 차이를 줄인다. 편집용 텍스트 SVG는 동일한 한국어 글꼴이 필요하다. PDF는 설치된 한국어 글꼴을 부분 내장한다. 글꼴을 저장소에 재배포하지 않는다. 글꼴이 없는 서버에서는 명확히 오류를 반환한다.

Matplotlib 인쇄 출력과 Plotly/ECharts 화면은 같은 숫자를 사용하지만 픽셀 단위로 동일하지 않다. 인쇄에서 지원하지 않는 비선형 선, 일부 구간 스타일·데이터 좌표 도형은 오류로 알린다. ECharts는 바이올린과 저장 이미지·도형·위치 주석·일부 구간 스타일을 지원하지 않아 미리보기 버튼 대신 이유가 표시된다. 출력 성공을 이유로 렌더러의 모든 기존 스타일을 지원한다고 판단하면 안 된다.

## 성능 실측

`scripts/benchmark_report_charts.py`의 Python tracemalloc 활성 실행 결과다. 프로세스 RSS나 브라우저 메모리는 아니다. 초기 글꼴·모듈 비용이 포함되어 항목 간 냉/온 조건도 동일하지 않다.

| 규모 | 관측치 | 출력 명세 구성 | SVG 렌더링 | Python 추적 peak |
|---|---:|---:|---:|---:|
| 소규모 | 60 | 2.051초 | 2.357초 | 48.64MB |
| 중규모 | 2,000 | 3.399초 | 0.244초 | 9.21MB |
| 대규모 | 20,000 | 25.417초 | 0.238초 | 43.87MB |
| 다중 패널 | 1,000 | 2.341초 | 0.777초 | 5.56MB |

12개 합성 템플릿의 명세 구성+PDF+PNG+SVG+JSON 생성은 각각 0.660~1.445초였다. 대규모 명세 구성은 실시간 수준이 아니다. 기존 지원 종류 검사와 직렬화 비용을 줄이는 후속 최적화가 필요하다.

ECharts는 필요한 차트와 SVG만 지연 로딩해 640.92kB(압축 215.38kB) 별도 청크다. 초기 전체 import의 1,117.88kB에서 줄였다. 기존 Plotly 중심 main은 4,937.28kB(압축 1,484.48kB)이며 번들 크기 개선은 남아 있다.
