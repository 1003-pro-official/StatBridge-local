## 결론

이번 점검은 실제 브라우저에서 수행했다. 테스트 통과나 코드 변경만으로 결함이 해결됐다고 판단하지 않았다.

## 우선 해결할 문제

### 1. P1 — ID 표기가 바뀌면 민간소비의 실제 계열이 달라짐

입력:

> 국내총생산에 대한 지출(원계열 실질 분기 및 연간) (DT_200Y110)의 민간소비를 2024년 1분기부터 2024년 4분기까지 분기별로 보여줘.

| 표기 | 화면 계열명 | 2024Q1 화면 값 | 2024Q4 화면 값 |
|---|---|---|---|
| `(DT_200Y110)` | 국내총생산에 대한 지출(원계열 실질 분기 및 연간) | 552,333.4 십억원 | 598,632.7 십억원 |
| `[DT_200Y110]` | 국내총생산에 대한 지출(원계열 실질 분기 및 연간) · 민간 | 274,316.3 십억원 | 279,591.5 십억원 |

괄호 질의는 민간 분류가 표시되지 않으며 대괄호 질의와 다른 자료를 반환한다. 괄호 결과의 정확한 분류명을 별도 원자료로 확인하지 않았으므로 이를 특정 GDP 항목으로 단정하지 않는다. 카탈로그 DT_200Y110에는 ‘민간’ 분류가 있음을 화면에서도 확인했다.

`canonical_request_planner.py`의 ID 연결 정규식은 여전히 대괄호만 처리한다. 표 ID만 맞추는 것에 더해 사용자가 지정한 민간 분류와 조회 계획·반환 자료가 일치하는지 검증해야 한다. 두 GDP 계열 수치는 이번에 KOSIS 독립 대조를 하지 않았다.

완료 기준: 괄호·대괄호·정식 표명 질의가 같은 민간 분류와 자료를 반환하고, 분류·주기·단위를 화면에서 확인할 수 있어야 한다.

### 2. P1 — 분기 자료가 1~4월 위치에 놓임

입력:

> 예금은행 대출금리(신규취급액 기준) (DT_121Y006)와 국내총생산에 대한 지출(계절조정 실질 분기) (DT_200Y108)을 2024-01-01부터 2024-12-31까지 각각 원래 주기를 유지해서 비교해줘.

월별 12개·분기별 4개 관측치는 유지되고, 다른 단위·주기여서 분리해야 한다는 안내도 나온다. Y축 단위는 연%·십억원으로 개선됐다.

그러나 렌더링된 SVG에서 월별 첫 네 점과 분기 네 점의 X좌표가 모두 `24.7, 56.03, 87.35, 118.68`이다. 월별 마지막 점은 `369.3`이다. 월의 202401~202412와 분기의 202401~202404를 같은 문자열 범주로 취급하는 문제다. 공유 눈금도 202401, 202403, …, 202411이다.

`plotly_renderer.py:50`의 shared_xaxes 설정은 separate 배치에서 주기를 확인하지 않는다.

완료 기준: 서로 다른 주기에는 독립 축과 ‘2024년 1분기’ 같은 표시를 사용하거나, 기준을 명시한 달력 좌표로 변환해야 한다. 원자료 ID와 표시 좌표는 구분한다.

### 3. P1 — 금리를 구성비로 정규화

입력:

> 예금은행 대출금리(신규취급액 기준)에서 가계대출과 기업대출을 2024-01-01부터 2024-12-31까지 월별로 비교해줘.

출력 선택에서 원그래프를 직접 선택했다. 앱의 자동 선택 사례는 아니다.

2024년 12월 기업 4.62 연리%·가계 4.72 연리%를 기업 49.46%·가계 50.54% 구성비로 표시했다. 금리 합계는 대출 전체가 아니므로 이는 대출 구성비를 뜻하지 않는다. 두 금리의 차이는 0.10%p다.

완료 기준: 금리·지수 등 비가산 지표를 구성비·합산 차트에서 제한하고, 같은 전체를 구성하는 항목인지 확인해야 한다. 선·막대 비교 같은 대안을 안내한다.

## 다른 남은 문제와 환경 제한

### 복합 편집과 모델 준비 상태

`제목을 검토용 생산자물가지수로 바꾸고 선 색상을 빨간색으로 변경해줘.`는 ‘제목 RGB 색상’을 확인하게 했다. `colorRequests.ts`의 절 분리·제목 우선 대상 선택이 남아 있다.

확정 후에는 OpenAI 연결 설정이 필요하다는 오류가 나왔다. 단일 `선 색상을 빨간색으로 변경해줘.`도 같은 설정 오류로 중단됐다. 따라서 이전의 ‘제목 색상 미지원’ 오류까지 같은 방식으로 재현했다고 주장하지 않는다. 현재 환경에서 모델을 사용하는 편집의 최종 성공 여부는 확인할 수 없다.

수동 제목 변경, 수동 차트 종류 변경, 자연어의 명확한 기간 변경은 성공했다. 기능별로 가능한 동작과 필요한 모델 설정을 먼저 안내하는 편이 좋다. 키 미설정 오류에 ‘보완할 수정 요소·추가 설명’을 요구하는 안내는 설정 문제를 해결하지 못한다. 수동 제목 변경 성공 뒤에도 이전 수정 역질문이 남는 사례도 관찰했다.

### 기간 처리와 공통 조회 복구

- `2024년 1월부터 12월까지 …` 및 `최근 5년 경제심리지수 추이`는 여전히 날짜 선택을 다시 요구한다.
- 2016~2025년 GDP 성장기여도는 처음에 두 계열 각 40개, 총 80개로 조회됐다. `기간을 2024-01-01부터 2025-12-31까지로 변경해줘.`는 총 16개로 갱신하고 편집 기록에도 실제 기간을 남겼다.
- 하지만 현재 기간 입력칸은 2020-01-01~2025-12-31이었다. `WorkspaceData.tsx:7`의 고정 초기값이 남아 있다.
- 생성한 그래프의 자동 제목은 빈 값이고 작업 제목은 ‘통계 그래프 편집’이었다. 과거의 ‘2016~2025년 자동 제목 유지’는 이번 조건에서 재현하지 못했다. 제목 생성·보존·기간 변경 정책을 다시 확인해야 한다.
- 모호한 대출금리+PPI 비교에서 신규취급액 표를 선택하면 ‘이 선택과 연결된 지원 통계표가 없습니다’가 나왔다. 안내대로 같은 선택을 다시 눌러도 진행하지 못했다. 역전 날짜를 숨기는 것만으로 해당 비교 흐름이 해결된 것은 아니다. 공통 범위 함수의 역전 검사도 코드상 추가되지 않았다.

### 보고서 설명과 파일의 근거

- 보고서 요약은 보이지만 PPI 변화량을 ‘0.42 2020＝100 상승’으로 설명한다. ‘0.42지수포인트 상승’처럼 지수 수준의 기준과 변화량 단위를 구분해야 한다.
- 핵심 인사이트는 ‘MCP 12개 행을 1개 계열로 변환’, 편집 후에는 제목 변경 로그다. 통계 해석과 처리 기록을 구분해야 한다.
- CSV는 데이터·시점·값·단위 4열이다. 표 ID·출처·조회 시점은 여전히 없다.
- 실제 PNG는 수동 제목·막대·단위·기간 눈금을 포함하지만 출처·DT_404Y014가 없다. 같은 상태의 PDF에는 `자료: kosis_api · DT_404Y014`가 있다. PNG는 `workspacePng()`의 클라이언트 렌더링, PDF는 서버 보고서 출력 경로를 사용한다. 파일 형식별 출처 정책을 일치시켜야 한다.
- 서버의 ‘내 저장 그래프’ 목록은 제목만 표시한다. 반면 새 브라우저 대화 목록에는 저장 날짜와 기록 수, 다른 PC에 자동 동기화되지 않는다는 설명이 있다. 두 저장 기능의 범위·시점 차이를 명확히 해야 한다.

## 확인된 개선과 정상 동작

1. 실행 근거 버튼이 창을 열고 분석/그래프 단계, 사용 표, 기간·관측 수를 보여준다.
2. 날짜 역전 질의를 지원 데이터 없음으로 표현하지 않고 요청 확인과 기간 수정으로 안내한다. 실제 정상 날짜로 바꿔 조회 단계까지 이어졌다.
3. 미지원 연체율을 명시적으로 확인 질문에 표시하고 입력한 기간도 유지한다. 나머지 두 지표만 출력해 전체 성공으로 표시하지 않았다.
4. 다른 단위·주기의 같은 축 결합을 막고 이유를 안내한다. 이번 혼합 출력의 각 Y축 단위는 맞게 표시됐다.
5. 수동 제목·차트 종류 편집을 대화 기록에 남긴다. Undo는 선그래프, Redo는 막대그래프로 복원했다.
6. 새로고침 후 분석 홈으로 돌아가며 기존 작업은 브라우저 대화 보관함에 남는다. 보관함에서 PPI 제목·막대·13개 대화/편집 기록이 복원됐다. 서버 재시작 복원과 구분한다.
7. PPI 총지수 2024년 12개월의 화면 전체 표·새 CSV는 이전 KOSIS 독립 대조 결과의 시점·수치·단위와 전부 일치했다. 이번에는 KOSIS를 새로 독립 조회하지 않았다.
8. CSV·PNG·PDF 실제 다운로드를 확인했다. PNG의 수동 제목·한글·막대·축 표시는 읽을 수 있었고, PDF는 1페이지이며 제목·단위·출처 텍스트를 확인했다.
9. 2027년 PPI 요청은 제공 범위를 안내하고 조회를 막았다. 미래 값을 생성하지 않았다.
10. 카탈로그는 349개 표와 대/중/소분류, 주기·단위·분류 정보를 표시했다.

## 제한과 남긴 상태

- OpenAI 키 미설정으로 모델 편집의 최종 성공은 확인할 수 없다. 설정을 변경하거나 키를 요구·노출하지 않았다.
- 전체 349개 표 수치·접근성·작은 화면·모든 차트 출력·실제 통신 장애·서버 재시작은 검증하지 않았다.
- 네이티브 날짜 fill이 화면 값만 반영하는 도구 문제가 있었다. 방향키로 실제 변경 이벤트를 발생시킨 뒤 버튼 활성화와 조회 성공을 확인했다. 이를 앱의 날짜 버튼 결함으로 분류하지 않는다.
- 새 그래프로 넘어갈 때 ‘이전 대화 저장 후 시작’을 한 번 선택해 검토용 서버 그래프가 1개 추가됐다. 기존 1/5에서 현재 2/5이며 새 항목은 ‘통계 그래프’다. 삭제하지 않았다. 브라우저 보관함에는 이번 검토 대화도 남아 있다.
- 코드·계정 설정·기존 저장 그래프는 변경하지 않았다. 문서 PR에는 본 보고서만 추가한다. 원자료·진단 증거와 임시 산출물은 저장소에 포함하지 않는다.

## 증거 보관과 담당자 확인 요청

DOM·조작·SVG 좌표 기록, 워크스페이스·금리 원그래프·혼합 주기 스크린샷, CSV·PNG·PDF 실제 출력과 PDF 렌더는 검토자의 로컬 산출물 폴더에 보관한다. 로컬 경로는 다른 담당자에게 작동하지 않으므로 본 문서에는 재현 문장·관찰값·확인 한계를 직접 기록했다. 임시 진단 파일·원자료·생성 출력 파일은 커밋하지 않는다.

담당자에게 요청하는 사항:

1. 대상 브랜치에서 F01~F03을 먼저 재현하고 실제 선택 분류·원자료 주기·차트 의미를 검증한다.
2. 각 수정의 담당자와 리뷰어를 정하고 위 완료 기준을 합의한다.
3. OpenAI 편집 설정을 준비한 환경에서 복합 편집을 재검증한다. 키 값은 문서·PR·로그에 남기지 않는다.
4. 수정 후 같은 12개 질의와 파일 출력·편집·복구 동선을 다시 확인하고, 공식 평가와 탐색적 UI 점검을 구분해 기록한다.
