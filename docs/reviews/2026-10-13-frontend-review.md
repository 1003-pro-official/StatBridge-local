# StatBridge 담당자 전달용 검토 보고서 및 PR 제안

2026-10-13 · ai-assisted · 사람 검토 전 진단 문서

대상: PM / Evaluation, Backend · Data · MCP, Agent · LLM · Frontend 담당자

## 1. 전달 요약

한국은행 직원의 통계 탐색·비교·보고서 작성 업무를 기준으로 프로젝트 목적과 실제 화면을 검토했다. 자연어 질의를 입력하고 분석하기, 조건 선택, 그래프 생성·수정, 저장·복원, 파일 내려받기를 수행했다.

현재 자연어 탐색과 3개 패널 편집 흐름은 프로젝트 방향에 부합한다. 다만 **요청과 다른 분류 선택, 월·분기 시간축 충돌, 금리를 구성비로 표시, 기간 변경 후 이전 제목 유지**는 결과를 신뢰하거나 보고서에 인용할 때 잘못된 해석을 유발한다. 이 문제를 화면 장식 변경보다 먼저 해결할 것을 제안한다.

생산자물가지수 총지수 2024년 12개월은 KOSIS 직접 응답·화면 표·다운로드 CSV의 시점·수치·단위가 모두 일치했다. 이 결과는 해당 계열과 기간에 한정하며 전체 서비스 정확도를 의미하지 않는다.

이 문서는 관찰 결과와 수정 제안이다. 담당 배정·우선순위·수정 범위는 사람의 검토로 확정해야 한다. 실사용 점검 당시 코드 수정과 서비스 재시작은 수행하지 않았다. 이번 PR은 검토 문서만 추가한다.

## 2. 프로젝트 목적에 따른 판단 기준

[README](../../README.md), [초기 프로젝트 설명](../company/01-한국은행통계-탐색시각화-에이전트-프로젝트.md), [차트 워크스페이스 UX](../chart_workspace_ux.md)를 기준으로 검토했다.

- 내부 연구 PoC의 핵심 흐름은 자연어 → 한국은행 작성 통계표 탐색 → 조회 조건 확정 → KOSIS 또는 로컬 CSV 조회 → 표·그래프 → 설명·출처·제약이다.
- 지원 범위는 한국은행 작성 통계표 349개다. 화면 접근성 트리의 요소 번호를 표 개수로 해석하지 않는다.
- 수치는 원자료에서 가져오며, 사용한 표와 처리 방법을 결과에 함께 제공해야 한다.
- 3개 패널과 하단 자연어 편집창은 기존 설계 의도다. 이를 유지하면서 조회 조건과 결과 검증을 쉽게 만드는 방향이 적절하다.
- 기관 인증·SSO, 실제 운영 배포 준비는 이후 단계의 별도 과제다. PoC 테스트 계정 자체를 이번 검토의 핵심 결함으로 보지 않는다.

## 3. 확인 범위와 증거의 수준

초기 자연어 질의 11종과 추가 질의 9종을 실행했다. 일부 내용은 반복·표기 변경 사례를 포함하며 고유한 평가 문항 20개 또는 공식 평가 점수로 집계하지 않는다. 지원 불가·기간 오류 사례는 오류 안내 단계에서 종료했다.

| 방법 | 확인한 범위 |
|---|---|
| 실제 UI 조작 | 질의 입력·분석, 역질문, 날짜 선택, 그래프 종류, 자연어·수동 편집, Undo/Redo, 저장·새로고침·재열기·명세 복원 |
| 실제 파일 확인 | CSV, 기본 PNG/PDF, 제목·색상 편집 후 PNG, 저장 JSON |
| 독립 원자료 대조 | 생산자물가지수 총지수 DT_404Y014, 2024년 12개월만 KOSIS 직접 조회와 대조 |
| 코드·격리 진단 | 정본 계획의 ID 표기 차이, 색상 대상 파서, HTTP 오류 분류; 외부 장애를 일으키지 않은 모의 확인 |

비공개 평가 저장소·정답·holdout 자료는 사용하지 않았다. 진단 파일은 저장소 밖에 보관했으며 이 PR에 포함하지 않는다. 브라우저의 검토용 저장 그래프 ‘검토용 생산자물가지수’ 1개는 남아 있다.

실사용 관찰은 로컬 `eval/reporter-v2.1` 브랜치 HEAD `bc3db7dc607297e6d67151a67e3317526dcb8c9f`와 당시 작업 트리를 대상으로 했다. 기존 미커밋 변경이 있어 HEAD만으로 화면을 완전히 재현할 수는 없다. 본 문서 PR은 최신 `main` 커밋 `d6da1375b13cc06368a05c50ab292d5afcbc4d95`에서 분기했다. 아래 결함은 관찰 환경의 진단이며 최신 main에서 모두 다시 재현한 결과가 아니다. 구현 담당자는 수정 전에 대상 브랜치에서 재현 여부를 확인해야 한다.

### F01. 요청 분류 오선택

재현 입력:

> 국내총생산에 대한 지출(원계열 실질 분기 및 연간) (DT_200Y110)의 민간소비를 2024년 1분기부터 2024년 4분기까지 분기별로 보여줘.

두 차례 서비스 분류가 선택됐다. 화면 2024Q1 값은 43,266 십억원이었다. ID만 `[DT_200Y110]`으로 바꾸면 민간 분류, 274,316.3 십억원이었다. 표가 맞더라도 항목이 다르면 요청을 충족하지 않는다. 이 국민계정 수치는 독립 KOSIS 대조를 수행하지 않았다.

`src/agent/canonical_request_planner.py`의 인접 ID 연결은 대괄호만 처리한다. 공개 사전의 격리 호출에서 괄호 ID는 계획 0개, 대괄호 ID는 민간 계획을 반환했다. 정본 경로가 비활성화되는 원인은 확인했지만, 이후 서비스가 선택되는 대체 탐색의 세부 판단은 추가 추적이 필요하다.

### F02. 혼합 주기 시간축

재현 입력:

> 예금은행 대출금리(신규취급액 기준) (DT_121Y006)와 국내총생산에 대한 지출(계절조정 실질 분기) (DT_200Y108)을 2024-01-01부터 2024-12-31까지 각각 원래 주기를 유지해서 비교해줘.

원래 주기와 12/4개 관측 수는 유지됐다. 그러나 월의 202401~202412와 분기의 202401~202404가 동일 문자열 좌표로 처리됐다. 렌더링된 SVG에서 월별 첫 네 점과 분기 네 점의 X좌표가 동일했다. `plotly_renderer.py`의 separate 배치 공유 축 설정에 주기 확인이 없다. 원자료 코드와 표시용 시간좌표를 구분해야 한다.

### F03. 경제적 의미가 성립하지 않는 구성비

재현 입력:

> 예금은행 대출금리(신규취급액 기준)에서 가계대출과 기업대출을 2024-01-01부터 2024-12-31까지 월별로 비교해줘.

출력 선택에서 원그래프를 **직접 선택**했다. 앱이 자동으로 선택한 사례는 아니다. 기업 4.62%, 가계 4.72%를 각각 49.46%, 50.54%로 정규화했다. 이는 대출 구성비가 아니다. `chart_availability.py`의 단위·시점·값 검증에 측정 개념과 구성항목 관계를 추가해야 한다. 도넛·트리맵·누적 차트도 같은 원칙으로 검토하되 모두를 실사용 재현한 것으로 주장하지 않는다.

### F04~F06. 기간과 편집

- F04: `GDP 성장기여도에서 민간소비와 설비투자를 2016년 1분기부터 2025년 4분기까지 분기별로 비교해줘.`는 최초 각 40개 분기로 정상 조회됐다. 이후 `기간을 2024-01-01부터 2025-12-31까지로 변경해줘.`는 각 8개 분기로 갱신했으나 제목은 이전 기간이었다. `chart_edit_period.py`의 기존 명세 복사와 자동·수동 제목 구분 부재를 확인했다. 최초 조회의 기간 누락 문제로 해석하지 않는다.
- F05: `2024년 1월부터 2024년 12월까지 예금은행 대출금리와 생산자물가지수 총지수를 비교해줘.`에서 신규취급액 DT_121Y006 선택 후 역전 기간이 두 차례 표시됐다. `bridge_api.py`의 `_availability_from_plans`가 시작 최댓값과 종료 최솟값의 역전을 확인하지 않는다. 왜 1964년 종료 자료가 포함됐는지는 조회 계획 추적이 필요하다.
- F06: `제목을 검토용 생산자물가지수로 바꾸고 선 색상을 빨간색으로 변경해줘.`에서 제목 RGB 확인 후 지원하지 않는 제목 색상 변경으로 중단됐다. 각각 단일 요청은 성공했다. `colorRequests.ts`가 ‘바꾸고 선’을 분리하지 않고 제목을 우선 대상으로 선택하는 것을 격리 호출로 확인했다.

### F07~F12. 사용성·오류·근거

- F07: `2024년 1월부터 12월까지 생산자물가지수 총지수를 월별 선그래프로 보여줘.`와 `최근 5년 경제심리지수 추이`에서 기간을 다시 요구했다. ISO 범위는 인식됐다. `request_period.py`의 연도 토큰·상대 기간 처리가 개선 대상이다.
- F08: `생산자물가지수(기본분류)를 2024-12-31부터 2024-01-01까지 보여줘.`는 날짜 오류와 함께 지원 데이터 없음·런처 실행 안내를 표시했다. `api/client.ts`는 HTTP 실패를 no_match로 변환한다. 격리 모의 400/422/500·통신 실패도 같은 상태였으며 실제 서버 장애 시험은 아니다.
- F09: 핵심 인사이트가 ‘MCP 24개 행을 2개 계열로 변환’ 같은 처리 기록이었다. `ChartWorkspace.css`는 워크스페이스 분석 요약·기간 안내를 숨긴다. 미지원 지표의 구체적인 이유도 접혀 있었다.
- F10: `WorkspaceData.tsx` 기간 초기값이 2020-01-01~2025-12-31이다. 2024년 저장 그래프 재열기에서도 같은 값이었다.
- F11: `plotly_renderer.py`의 공통 y_axis_label이 개별 단위를 덮어쓴다. 사이드바·표에 단위가 있어도 그래프 자체에는 각 단위가 필요하다.
- F12: CSV는 데이터·시점·값·단위 4열이다. PNG/PDF는 `kosis_api · DT_404Y014`를 표시한다. 사용자용 출처 표현과 조회 시점이 필요하다. 저장 목록은 saved_at을 표시하지 않는다. 동일 표 출처 카드 중복 및 `App.tsx`의 ‘전체 실행 근거 보기’ 버튼에 동작 연결이 없는 것도 확인했다. CSV 열을 변경할 경우 기존 이용자 계약을 함께 검토한다.

| 모호한 대출금리 | 신규 거래/현재 잔액 기준을 쉬운 말로 확인 |
| 미지원 지표·총액 | 연체율 포함 복수 요청 및 주택담보대출 전체 총액 요청을 다른 측정 개념으로 대체하지 않음 |
| 미래 자료 | 2027년 PPI 요청에 제공 범위 밖임을 안내, 미래 수치 생성 없음 |
| 저장·복원 | 제목·빨간 선·12개 관측치, 새로고침·Undo/Redo·명세 복원·저장 목록 재열기 확인 |
| 파일 출력 | CSV 수치 일치, 단일 그래프 PNG/PDF 한글·기간·축·출처 잘림 없음; 편집 PNG 제목·색상 유지 |

수치 해석 예시:

- 생산자물가지수 118.19→119.52는 1.33지수포인트 상승, 1월 대비 약 1.13% 증가다. 전년동월대비 상승률이 아니다.
- 대출평균 5.04%→4.64%는 0.40%p 하락이다. 동시에 물가지수가 상승했다는 관찰로 인과관계를 판단할 수 없다.
- GDP 성장기여도 2025Q4 민간 +0.2%p·설비투자 -0.1%p의 합 +0.1%p는 전체 GDP 성장률이 아니다.
- 가계 4.72%와 기업 4.62%의 차이는 0.10%p다. 금리 합계로 계산한 구성비는 대출 비중이 아니다.

## 6. 한국은행 직원 기준 화면 개선안

1. **조회 조건 상시 표시:** 표명·ID, 항목·분류, 기간, 주기, 단위, 원계열/계절조정, 명목/실질을 그래프 상단에서 확인할 수 있게 한다. 확정한 조건은 편집·복원에서도 유지한다.
2. **필요한 확인만 질문:** 모호한 측정 기준은 확인하고, 이미 입력한 날짜·분류를 반복 요구하지 않는다. 재선택이 필요한 이유와 대안을 함께 보여준다.
3. **3개 패널 유지:** 데이터·차트·속성 패널과 자연어 편집창을 유지하되 선택한 차트에 필요한 속성을 먼저 노출한다. 첫 방문 소개 영역은 작업 시작 후 축소한다.
4. **표 확인 접근 개선:** 일부 관측치 미리보기와 전체 표 전환을 명확히 구분한다. 차트와 표를 쉽게 오가며 선택한 계열을 확인하게 한다.
5. **인사이트와 근거 구분:** 실제 변화·단위·해석 한계를 결과 설명에 표시한다. 조회·정렬·가공 기록은 실행 근거로 열 수 있게 한다. 지원 불가 이유는 기본 화면에 표시한다.
6. **출처와 시점:** 작성기관 한국은행과 제공 경로 KOSIS를 구분하고 표별로 출처를 묶는다. 조회일·저장일·자료 기준시점을 구분해 저장 스냅샷을 최신 자료로 오인하지 않게 한다.

키보드 접근성, 작은 화면, 긴 제목, 다중 패널 출력은 추가 검토 대상이다. 이번 점검에서 확정된 결함으로 분류하지 않는다.

## 7. 권장 PR 운영 방식

### 7.1 먼저 검토 문서 PR

권장 제목: `docs: 한국은행 사용자 관점의 UI 검토 결과와 개선 기준 정리`

본 PR은 `docs/reviews/2026-10-13-frontend-review.md`를 추가한다. 사람 검토를 통해 진단 내용과 개선 기준을 확정한다. 현황·재현·기대 동작·확인 한계를 포함한다. 이 대화의 임시 진단 스크립트, 원응답, CSV, 저장 JSON, 자동 생성 증거 파일을 일괄 커밋하지 않는다. 공개 가능한 증거 공유 방법은 담당자가 검토한다.

### 7.2 구현 PR은 목적별로 분리

| 순서 | PR 목적 | 관련 항목 | 완료 판단 |
|---|---|---|---|
| 1 | 표 ID 표기 정규화와 요청 분류 검증 | F01 | 표기 변경 재현 사례에서 동일한 올바른 분류 선택 |
| 2 | 혼합 주기 좌표와 패널별 단위 수정 | F02, F11 | 월·분기 위치 및 각 축 단위 확인 |
| 3 | 경제적 의미에 따른 차트 적합성 | F03 | 비가산 금리 구성비 차단, 적합한 구성항목 사례 유지 |
| 4 | 제공 기간·기간 해석·자동 제목 정합성 | F04, F05, F07 | 역전 범위 차단, 기간 변형 해석, 제목·데이터 일치 |
| 5 | 복합 편집 대상과 복원된 조건 동기화 | F06, F10 | 복합 제목·색상 적용, 복원 후 실제 기간 표시 |
| 6 | 오류 상태·설명·근거·출처 개선 | F08, F09, F12 | 오류별 회복 안내, 결과 설명 접근, 시점·출처 추적 |

4번과 6번은 수정량이 커지면 다시 분리한다. 공유 파일을 수정하는 PR은 순서를 정해 충돌을 줄인다. 첫 문서 PR에 전체 재설계를 함께 넣지 않는다.

현재 작업 폴더에는 기존 수정·삭제·미추적 파일이 많다. 최신 main의 별도 작업공간에서 필요한 파일만 반영하고 diff를 확인하는 방식을 권장한다. 사용자 기존 변경을 reset하거나 무관한 변경을 한 PR에 포함하지 않는다.

### 7.3 저장소 규칙에 따른 제출 조건

- CONTRIBUTING.md가 정본이다. 최신 main에서 목적별 기능 브랜치로 작업하고 base는 main으로 설정한다.
- Conventional Commits 사용, PR 템플릿 작성, ai-assisted 표시, 영역 담당자 리뷰 요청.
- API 계약·데이터 선택 방식 변경 시 README와 관련 테스트도 갱신.
- 최소 1명 승인, 작성자는 자기 PR을 머지하지 않음. 승인자가 Squash merge.
- 공개 dev/test를 이용한 회귀 확인과 전체 흐름 평가를 구분하고 점수를 섞지 않음.
- 아래 필수 검증의 실제 결과를 기록. 미실행·실패·환경 제약을 숨기지 않음.

```bash
PYTHONPATH=src/backend:src/agent .venv/bin/python -m pytest -q tests eval/table-discovery/v4.1/tests
.venv/bin/python eval/table-discovery/v4.1/scripts/validate_v41.py
cd src/agent/frontend && pnpm build
```

Windows에서는 Python 경로를 `.venv\Scripts\python.exe`로 바꾸고, PowerShell의 PYTHONPATH는 환경 변수 방식으로 설정한다. 외부 호출·원자료 조회는 키와 데이터가 제공된 환경에서 확인한 범위를 별도로 명시한다.

문서 PR의 필수 검증 결과와 실제 실행 명령은 PR 본문에 기록한다. 이 검증 결과는 문서화한 UI 결함의 해결 또는 재현 확인을 의미하지 않는다.

## 8. 남은 확인과 제한

- 모든 349개 표의 항목·수치 정확도를 확인하지 않았다. 공식 성능 수치나 합격률을 제시하지 않는다.
- 국민계정·금리 등 다른 계열 수치는 화면 관찰이며 독립 원자료 대조와 구분한다.
- 서버 재시작 후 저장 복원, 실제 통신 장애, 다중 패널·긴 제목의 모든 파일 출력은 미검증이다.
- 빠른 Enter 두 번 입력에서 분석 버튼 비활성화를 관찰했지만 요청 수·응답 순서 교차를 계측하지 않았다. 확정된 경쟁 상태 결함으로 분류하지 않는다.
- 자동화 연속 입력 중 이전 결과가 잠시 보인 경우는 입력 확정 후 재실행했다. 자동화 반영 시점과 앱 상태 문제를 구분하지 못한 사례는 결함에 포함하지 않았다.
- 실제 한국은행 직원 대상 과업 수행·사용성 인터뷰가 필요하다. 표 탐색 시간, 조건 확인 성공, 해석 오류, 저장·보고서 인용 성공을 관찰 지표로 제안한다.

## 9. 증거 보관과 담당자 확인 요청

초기 11종 질의 기록, 추가 9종·편집·복원·출력 기록, DOM·SVG 관찰, 스크린샷, PPI 대조 결과와 격리 진단 결과는 검토자의 로컬 산출물 폴더에 보관했다. 공개 저장소에는 임시 스크립트·원응답·CSV·저장 JSON·생성 증거 파일을 포함하지 않는다. 공개 가능한 증거의 별도 첨부는 내용과 공개 경계를 사람이 검토한 뒤 진행한다.

담당자는 먼저 대상 브랜치에서 P1 항목을 재현하고 수정 범위를 확인해 주시기 바란다. 이후 목적별 PR 소유자·리뷰어 지정, 완료 기준 합의, 남은 검증 환경과 사용자 검토 일정을 결정한다.
