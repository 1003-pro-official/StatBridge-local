# 보고서 편집 명령과 UI

## 자연어

기존 HCX-007 → 구조화 명령 → 전체 요청 coverage 확인 → ChartEditCommand → ReportOptions/ChartSpec 검증 → 데이터·대상 검증 → 원자적 재렌더링 흐름을 유지한다. HCX-003/Jev는 조회 질의의 보조이며 이 편집 작업에서 통계표나 관측값을 새로 선택하지 않는다.

`set_report`의 `params.patch`를 현재 보고서 설정에 합친다. 템플릿 ID와 ReportOptions JSON 스키마를 모델 문맥에 제공한다. 예: “한국은행 보고서형 템플릿을 적용해줘”, “2025년 1분기부터 사용자 지정 전망 구간으로 표시해줘”, “두 열의 다중 패널로 바꿔줘”, “각주에 합성 검증 자료라고 적어줘”. 시점은 실제 `periods`와 같아야 한다. 없는 정책 날짜·출처·신뢰구간은 질문하거나 실패한다.

기존 제목·부제·축 이름/범위/형식·계열 스타일·범례·도형·메모·기준선·강조·숨김/정렬·원자료 표시 변환 명령은 계속 지원한다. 텍스트로 일반 `set_chart_type`을 명시하면 숨은 보고서 kind가 덮어쓰지 않도록 일반 차트 모드로 돌아간다. 패널 layout 요청은 보고서 메타데이터를 유지해 반영한다.

“인쇄용 PDF로 출력해줘”, “SVG 파일로 저장해 주세요”, “PNG로 다운로드해줘”, “JSON으로 저장해줘” 같은 **단독 출력 명령**은 고정된 클라이언트 경로로 처리한다. 기존 이모티콘 초안이 있으면 먼저 저장 후 해당 버전을 출력한다. 편집+출력이 한 문장에 섞인 요청은 편집을 먼저 적용한 뒤 출력 버튼을 사용한다. 서버에 임의 Python/JS를 만들거나 실행하지 않는다.

## 직접 설정

수정이 → 그림판 편집 → 보고서 차트·인쇄 설정. 템플릿/유형/패널/날짜 표시/전망 시작/추가 출처/각주/제공된 구간·이벤트/출력 크기를 모아 적용한다. 제목·부제·색·두께는 입력란에서 나갈 때, 범례·격자·로그축·선 모양은 선택 시 서버에 검증된 명령으로 반영한다. 계열 제외·다시 표시·순서 이동도 조회된 계열만 사용한다. 새 통계표 추가는 기존 검색·조회/복수 계열 흐름에서 수행한다.

신뢰구간·이벤트 입력은 현재 JSON 방식이다. 각 원자료·단위의 의미 확인 없이 일반 값을 기여도나 전망으로 바꾸지 않는다. 다른 단위의 이중 축을 자동 추천하지 않는다. 노출된 축 범위를 사용자가 변경하면 잘린 관측값이 생길 수 있으며 전문 통계 해석은 사용자가 검토해야 한다.

## API

| 경로 | 입력 / 반환 |
|---|---|
| GET /api/report/templates | 등록 템플릿 12개, 예약 미지원 유형, 구간 정책 |
| POST /api/report/recommend | 현재 편집 세션·버전, options·추천 이유. 자동 이중 축 없음 |
| POST /api/output/edit | 기존 입력 + report / clear_report / commands / document. revision으로 낙관적 잠금 |
| POST /api/report/export | edit_session_id, revision, format=json/png/svg/pdf. 파일 MIME·버전 헤더 |

직접 `commands`와 텍스트·그림·undo를 한 요청에 섞지 않는다. 이모티콘 초안은 직접 설정과 함께 저장할 수 있다. JSON 복원은 별도 요청이다. 모든 편집 성공은 기존 이력에 한 번 저장되어 undo/redo에 포함된다.
