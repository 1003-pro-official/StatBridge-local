# 원문 금액 요청이 비중 표로 바뀌는 오류 수정

작업 위치: `StatBridge-local1`만 수정했다. `StatBridge1`은 수정하지 않았다. 기존 이모티콘 작업은 유지했다.

## 재현과 원인

요청: “주택담보대출 신규취급액 2020년1월1일부터 2025년12월31일까지 그래프 그려줘”.

수정 전 사전 resolver에서 `DT_181Y011`(차주당 주택담보대출 신규취급액)과 `DT_181Y015`(주택담보대출 신규취급액 비중)가 각각 117점을 받았다. 신규취급액 기준 대출금리와 잔액 표도 후보에 남았다. 기존 검사는 비중을 요청하면 비중 표를 요구했지만, 금액을 요청한 경우 비중·금리를 제외하는 반대 방향 검사가 없었다. “대출”이라는 넓은 주제 일치만으로 실제 조회 검증도 통과할 수 있었다.

HCX의 확장 텍스트를 사전 조회 및 API 계획에 사용했고, 하이브리드 검색은 높은 순위의 표로 선택을 교체할 수 있었다. 벡터 후보가 규칙 검색에서 제외된 표를 다시 도입하는 경로에도 측정 조건 검사가 없었다. 따라서 금액과 비중이 동점인 상태에서 검색·모델 결과에 따라 비중 표가 출력될 수 있었다. 당시 화면의 정확한 요청 로그는 없으므로 실제 화면에서 어느 검색 단계가 순위를 바꿨는지까지 단정하지 않는다.

## 수정

- `request_match_guard.py`: 정본 표·항목 이름으로 측정 조건을 검사하는 공통 함수를 추가했다. 금액/비중/금리, 신규취급액/잔액, 수출입 금액/물량/물가, 명목/실질, 원계열/계절조정, 말잔/평잔, 실적/전망과 명시 총액/차주당 구분을 검사한다. 별칭이나 분류 이름만으로 잘못된 측정 개념을 허용하지 않는다.
- `stat_language_resolver.py`: 후보 점수 계산 전에 공통 조건을 적용한다. “비중 말고”, “비중 대신”, “비중이 아니라” 등 명시적으로 배제한 지표를 표 제목 일치로 다시 선택하지 않는다. 신규취급액 비중 상태에서 바깥 측정 개념은 비중으로 기록한다.
- `request_match_guard.py`: 비교 질문의 지표별 구간을 나눌 때도 측정 조건을 검사한다. “2020년과 2025년”의 날짜 접속사를 별도 지표로 분리하지 않도록 한다. 금리와 신규대출 금액을 비교할 때 서로의 측정 기준을 강제하지 않는다.
- `hybrid_retriever.py`: 벡터 검색이 재도입한 후보도 측정 조건과 사용자 확정 조건을 통과해야 반환한다.
- `agent_runtime.py`: 비교 계열 검색과 원문 기준의 최종 후보를 검사한다. 원문 사전 해석이 이미 해결된 경우 모델 확장으로 측정 개념·날짜·분류를 바꾸지 않고 원문으로 조회 계획을 만든다. 단수 요청에 모델이 임의로 비교 계열을 추가하는 경로를 막는다. 조회 직전 기존 재검증은 보강된 공통 조건을 사용해 잘못된 표를 조회 전에 차단한다.
- `tests/test_measure_intent.py`: 28개 회귀 사례. 전체 349개 정식 표 이름의 자기 측정 조건, 금액·비중·비율·구성비·잔액·금리·부정 표현, 기타 측정 기준, 잘못된 모델 확장·최상위 검색 점수·벡터 재진입·비교 환각, 조회 직전 차단을 검증한다. 비중 동의어는 후속 대화 상태에도 `비중`으로 정규화하며, 부정한 지표는 상태에서 제거한다.

## 실제 수치 확인

모델을 비활성화하고 원문 선택 후 실제 KOSIS API를 호출한 결과:

- 선택 표: `DT_181Y011`, 차주당 주택담보대출 신규취급액.
- 자료 주기: 분기. `202001`~`202504`는 2020년 1분기~2025년 4분기다.
- 반환: 24행, 단위 `십만원`, source `kosis_api`.
- 첫 세 값: 2020년 1분기 1242.5, 2분기 1207.8, 3분기 1449.9.
- `OutputAgent.prepare`로 실제 반환 데이터의 Plotly 그래프를 생성했다.
- 증거: `evaluation_runs/measure_intent_live_20261008.json`.

이 표는 전체 주택담보대출 신규취급 총액이 아닌 차주당 금액이다. 총액 요청을 이 표로 대체하지 않는 회귀 사례를 포함했다.

## 검증 범위

골든셋은 기존 질문·정답·판정 기준을 바꾸지 않고 실행한다. 1104문항과 4표 비교 36문항은 실제 FastAPI TestClient의 `POST /api/query(execute=false)` 반환 경계에서 표·항목·분류·주기·기간·역질문과 exact API params를 검증한다. 이 골든셋은 수치 조회·그래프를 평가하지 않으며, 공개 카탈로그 기반 개발 회귀셋이다. 수치 조회·그래프는 위 별도 실조회와 회귀 테스트로 확인한다. 자연어의 모든 가능한 표현에 대한 완전성을 주장하지 않는다.

## 실제 설정 API 확인

HCX-003 분류와 하이브리드 검색을 활성화한 새 프로세스에서 실제 애플리케이션의 `POST /api/query`를 TestClient로 호출했다. 표·수치·출력 생성에 모의 응답을 사용하지 않았다.

- HTTP 200, 응답 상태 `resolved`, 반환 표 `DT_181Y011`, 그래프 있음.
- 분류 상태 `success`, 하이브리드 검색 활성화.
- `dictionary_query`는 사용자가 입력한 원문을 유지했다.
- API 계획: 항목 `13103852628999`, 대표 분류 `13102852628ACC_ITEM.0000`, 분기 `Q`, 기간 `202001`~`202504`.
- 화면 표시 기간 `2020-01-01`~`2025-12-31` 유지.
- 증거: `evaluation_runs/measure_intent_endpoint_20261008.json`.
