# 개별 테두리 및 양식 복원 검증

## 실행 구분

첨부 5·13·18쪽의 고정 관측값과 독립 Decimal 정답으로 평가했다. 실시간 KOSIS/GPT 품질 평가가 아니며 관련 평가의 외부 HTTP는 전송 전에 차단했다. 새로운 표 서식 편집과 단축키는 GPT를 호출하지 않는다.

## 실제 UI와 다운로드

격리 계정에서 18쪽 B4:C5 범위를 선택해 위쪽 3px 점선, 왼쪽 2px 실선, 아래쪽 이중선을 순서대로 적용했다. Ctrl+Z로 아래 선만 없어지고 Ctrl+Shift+Z로 복원되는 것을 DOM 스타일로 확인했다. 테두리 없음 적용 후 모든 변이 none이 됐고 Ctrl+Z로 원래 세 변이 복원됐다.

BOK-T06을 고르면 머리글이 노랑/이중선이 되고 기존 왼쪽 속성 패널의 BOK-T02 선택도 머리글 배경과 구분선에 반영됐다. 기존 상세 설정을 열어 다단 머리글·계층형 행 제어가 유지됨을 확인했다. 선택 범위만 소수점 3자리로 바꿔 다른 수치의 자릿수가 바뀌지 않는 것을 확인했다.

같은 편집 결과를 실제 UI의 XLSX/PDF/PNG 버튼으로 다운로드했다. XLSX B6의 top=dotted/left=medium, B7 bottom=double, number_format=#,##0.000, 원래 값 14102.8, 머리글 배경 00edf3f8, 계산근거 60행(+머리글)을 검산했다. PDF 1쪽, PNG 1152×800. PNG도 열어서 표·선·숫자·주석을 점검했다. XLSX의 점선 굵기 제한은 UI에 안내한다.

격리 계정에 저장 후 페이지 새로고침/보관함 복원으로 위·옆·아래 선과 소수점이 그대로 유지됨을 확인했다. 정상 계정의 분석 파일은 덮어쓰지 않는다. 정상 앱에서는 기존 저장 분석을 읽어 수정·단축키를 검증한다.

전체 회귀 동안 Python/테스트 소스 해시는 고정됐다. 이 실행 이후 최종 파일 점검으로 이중선의 선 간격과 최신 시점 강조 대상을 보정했으며, 해당 변경과 새 강조 테스트를 포함한 관련 126건을 두 폴더에서 재실행했다. 최종 관련 126건을 포함한 전체 2008건을 다시 실행한 것은 아니다. StatBridge1의 전체 공개 회귀도 별도로 반복하지 않았고 관련 검사 및 동일 소스 해시로 확인했다. 반복 검사를 독립 사례 수로 합산하지 않는다.

두 폴더의 최종 TypeScript/Vite 빌드와 v4.1 공개 계약 검사도 통과했다. 큰 JS 번들 경고는 남아 있지만 빌드 오류는 없다.

실제 local1에서 기존 저장 분석을 열어 아래쪽 이중선 적용→Ctrl+Z로 제거→Ctrl+Y로 복원, BOK-T02 선택으로 연도별 4열 머리글 생성, PNG 실제 다운로드를 확인했다. 최종 PNG 1680×560의 두 패널과 분리된 이중선도 시각 점검했다. StatBridge1에서도 기존 분석에 왼쪽 2px 파선이 적용됨을 확인했다. 정상 계정의 저장 파일은 수정하지 않았다.

최종 계정/저장 보존: local1 users 5/graphs 9, StatBridge1 users 4/graphs 5의 레코드 및 저장 JSON.gz, .env 해시가 작업 전과 일치한다. 실제 API로 기존 저장 분석 5+2개 복원을 확인했고 미완료 파일 연결 목록은 빈 목록이다.

앞선 미완료 캐시 제거 관련 검사는 local1 114건/StatBridge1 43건이 통과했고 이번 전체 회귀에도 포함된다. 편집과 관련 평가에 GPT 호출을 추가하지 않았다.
 상세 로그, 각 사례 판정, 원자료 보존 해시, 다운로드 검증과 UI 이미지는 .venv/cache/table-borders-20261019에 보관한다. CSV는 서식을 보존하지 않으며 HWP 직접 내보내기는 이번 범위가 아니다.
