# 표 확대보기·문서 높이·텍스트·챗봇 첨부 수정 (ai-assisted)

## 문제와 변경

1. ReportTableView가 편집기를 포함한 같은 JSX를 본문과 확대 dialog 양쪽에 재사용하고 있었다. ReportTablePreview를 분리해 확대 화면에는 제목·표·각주·출처만 그린다. 도구막대·셀 편집·고급 설정을 포함하지 않는다.
2. 큰 표 문서에서도 그래프용 작업 영역의 최대 높이와 100% 높이가 남아 있었고 overflow:visible 내용만 다음 관측요약 위에 그려졌다. table-workspace 명시 클래스로 표 모드의 root/grid/center/document를 정상 문서 흐름과 자동 높이로 바꾸고 최대 높이를 해제했다. 좌우 패널 폭과 채팅 높이는 별도로 제한한다. 그래프 모드의 화면 높이는 유지한다.
3. 셀을 클릭해 제목·머리글·행 이름을 선택한 뒤 글자를 입력하면 인라인 수정이 시작된다. 선택 셀 텍스트 수정 버튼 및 기존 더블클릭/F2도 제공한다. Enter/포커스 이동 확정, Esc 취소이며 원자료 숫자 덮어쓰기는 금지한다.
4. Sujeongi의 tableMode 첨부 UI 숨김과 ChartSketchEditor의 참고 표 전송 거부를 제거했다. 표 편집 챗봇에서 PNG/JPG/WebP/PDF 참고 파일을 선택하고 수정 내용을 보낼 수 있다. 최대 3개·파일당 4MB·PDF 5쪽 제한은 기존 검증을 재사용한다. CSV/XLSX 원자료 연결과 이 참고 서식 첨부는 서로 다른 기능이다.
5. API 요청에 edit_target=table을 추가했다. 첨부 표의 해석은 기존 이미지 모델 연결을 한 번 호출하고, set_table 외 명령·데이터 선택/기간 필터·숫자 직접 대체·잘못된 행열 ID를 서버가 독립 차단한다. 첨부의 지시문과 숫자를 실행/원자료로 취급하지 않는다. 현재 실제 ID와 닫힌 TableOptions 스키마를 제공하고 결과를 기존 OutputAgent와 원자적 편집 이력에 적용한다. 실패 시 현재 표·버전·첨부 초안은 유지한다. 여러 파일도 한 편집 요청에서 함께 해석한다.

## 실제 UI 및 공급자 확인

- local1에서 직접 편집 후 footer가 작업 영역 안에 있고 관측요약은 아래에 있는지 DOM boundingClientRect로 검증했다. 기본 작업 영역 높이 약 981px, 상세 설정을 펼친 높이 약 1611px에서도 겹침이 없었다. 채팅을 열어 작업 영역이 약 1093px일 때도 요약은 20px 아래였다.
- 두 실제 앱의 확대 화면에서 셀 직접 편집기 0개를 확인했다. local1 확대 표 내부의 버튼도 0개였다.
- local1에서 셀 클릭→텍스트 수정 버튼→한국어 표시명 변경을 확정했다. 다른 셀 클릭 후 x 타이핑으로 인라인 입력이 시작되는 것과 Esc 취소도 확인했다.
- 두 앱에서 파일 선택창으로 reference-page-18.png를 실제 첨부하고 파일명이 표시됨을 확인했다. StatBridge1은 중복 유료 호출을 하지 않았다.
- local1에서 실제 기존 OpenAI gpt-5.4 연결로 첨부 표 편집 요청 1건을 성공했다. 표 제목이 «표 첨부 편집 검증»으로 바뀌고 머리글 배경이 DCEEFF로 바뀌었다. 먼저 직접 수정한 표시명은 보존됐다.
- 실제 UI에서 XLSX를 다운로드해 원자료 관측 20개 모두를 기존 저장 분석의 원자료와 대조했다. 모두 일치하며 계산근거 20행(+머리글), 제목·머리글 색도 일치한다. 모델 interpret 경로는 1회이며, 공급자 HTTP 재시도 수나 토큰 수를 별도 계측한 것은 아니다.

## 자동 검증

표 참고 파일 경로는 공급자 모의 계약 테스트로 별도 검증한다. 허용되는 표 서식 변경 1회 호출, 편집 가능한 텍스트, 원자료·숫자 대체 금지, 비표 명령/코드/필터 거부, API 실패 시 버전·원본 보존 및 되돌리기를 포함한다. 모의 테스트를 실제 GPT 호출로 보고하지 않는다. 실행 결과와 보존 해시는 .venv/cache/table-ui-fixes-20261019에 보관한다. 최종 실행 결과는 아래에 기록한다.
