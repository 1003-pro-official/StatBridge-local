# 실제 파생지표 질문 · Langfuse 실행 분석 (ai-assisted)

2026-10-20, local1 운영 API 8000 / UI 5173에서 실제 질문을 두 번 입력했다. GPT-5.4와 KOSIS API를 실제 호출했다. 모의 자료나 저장된 그래프 복원 테스트가 아니다. StatBridge1은 이번 신규 질의 실험에 포함하지 않았으며, 이 보고서만 동일하게 제공한다. 두 폴더의 기존 계정·저장 분석은 내용 해시가 동일했다. 분석 저장 버튼은 누르지 않았다.

## 입력 및 계산 확인

> 2023년 1월부터 12월까지 생산자물가지수(기본분류) 총지수의 전년동월 대비 변화율을 계산해서 월별 선 그래프로 보여줘.

- 실제 선택: 한국은행 301, `DT_404Y014`, 항목 `13103134604999`, 총지수 분류 `objL1=13102134604ACC_CD.*AA`, 월별, 원자료 단위 2020=100.
- 모델 계획: `yoy_pct(source)`. Python 계산: `(당월 지수 / 12개월 전 지수 - 1) × 100`, 결과 단위 %.
- 원자료 조회: 2022-01~2023-12, 출력: 2023-01~2023-12의 12개 값. 출처 `kosis_api`; 파일·로컬 CSV 대체 없음.
- 첫 실행과 반복 실행을 각각 Decimal 40자리로 독립 검산: 총 24개 PASS, 최대 절대오차 약 `1.05e-14`, 허용오차 `1e-10`.

## 지연 원인과 불필요한 호출 판단

1. **주요 병목은 계획 및 GPT 대기다.** 첫 분석 요청의 약 68.6%, 반복의 약 87.9%가 GPT HTTP 호출 시간이다. 검색이나 Python 계산을 최적화해 얻을 이득은 작다.
2. **메타데이터 캐시는 작동한다.** 첫 실행은 TBL/ITM/PRD 3회와 관측값 1회, 반복은 관측값 1회였다. 계획을 수정하지 않고도 약 3초의 메타데이터 조회가 없어졌다. 다만 공급자 응답시간 변동도 있으므로 전체 차이를 전부 캐시 효과로 단정하지 않는다.
3. **한 실행의 세 모델 호출은 재시도 폭주가 아니다.** 계산 근거에 planning 2회, semantic_review 1회가 기록됐다. 시간 순서와 코드상 첫 planning 뒤 필요한 표의 메타데이터를 공급하고 다음 planning에서 DAG를 만든 뒤 별도 경제학적 의미 검토를 한다. 출력·수치 계산·문장 요약에서 추가 모델 호출은 없었다. NCP 호출도 없었다.
4. **첫 메타데이터 요청 결정은 줄일 후보가 있다.** 정확한 표 이름·항목이 명시된 요청에 한해, 서버가 제한된 후보의 실제 메타데이터를 먼저 제공하면 모델이 도구 호출을 결정하는 1회를 줄일 가능성이 있다. 이번 두 실행의 첫 모델 대기시간은 2.62초/1.94초였다. 후보가 불명확한 요청까지 상위 1개 표를 자동 확정해서는 안 된다. 실제 절감 효과는 패치 후 별도 비교가 필요하다.
5. **동일 질문의 검증 계획 재사용은 작동하지 않는다.** 두 계산 근거 모두 `plan_cache_hit=false`이고 재실행에도 3회를 다시 호출했다. 현재 `derived_supplement.py`의 fingerprint 캐시는 파일 기반 기간 비교 경로에 한정되어 일반 API 전용 새 질의에 적용되지 않는다. 사용자·정규화 질문·기간·실제 메타데이터 지문·카탈로그 버전·스키마/검증기 버전을 키로 검증 계획과 의미 검토 결과를 함께 재사용하는 것이 우선 개선 후보다. 자료 값은 재조회하고, 계획·출처·단위·주기·자원 검증은 다시 실행해야 한다. 의미 검토를 무조건 생략하는 제안은 아니다.
6. **공급자 토큰 캐시와 앱 계획 캐시는 다르다.** 반복의 입력 캐시 토큰은 늘었지만 네트워크 요청은 그대로 3회이고 GPT 총 대기시간도 줄지 않았다. 캐시 토큰 수만으로 체감속도나 요금을 단정할 수 없다. 공식 가격 확인 없이 금액 추정은 하지 않았다.
7. **출력의 추가 렌더링은 소규모 개선 후보다.** 출력 요청에서 `chart.render` 8회가 기록됐다. 실제 그림 외에 `chart_availability.inspect_charts`가 지원 여부 확인을 위해 차트 종류들을 렌더링하는 코드가 있다. 결과 지문별 지원 여부 재사용을 검토할 수 있지만 이번 출력 전체가 0.23~0.39초여서 GPT보다 우선순위가 낮다. 중첩된 `sources.fetch`/`output.prepare` 동명 span은 워크플로우와 실제 서비스의 경계를 각각 기록한 것으로 모델·API 중복 호출로 세지 않았다.
8. **모델 호출 목적 표시는 더 명확해질 수 있다.** Cloud generation 이름은 모두 `model.openai`다. 계획 도구 선택·DAG 생성·의미 검토 구분은 이번에는 로컬 계산 근거의 usage.stage와 실행 순서를 대조했다. 안전한 purpose/attempt 속성을 기록하면 원문 프롬프트 없이도 대시보드에서 구분하기 쉬워진다.

이번 작업은 실제 실행과 분석이다. 최적화 제안의 예상 효과를 이미 반영된 개선으로 보고하지 않는다. 애플리케이션 실행 코드는 변경하지 않았으며 따라서 신규 코드 회귀 검사는 수행하지 않았다. 검증에 사용된 모델 호출은 총 6회이며 검사 자체가 추가 모델을 호출하지 않았다.
