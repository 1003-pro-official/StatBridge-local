# 질문 분류 및 계산 근거 표시 수정 (ai-assisted, 2026-10-19)

사용자 최종 정책: 사내 매출·급여·재고·회사 비용은 지원하지 않는다. 해당 자료를 업로드하도록 안내하거나 공개 물가통계로 대신 계산하지 않고, KOSIS 제공 자료를 사용하는 질문으로 다시 작성하도록 안내한다.

원인과 수정:
- 기존 `실질 가치`/`실질화` 중심 정규식에서 `실질 비용`, `...로 조정`, 여러 사칙연산 표현이 빠져 일반 통계 조회로 처리됐다. 실제 수정 전 회사 비용 질문이 `need_output_config`로 반환되어 일반 조회의 그래프 출력 준비로 넘어가는 것을 확인했다.
- 계산·증감·실질화·누적·지수 변환·통계 연산 표현을 파생지표 경로로 분류한다. 지원 가능한 식인지는 기존 승인 카탈로그·폐쇄 DAG·단위·의미 검증을 그대로 거친다.
- 회사·개인 소유 원자료의 요구는 계획 전, 업로드 시작 전, 실제 실행 전 검증에서 차단한다. 지원불가 안내는 추가 GPT 호출이 없고, 새 그래프·업로드 작업을 만들지 않는다. 재작성 시 기존 사내 요청 조건이 새 질문에 붙지 않도록 응답의 대화 상태를 비운다. 이전 그래프 및 저장 분석은 삭제하지 않는다.
- 회귀 과정에서 통계표명에 있는 `대출 비중`까지 계산으로 분류하는 2건을 발견했다. `비중`/`비율`은 계산·산출 요청과 구별하도록 보완하고, 복합 통계 조회의 기존 추가 질문 경로를 유지한다.
- 제목에 인용한 `변화율`/`계산 결과`를 산식 변경으로 오인하지 않는다. 시각 편집과 실제 산식 변경을 함께 요청하면 산식 변경도 처리한다.
- 출력의 `어떻게 계산했나요?`를 기본 펼침 상태로 표시한다. 검증된 실제 DAG에서 사칙연산·전년비·전기비·이동평균·누적·기준100·로그·거듭제곱·기간별 변화율 산식을 결정론적으로 설명하고, 조회기간·원자료·표/항목 ID·결측 기록을 유지한다. 설명용 GPT 호출은 없다.

실제 실행 증거:
- 두 실제 앱에서 회사 비용 요청은 지원불가/질문 재작성으로 표시되며 새 그래프와 해당 요청용 업로드 영역이 없다.
- 실제 KOSIS DT_404Y014 총지수 원자료 24개(202201–202312)를 사용해 2023년 변화율 12개씩을 계산했다. 모델은 실제 GPT-5.4이며 각 앱에서 계획 2회/의미 검토 1회였다. 추가 설명 생성 호출은 없다.
- Decimal 40자리 독립 검산: 각 앱 12개 모두 오차 1e-10 이내, 최대 오차 약 1.05e-14.
- 실제 회사 자료 거절 HTTP 8건, 일반 조회/복합 비중 조회 HTTP 4건을 통과했다. 실제 원자료 열람 화면에서 24개 관측값 표시를 확인했다.
- 두 앱 백엔드를 정상 런처로 재시작했다. 각 `.env`, 계정 DB, 저장 분석 원본을 복사하거나 수정하지 않았다. 원본 해시 보존과 기존 테스트 계정 저장 분석 7건의 실제 복원을 확인했다.

제약:
- 자연어 전체에서 오류가 절대로 없다는 보장은 하지 않는다. 이 변경은 분류 회귀와 지원 범위 위반의 방지이며, 추가 계산은 항상 기존 ID·수식·단위·의미 검증 대상이다.
- 이번에는 기존 300개 평가셋의 GPT 전량 재평가나 저장소 전체 테스트를 재실행하지 않았다. 실제 GPT/KOSIS 검증 2건과 오프라인 관련 회귀·프런트엔드 검증을 구분한다.
- 프런트엔드 빌드는 성공했으며 기존 번들 크기 경고가 남는다.

검증 횟수와 최종 상태는 같은 폴더의 results.json 및 각 프로젝트 eval/derived_regression_targeted.xml에 기록한다. 개인정보·회사 관측값을 시험 데이터로 만들거나 외부 공급자에 전송하지 않았다. 질문 문자열만 사용했다.

최종 실행 결과: 각 폴더 백엔드 관련 회귀 816/816 통과, 실패 0, 미실행 0(수집된 관련 회귀 범위). 프런트엔드 27/27 통과 및 빌드 성공. 전체 저장소/300개 GPT 평가는 이번 범위에서 실행하지 않았다. 일반 조회 추가 회귀의 중간 결과 463 PASS/2 FAIL은 분류 수정 후 최종 결합 816 PASS에서 해소됐다.
