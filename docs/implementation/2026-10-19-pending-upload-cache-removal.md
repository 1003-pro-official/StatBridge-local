# 미완료 파일 연결 안내 및 캐시 제거 (ai-assisted)

로그인 뒤 첫 화면의 «연결하던 자료가 있습니다» 영역과 자동 목록 조회를 제거했다. 해당 UI 컴포넌트를 삭제했고, 기존 목록 API는 호환성을 위해 인증 후 빈 목록을 반환한다.

미완료 보완 작업과 업로드 원본 바이트는 진행 중 서버 메모리에만 보관한다. 서버 재시작/12시간 만료 시 폐기되며 디스크에 workspace/revision/raw 파일을 만들지 않는다. 앱 시작 시 기존 전용 보완 디렉터리 안의 정상 owner/UUID 경로에서 calculation_id가 없는 미완료 캐시만 제거한다. 범위를 벗어난 경로나 심볼릭 링크는 제거하지 않는다.

계산이 성공하면 해당 분석의 재현·수정에 필요한 workspace, 파일 해시, 원본과 근거를 저장한다. 완료 분석 및 계정 DB·저장 그래프·환경 설정은 유지한다. 파일 업로드 기능 자체는 현재 질문에 필요한 경우 계속 제공한다.

검증: 새 메모리 보관/재시작/완료 후 보존/기존 캐시 정리/만료 테스트 및 CSV·JSON·TSV·XLSX 검사, 관련 파생지표 회귀를 실행했다. 기존 «업로드 즉시 파일 저장» 테스트는 «완료 전 디스크 파일 없음, 메모리 해시 일치, 완료 후 동일 원본 해시 보존»으로 정책을 갱신했다. 결과 로그는 각 .venv/cache/pending-upload-removal-20261019에 보관한다.

두 앱을 재시작하고 실제 로그인 첫 화면에서 안내가 없는 것을 확인했다. 미완료 디스크 workspace는 두 프로젝트 모두 0개이고 완료 workspace는 local1 2개/StatBridge1 1개 보존했다. 기존 저장 분석 local1 5개/StatBridge1 2개가 모두 복원됐고 계정·저장 파일·.env 해시가 일치한다.
