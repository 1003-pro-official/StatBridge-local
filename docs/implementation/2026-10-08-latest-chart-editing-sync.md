# 최신 그래프 편집과 조회 런타임 동기화

날짜: 2026-10-08 · ai-assisted · human_approved=false

## 차이와 병합 기준

StatBridge1의 포터블 앱에는 최근 수정이 UI·그래프 편집 기능이 있었고, Git checkout인 StatBridge-local1에는 이후 반영된 정본 조회 계획·349개 표 골든셋 패치가 있었다. 수정 시간을 기준으로 한쪽 폴더 전체를 덮어쓰지 않고 두 경로의 차이를 비교해 합쳤다. 최신 upstream/main에서 새 기능 브랜치를 만들었다.

| 공통 코드 | 저장소 구조 | 포터블 구조 |
|---|---|---|
| Agent / React | src/agent | StatBridge-official/src/agent |
| Backend / MCP | src/backend | statbridge_mcp_server |
| 실행 데이터 | data/processed, data/tables | runtime_data/processed, runtime_data/tables |
| 설정 | 루트 .env | statbridge_mcp_server/.env |

공통 앱 소스와 에셋 **103/103개 SHA256 일치**를 확인했다. 폴더별 런처·가상환경·환경 설정·원자료·벡터 DB·캐시·기존 평가 로그는 동기화 대상에서 제외했다. 포터블의 예전 statbridge_agent.py는 공통 agent_runtime 진입점으로 연결했다. Git 기록과 공개 평가 도구·문서는 local1에서 관리한다.

## 합친 변경

- 수정이 전체 높이 사이드바, 접을 수 있는 그림판 도구, 채팅 맥락 보관과 완료 후 닫기, 입력창·버튼 디자인 및 RGB 색상·투명도 미리보기.
- 헤더 `그래프를 어떻게 수정할까요?`, 출력 화면 안내 `그래프 수정은 수정이에게 맡겨 보세요`, 중복 도움 문구 정리와 주요 데이터 예시 5개.
- 텍스트의 복합 편집 지시와 명령별 coverage 검증, 화살표 주석과 화살표 이후 계열 색상 변경 구분, 도형·아이콘 도움 목록.
- 최초 그래프의 흰 배경, 양 축 격자 제거, 제목 가운데 정렬, 상단 주석 겹침 조정, 전체 상자 좌표 적용과 최근 강조 영역 확대.
- 기간 변경 시 기존 통계표·항목·분류·스타일을 유지한 재조회, 실패 시 기존 출력 유지, 데이터와 스타일을 함께 되돌리기/다시 적용.
- local1의 정본 조회 계획·복수 표 ID 범위 검증·연도 포함 표 제목 처리·경상수지 구성 계열과 독립 구간 색상 편집을 보존.
- 저장소/포터블 경로 자동 구분. 데이터·벡터 경로 환경 변수와 각 폴더의 기존 설정 위치 유지.

기간·도형 좌표를 안정적으로 연결하도록 월/분기 x축은 정본 기간 코드의 category 축을 사용한다. 월 데이터를 숫자 좌표 한 점으로 뭉치지 않으며 월별 눈금 간격과 회전은 유지한다. 관련 테스트 기대값도 이 표현 계약에 맞췄고, 기존 테스트 함수는 삭제하지 않았다.

## 실제 조회에서 추가로 찾은 문제

정본 질의는 최초 계획을 엄격히 재구성한다. 사용자가 UI에서 기간을 선택한 뒤 조회된 계획은 날짜가 바뀌므로 `/api/output`이 정상 세션을 `요청과 통계표가 일치하지 않습니다`로 거부했다. 기간 재수정의 재조회도 같은 원인으로 막힐 수 있었다.

서버가 보관한 출력 세션에서 확정한 기간을 재검증에 전달하도록 수정했다. 표·항목·기관·주기·분류와 기간 외 exact API params 검증은 유지한다. 출력 자연어 요청에 표를 다시 명시한 경우에도 같은 확정 기간을 사용한다. 임의 항목·기관·분류·주기로 변조하면 여전히 거부하는 회귀 테스트를 추가했다. 클라이언트 요청 모델에는 확정 기간 검증 우회 필드를 추가하지 않았다.

StatBridge1 자체 가상환경에서 API health와 349개 표 카탈로그를 확인했다. 두 폴더 모두 MCP 실제 수치 조회 → 선 그래프 출력 → 양 축 격자 제거 → 2015년으로 확대 → 2018년으로 재수정 흐름이 성공했다. 최초 26개 관측값이 2015년 시작의 46개로 확대됐고, 격자 제거 상태를 유지했다. 흰 배경과 스타일 편집 시 데이터 불변도 확인했다.

최종 전체 pytest는 프로세스 환경에서 외부 모델 키를 공백으로 설정해 네트워크 모델 호출을 끄고 실행했다. 저장된 .env는 변경하지 않았다. 별도 실제 API 골든셋은 기존 모델·검색 설정으로 실행했다. 포터블 자체 가상환경에는 pytest가 없어 포터블 pytest는 local1의 테스트 Python과 포터블 소스 경로로 실행했다. 실제 API smoke는 각 폴더의 자체 Python을 사용했다. 프런트 build의 기존 약 4.9MB Plotly 번들 경고는 남아 있다. 브라우저에서 모든 편집 조합의 시각 검사 또는 모든 자유 문장 해석 성공을 주장하지 않는다.

골든셋은 query-only `POST /api/query(execute=false)`에서 HTTP/Agent/API 상태, 표·계열 집합, exact params, 역질문·기간 대기를 검증한다. 수치 조회와 출력 호출은 각 0회다. 실제 그래프·편집 검증은 별도 smoke와 회귀 테스트로 확인했다. 공개 dev / ai-assisted / human_approved=false이며 블라인드 일반화 점수가 아니다.
