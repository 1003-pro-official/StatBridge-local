# 2026-10-22 v1.1 평가·소비자심리지수 단위 보완 종합

ai-assisted · 사람의 코드·보고서 정성 검토는 대기 상태이다.

## 제품 변경

동일 표시명을 가진 계열도 표·항목·분류 코드로 구분하고 실제 출처 식별자를 출력한다. 기간만 변경하는 후속 요청은 서버에서 확정한 기간과 계열을 유지한다. 원자료 응답 검증 오류에서는 같은 계획을 재생성하거나 파일 업로드를 반복 요청하지 않고 원인과 현재 작업을 보존한다. 계산 조건 검증 오류는 조건 확인으로 안내한다.

소비자심리지수 전체 월별 계열에 한해 공식 정의에 근거한 계산용 단위 ‘지수’를 제공한다. KOSIS가 반환하지 않은 UNIT_NM을 원응답에 만들어 넣지 않는다. 정확한 기관·표·항목·분류·주기와 성공한 API 응답을 확인하며, 다른 계열이나 기존 단위는 변경하지 않는다. 계산 영수증에 공식 출처와 보완 이유를 기록하고 단위 정책 변경 시 검증 계획 캐시를 무효화한다.

## 실제 자료 확인

KOSIS 기관 301, 표 DT_511Y002의 소비자심리지수 전체 계열을 실제 조회하여 2023년 1월~2025년 12월 관측 36개를 받았다. 관측 응답과 ITM 메타데이터 66개 모두 단위가 미제공이었다. 한국은행 [2025년 12월 소비자동향조사 결과](https://www.bok.or.kr/portal/bbs/B0000501/view.do?menuNo=200690&nttId=10095310)의 PDF 9쪽 정의에 따라 장기평균 100·장기표준편차 10인 표준화 지수로 분류했다. 문서 해시와 정확한 선택 조건은 [단위 근거 기록](2026-10-22-ccsi-verified-unit.md)에 남겼다.

상대 변화율 `(당월/전월−1)×100`은 표준화 지수값의 계산이며 소비심리 자체의 비율 증가나 한국은행 공식 증감률을 의미하지 않는다. 실제 API 값으로 계산 가능한 35개 변화율을 Decimal 독립 산식과 0.000001 허용 오차로 비교하여 일치했다. 첫 달 결측은 채우지 않았으며 라이브 빈티지와 고정 평가 정답을 섞지 않았다.

## v1.1 평가와 비용 절감

v1.1에서는 동일 입력의 기존 관측 104개를 재사용하고 변경된 파생 질문 2개·후속 기간 편집 8개를 각 프로젝트에서 실행했다. 당시 결과는 정량 충족·정성 검토 대기 113개, 단위 누락 실패 1개, 제외 6개였다. 단위 보완 후 남은 1개만 양쪽에서 다시 실행했다. 최종 합산은 양쪽 각각 **정량 충족·정성 검토 대기 114개, 실패 0개, 제외 6개**이다. 120개 전체 신규 실행이나 사람 검수 완료 점수가 아니다.

후속 편집 8개는 패키지가 기대 기간으로 만든 직접 편집 명령을 검증하므로 자연어 이해의 독립 평가가 아니다. 보고서 관측기는 실제 출력 출처와 paragraphs를 읽으며 정답의 계열명을 관측에 붙이지 않는다. 평가 원본·정답은 수정하지 않았다. [v1.1 상세 기록](2026-10-22-e2e-v11-delta-evaluation.md)과 [앞선 실패 분류](2026-10-22-e2e-v1-failure-review.md)를 함께 참고한다.

v1.1 차등 실행은 실제 Sol 호출 합계 12회, 단위 보완 재평가는 6회였다. 반복 모델 호출 대신 기존 영수증 재관측과 독립 검산을 사용했다. 이 두 단계의 호출 합계는 18회이며 이전 v1 평가 호출까지 포함한 하루 전체 청구 집계가 아니다. 실제 청구 금액은 조회하지 않았다.

## 검증·동기화·보존

단위 보완 직후 local1과 StatBridge1 각각 전체 회귀 2,287개 및 하위 검사 355개, 프런트엔드 빌드, 공개 v4.1 검증 50/70/30이 통과했다. PR 제출용 별도 클론에서도 전체 회귀 2,287개 및 하위 검사 355개, 빌드·공개 검증이 통과했다. 수집한 2,287개 고유 테스트와 113개 모듈을 실행 그룹에 대조했고 그룹별 통과 수는 639·486·659·503개이다. 빌드에는 기존 500KB 초과 청크 경고만 남았다. 이번 변경에는 프런트엔드 코드 수정이 없으며 실제 브라우저 UI를 새로 검증하지 않았다. 모델 평가는 인증 TestClient·고정 자료를 사용했고 라이브 API 자료 확인·검산은 별도로 수행했다.

두 폴더의 실행 코드·스크립트·스키마·테스트는 환경 설정을 제외하고 일치한다. 시작 포트·쿠키 및 프런트엔드 .env 차이는 각 실행 환경을 유지하기 위한 차이다. 과거 문서·평가·연구 파일의 존재 여부까지 두 폴더 전체가 같다고 주장하지 않는다. 오늘 수정한 코드·테스트·문서는 동일하게 반영했다.

환경 설정, 계정·저장 분석·연결 자료의 논리 행과 저장 파일을 읽기 전용 해시로 전후 비교한다. 원본 폴더에서 Git 브랜치 변경·커밋·패키지 설치를 수행하지 않고 별도 클론에서 두 커밋으로 제출한다. 원자료·비공개 평가 사례·정답·예측·사용자 DB·키·실행 로그는 PR에 포함하지 않는다. PR은 사람 검토 대상으로 남기고 병합하지 않는다.
