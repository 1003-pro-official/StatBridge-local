# E2E v1 실패 10개 원인 분리 및 재평가

2026-10-22 · ai-assisted. 이전 [첫 평가 기록](2026-10-22-e2e-v1-evaluation-patches.md)의 원본 104개 정량 충족·10개 실패·6개 제외를 출발점으로 삼았다. 원본 ZIP, 질문, 원래 정답, 채점 결과는 그대로 보존했다.

## 10개 판정의 원인

| 사례 | 주된 원인 | 재검증 결과 |
|---|---|---|
| SBE-0085 | 파생 응답 구조를 읽지 못하는 채점기와 금리차 정답 생성 오류 | 두 계열을 빼는 계산 36개 값이 정답 수정 후보와 일치 |
| SBE-0086 | 고정 원자료의 단위 누락 및 파생 채점 구조 오류 | 단위 미확정으로 차단 유지; 누락된 자료명을 명시 |

| SBE-0090 | 파생 채점 구조 오류 | 분기 표기 정규화 후 동일 검산 충족 |

| SBE-0106 | 동일한 분기 날짜 처리 오류 | 동일 검산 충족 |

주된 평가 문제는 채점기 7개, 금리차 정답 생성 1개, 단위 미제공 1개, 추가 조건 없이 완료를 요구한 계약 1개로 구분했다. 한 사례에 파생 구조 오류 등이 겹칠 수 있다. 산술 오답을 고쳐 점수를 높인 작업은 아니다.

금리차의 원래 정답 생성 코드는 첫 계열의 전기 차이를 계산했다. 질문은 두 계열 사이의 차이를 요청한다. 원본을 덮어쓰지 않고 두 원자료의 같은 시점 차로 수정 후보를 별도 생성했다. 원본·후보 해시와 변경 근거를 기록했으며 사람 승인 전 공식 정답으로 간주하지 않는다.

단위가 빈 소비자심리지수 자료는 로컬 승인 메타데이터에서도 단위를 확정하지 못했다. 임의로 지수 단위를 부여하지 않았다. 연간 매출액증가율의 증감률은 원래 단위가 비율이므로 기존 경제학적 검증이 상대 변화율인지 %p 차이인지 먼저 확인한다. 이 조건을 바꾸어 계산을 강행하지 않았다.

## 함께 발견한 제품 오류와 패치

원자료 검증 실패가 자동 파일 보완 경로를 거치면서 계획을 다시 생성했고, 구체적인 단위 오류가 일반적인 자료 확인 실패로 바뀌었다. 이 동작은 위 평가 문제와 별개의 제품 오류다.

- 원자료 조회·응답 검증 실패는 실제 자료 부재가 확인된 경우와 구분한다. 부재가 확인되지 않으면 같은 계획 재생성이나 파일 요청을 자동 실행하지 않는다.
- 단위 누락을 `source_metadata_incomplete`로 구분하고 자료명·단위 메타데이터 확인 안내·재시도·현재 요청 상태를 보존한다.
- 계획·계산의 검증 오류는 자료 부재 대신 `need_details` 계산 조건 확인으로 반환한다. 실제 API 장애와 원자료 부족은 계속 구분한다.
- 단위 검증, 승인된 출처 검증, 경제학적 의미 검증은 유지한다.

단위 누락 사례는 실제 모델 호출 6회에서 3회로 줄었고 원인 메시지를 유지했다. 계산 조건 사례도 주기를 보완한 뒤 3회 호출로 확인했으며 단순 상태 표시 검증을 위해 다른 문항을 재실행하지 않았다.

## 평가 도구 보완

공개 소스에는 평가 질문·정답 없이 [순수 검산 모듈](../../eval/e2e-contract-review/README.md)과 합성 입력 테스트만 추가했다. 달력 날짜·분기·연간 주기 별칭, 파생 `sources`/`points` 구조, 실제 출처, 피연산자 순서, 단위, 연산, 결측 근거, 수치를 검증한다. 잘못된 날짜·중복 시점·다른 출처·잘못된 값·단위·연산·추가 시점·NaN을 통과시키지 않는다.

고정 자료 어댑터에서 A/Y와 H/S를 정규화했다. 원자료 숫자와 비어 있는 단위는 바꾸지 않았다. 테스트 대역 응답에는 실제 API 계약의 기관·표 필드가 포함되지만 실제 KOSIS 네트워크 조회로 주장하지 않는다.

## 양쪽 실제 재실행 결과

local1과 StatBridge1 각각 파생 8개와 분기 후속 질문 2개를 실제 인증 FastAPI 경로로 재실행했다. 두 프로젝트에서 같은 결과를 얻었다.

- 수정 후보를 포함한 사후 정량 검산: 10개 중 8개 충족·정성 검토 대기, 2개 보류.
- 기존의 다른 104개 관측을 재사용하여 전체를 다시 집계하면 112개 정량 충족·정성 검토 대기, 2개 보류, 6개 제외이다. 이번에 120개 전체를 새로 실행한 것은 아니다.
- 원본 채점기에 동일 관측을 넣으면 구조·정답 문제가 유지되어 여전히 104개 정량 충족·10개 실패·6개 제외이다. 이 기록을 성공으로 덮어쓰지 않았다.
- 사람 정성 검토와 금리차 정답 수정안 승인은 남아 있다. 공식 100% 통과 점수로 표시하지 않는다.

이번 유료 실행은 두 프로젝트 각각 파생 8개를 한 번 실행하고, 마지막 조건 안내 수정 후 연간 사례 1개만 추가 실행했다. 모델 HTTP 호출은 각각 27회, 합계 54회이며 실제 응답 모델은 `gpt-6.1-sol`이다. local1 입력/출력 토큰은 126,430/4,989, StatBridge1은 126,464/5,135이다. 실제 청구 금액은 조회하지 않았다. 원자료는 고정 자료이고 브라우저·라이브 KOSIS 검증은 포함하지 않는다.

## 보존 및 재현

검증은 양쪽 각각 전체 2,262개와 하위 검사 355개 통과, 마지막 조건 안내 보완 후 관련 회귀 72개 재실행 통과, 최종 검산 모듈 합성 회귀 22개 재실행 통과이다. 마지막 관련 회귀에는 새 테스트 1개가 포함되어 최종 수집 목록은 2,263개이다. 전체 실행 그룹의 모듈 목록과 최종 수집 목록을 비교하여 중복·누락을 확인한다. TypeScript/Vite 빌드와 공개 v4.1 검증(`50/70/30`)도 양쪽에서 통과했다.

수정한 코드·검산 모듈·합성 테스트·문서를 두 프로젝트에 동일하게 반영하고 환경 변수·포트·쿠키·사용자 DB·저장 분석을 복사하지 않았다. 전후 감사로 `.env`, 사용자·저장 분석·연결 자료, 저장 파일의 내용 보존을 확인한다.

비공개 관측 기록은 local1의 Git 무시 경로 `.venv/cache/statbridge-e2e-v1-review-20261022`에 있다. `failure-review.json`에 사례별 원인과 양쪽 결과, `proposed-oracle-corrections.json`에 정답 수정 후보와 해시, `*-derived-predictions.jsonl`, `*-followup-predictions.jsonl`, `*-conditions-predictions.jsonl`에 관측을 분리 저장했다. `review_results.py`는 실행 후에만 정답을 읽어 사후 검산한다. 유료 실행기의 모델 입력에는 질문과 승인 메타데이터만 전달한다.

실행 명령과 환경은 같은 경로의 `run_derived.py`, `run_followups.py`, `run_full_tests.py`, `run_final_groups.py`에 남겼다. 유료 출력 파일이 이미 있으면 자동 재실행을 중단한다. 원본 평가 기록 폴더는 수정하지 않았다.
