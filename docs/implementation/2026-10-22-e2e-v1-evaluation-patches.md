# StatBridge E2E v1 평가와 제품 보완

작성일: 2026-10-22. ai-assisted. 원본 ZIP·질문·정답·허용 오차는 변경하지 않았다. 사람 정성 검토는 대기 상태이며 공식 100% 성능으로 표시하지 않는다.

## 평가 범위

`statbridge-e2e-v1-handoff.zip` SHA-256은 `94504db561702f77ee22e7511fc2ea9a11aee711243bb8424b9171c84966afd4`이다. 개발·테스트 120문항 중 6문항은 패키지 정의에 따라 제외한다. 조회·출력 78, 편집 8, 후속 질문 8, 파생 8, 보고서 12문항을 실행하였다. holdout 질문은 개발 피드백에 사용하지 않았다.

실행은 제공된 고정 원자료와 실제 인증 FastAPI 라우트를 사용했다. KOSIS 실시간 조회나 브라우저 조작 검증이 아니다. 임시 계정 DB를 사용하였으며 제품 출처·단위·경제학적 의미 검증을 해제하지 않았다. 편집 실행기는 기대 편집 상태로 명령을 구성하므로 자연어 편집 이해 성능으로 해석하지 않는다.

## 제품 수정

1. 동일한 표·표시 이름이라도 항목·분류 코드가 다르면 출력 계열을 분리한다. 같은 계열·같은 시점의 상충 값은 계속 차단한다.
2. 출력 명세에 실제 응답의 표·항목·분류·주기를 `sourceIdentity`로 보존한다. 원자료 출처를 계산 결과로 잘못 표시하지 않는다.
3. 조회 완료 `need_output_config` 응답에도 검증된 대화 상태를 전달한다.
4. “다른 기간으로” 등 자연스러운 기간 후속 질문을 인식한다. 지표가 명시된 새 요청은 기간 전용 요청으로 취급하지 않는다.
5. 후속 질문의 출력 재검증에서 서버가 확정한 기간만 원래 계획에 적용하여 비교한다. 항목·분류 등 다른 계획 속성의 검증은 유지한다.

위 변경과 회귀 테스트를 local1과 StatBridge1에 동일하게 반영했다. 포트·쿠키·환경 변수·계정·저장 분석은 복사하지 않았다.

## 평가 결과와 도구 한계

최초 원본 실행: 94개 중 68개 정량 충족, 26개 미관측. 수정 후 조회·출력 78개와 편집 8개는 모두 정량 충족이다. 보고서 12개는 실제 모델 답변을 받았고 원본의 자료·기간 계약을 충족했다. 보고서 문장 품질은 사람이 검토해야 한다.

최종 원본 채점기는 120개 중 정량 충족·정성 검토 대기 104, 실패 10, 제외 6을 반환했다. 이 숫자는 수정하지 않았다. 실패에는 아래 도구 문제가 포함된다.

- 후속 질문 8개는 모두 실제 출력까지 진행하고 출처·기간 별도 검사를 통과했다. 원본 채점기는 분기 말 달력 날짜의 마지막 숫자로 분기를 읽어 분기 사례 2개를 실패로 처리한다.
- 파생 사례의 기대 스키마는 `sources`와 단일 계산 결과 `points`인데 원본 채점기는 `expected.series`와 `oracle.series`를 요구하므로 파생 8개를 올바르게 채점하지 못한다.
- 별도 사후 검산에서 파생 5개는 출처·수치·결측 이력이 제공 정답과 일치했다. 결측 시점은 실제 계산 영수증의 결측 사유가 있는 경우에만 확인했으며 값을 채우지 않았다.
- 금리차 사례는 실제 두 원자료의 차와 출력 36개 값이 모두 일치한다. 그러나 `build_cases.py`가 두 계열 차 대신 첫 계열의 시점 간 차를 정답으로 작성한다. 원본 정답은 유지하였다.
- 소비자심리지수 고정 자료에는 단위가 비어 있다. 제품이 단위 미확정 자료를 차단했으며 임의 단위를 넣지 않았다.
- 기업경영분석 고정 자료는 연간 `A`, 제품 정규 주기는 `Y`이다. 정확한 키만 받는 고정 자료 어댑터에서 조회가 막혔다. 연간 주기 별칭 정규화 후 이 사례의 별도 재평가가 필요하다.

즉, 100% 통과로 결론 내리지 않는다. 남은 패키지 스키마·정답·자료 계약 보완은 평가 담당자가 검토해야 한다. 위 검산은 원본 점수와 합산한 공식 점수가 아니다.

## 유료 실행

사용자가 비용 상한 없이 평가에 필요한 호출을 승인하였다. 최초 20개를 각 1회 실행했고, 고정 자료 어댑터의 기관·표 필드 누락을 확인한 뒤 파생 8개만 응답 계약을 보완해 재실행했다. 통계 수치는 변경하지 않았다. 이 응답 정규화는 테스트 대역이며 실제 KOSIS 호출의 증거가 아니다.

총 28회 사례 실행에서 실제 모델 HTTP 호출 114회, 입력 토큰 403,477개, 출력 토큰 18,353개를 관측했다. 응답 본문에서 `gpt-6.1-sol`, `gpt-6-luna` 모델명을 확인했다. 실제 청구 금액은 조회하지 않았으므로 달러 비용을 추정하지 않는다. 실패 자료에서 자동 보완 경로가 계획을 다시 호출하므로 사례 수와 모델 호출 수는 다르다.

## 회귀 검증과 보존

두 폴더 각각 전체 회귀 2,235개·하위 검사 355개가 통과했다. 마지막 기간 보완 이후 관련 회귀 43개씩을 다시 실행했고 모두 통과했다. 여기에 새 회귀 1개가 포함된다. 양쪽 프런트엔드 빌드와 `git diff --check`도 통과했다. 실제 UI 브라우저 검증과 라이브 KOSIS 검증은 이번 결과에 포함하지 않는다.

전후 읽기 전용 감사에서 local1의 사용자 5·분석 9·연결 자료 219개 및 저장 파일 19개, StatBridge1의 사용자 4·분석 5·연결 자료 187개 및 저장 파일 6개가 보존되었다. `.env`와 계정 데이터 논리 해시도 동일하다.

## 재현 기록 위치

비공개 실행 기록은 local1의 Git 무시 경로 `.venv/cache/statbridge-e2e-v1-handoff-20261022`에 보존한다. 원본 예측·수정 후 예측·채점 결과·모델 사용량·보존 감사는 별도 파일이다. 평가 질문·기대 계약·정답·원자료·사용자 자료·API 키는 이 문서나 공개 소스에 복사하지 않았다.

원본 채점 재현: 패키지 `scripts/score.py`에 해당 캐시의 `combined-final-predictions.jsonl`과 `--output`을 지정한다. 별도 검산은 캐시의 `supplemental.py`, 회귀 재현은 `run_final_groups.py`와 `run_full_tests.py`에 기록하였다. 유료 재실행은 자동으로 반복하지 않도록 기존 출력 파일 존재 시 중단한다.
