# 보고서 표 편집과 최신 5개 보관함 (2026-10-19, ai-assisted)

## 사용 흐름

분석 결과에서 **표**를 선택하고 **상세 표 편집 시작**을 누릅니다. 기존 저장 분석도 다시 불러와 같은 편집기를 사용할 수 있습니다. 원자료 수치 입력 기능은 제공하지 않습니다.

1. 셀을 클릭하거나 대상 종류에서 셀/행/열/머리글을 선택합니다. 글자 크기·굵기·색·정렬·소수점·양수 부호·0 대시·테두리와 행 높이/열 너비를 변경합니다. 표시 이름은 원자료 이름과 별도로 저장합니다.
2. 인접 열을 선택해 다단 머리글을 만듭니다. 하위 머리글은 바로 위 그룹 안에 있어야 하며 겹치는 병합은 거부합니다. 인접 행도 최대 4단계 그룹으로 묶습니다. 그룹 이름은 합계를 새로 계산하지 않습니다.
3. 지표가 행인 표에서 실제 기준 A와 현재 B를 선택합니다. 차이 B−A, 증가율 (B/A−1)×100, 배수 B/A, 증감(증가율)을 추가할 수 있습니다. %의 차이는 %p로 기록합니다. 증가율 기준값이 0 이하이거나 원자료가 없으면 계산 불가 사유를 남깁니다.
4. 연간·분기 관측값을 한 표에 직접 배치하려면 시점을 행으로 바꾸고 같은 단위의 원자료 계열을 명시적으로 결합합니다. 연도와 분기 행은 각각 보존하며 합산·평균·보간하지 않습니다. 그래프는 기존 주기·단위 검증을 계속 적용합니다.
5. 조사 시계별 A/B처럼 일반 시계열 행·열 배치와 다른 표는 **원자료 참조 배치**로 행·열을 만든 뒤 각 셀에 조회된 계열과 시점을 연결합니다. 선택적으로 같은 계열의 실제 기준 A와 차이를 계산합니다. 없는 값이나 임의 숫자를 입력할 수 없습니다.
6. 셀/행/열/머리글 각주와 전체 표 각주를 연결합니다. **셀별 원자료·계산 근거**에서 계열·시점·주기·단위와 A/B 관측값을 확인합니다.
7. **파일 내보내기**에서 XLSX/CSV/PDF/PNG를 선택합니다. XLSX는 다단 머리글 병합, 서식, 열 너비/행 높이, 반복 머리글, 인쇄 영역을 저장하고 `계산근거` 시트에 원래 정밀도의 수치와 산식을 별도로 저장합니다. CSV는 계층 머리글을 행으로 평탄화합니다. PDF/PNG는 큰 표를 가로·세로로 분할하고 식별 열을 반복합니다.
8. 기존 되돌리기/다시 실행, 분석 저장, 설정 JSON 저장/복원을 그대로 사용합니다. 검증·렌더링 실패 시 이전 표와 편집 이력을 보존합니다.

## 구현 경로

UI `RichTableEditor.tsx` → 기존 `set_table` 직접 명령 → `research_chart_editing.py`/`TableOptions` → 닫힌 `TableLayout` 검증 → 관측값 참조 기반 `apply_layout` → 같은 layoutSections로 화면·내보내기 생성. 서식 편집에는 GPT나 KOSIS 재조회가 필요하지 않습니다. 원자료를 추가·기간 변경할 때에는 기존 데이터 검증 경로를 따릅니다. 숨김/교체로 기존 서식 대상이 사라지면 이전 표를 유지하고 대상 재선택이 필요합니다.

최대 120열·600행, 병합 40개·행 그룹 30개, 사용자 서식 500개, 계산 열 12개, 각주 40개, 인쇄 최대 120쪽을 제한합니다. 미허용 속성·임의 코드·없는 참조·중복 주기 값·교차 구역 병합을 거부합니다. Excel 문자열은 수식으로 기록하지 않으며 CSV 수식 삽입도 차단합니다.

## 분석 보관함 수정

원인은 계정 저장 5개와 브라우저 임시 분석 전체를 합칠 때 통합 목록 제한이 없었던 것입니다. ID로 합친 뒤 최신 시점순 **주 목록 5개**만 표시합니다. 기존 초과 기록은 삭제하지 않고 **이전 기록**에서 열 수 있습니다. 브라우저 활성 저장 키는 5개로 유지하고 이전 대화는 계정별 보존 키에 먼저 기록합니다. 보존 쓰기에 실패하면 기존 활성 자료를 건드리지 않습니다.

서버의 기존 BEGIN IMMEDIATE 기반 동시 저장 제한은 유지합니다. `/api/account/graphs`는 활성 `items` 최대 5개와 레거시 `olderItems`를 나눠 반환합니다. 새 여섯 번째 서버 저장은 기존처럼 409로 안내하며 기존 5개를 자동 삭제하지 않습니다. 기존 계정/저장 파일/.env는 두 폴더 간 동기화하지 않습니다.

## 평가 범위

`eval/report_table/evaluation_plan.json`과 `reference_cases.json`을 참고합니다. 첨부 PDF 물리적 5·13·18쪽에서 발췌한 88개 관측값과 독립 Decimal 수식으로 22개 계산 셀을 검증합니다. 기존 6개 표 양식·계정 보호 회귀도 함께 실행합니다. 모델 판정이나 모델 생성 정답을 사용하지 않습니다.

외부 HTTP 전송을 차단한 `tools/run_table_edit_eval.py`는 GPT 호출 0건으로 실행합니다. 실제 UI 검증은 별도 계정 DB의 참조 표와 두 정상 앱의 기존 저장 분석을 구분해서 수행합니다. 참조 PDF 검증을 실시간 KOSIS API 검증으로 보고하지 않습니다. 원본 첨부 파일·계정 DB·생성 파일·평가 로그는 공개 커밋에 포함하지 않습니다.

대표 표의 구조·편집·수치·파일 검증이며 원본 PDF의 픽셀 단위 복제, ZIP 모든 표 완전 재현, 전문가 통계 의미 승인을 의미하지 않습니다. 13쪽은 주요 2개 항목/7개 연·분기 행, 5쪽은 4개 응답 구간의 발췌입니다. XLSX는 openpyxl, PDF/PNG는 기존 matplotlib/Pillow 의존성을 재사용합니다.

실행 결과와 실제 UI 증거는 동일 폴더의 table-editor 검증 보고서 및 각 프로젝트 `.venv/cache/table-editor-20261019/`에 기록합니다.
