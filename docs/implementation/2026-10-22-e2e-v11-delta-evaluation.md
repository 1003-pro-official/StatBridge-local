## 원본과 비교

## 실행과 재사용

각 프로젝트에서 다음과 같이 진행했다.

| 구분 | 개수 | 처리 |
|---|---:|---|
| 변경된 파생 질문 | 2 | 실제 Sol 모델과 인증 API 경로로 신규 실행 |
| 변경된 후속 기간 편집 경로 | 8 | 외부 네트워크를 차단하고 실제 인증 API로 신규 실행 |
| 입력이 동일한 기존 관측 | 104 | 모델 재호출 없이 보존된 실제 결과 재사용 및 v1.1 채점 |
| Tier C | 6 | 패키지 정의에 따라 제외 |

질문이 같은지 비교한 뒤 기존 결과를 재사용했다. 각 항목의 재사용 여부와 출처는 별도 원장에 기록했다. 이전 관측에는 프로젝트 간 코드가 동일한 상태에서 공유한 관측도 있으므로, 재사용한 104개를 이번에 양쪽에서 새로 실행했다고 주장하지 않는다. 재사용 집합에는 단위 누락으로 이미 차단한 1개도 포함하며 이를 성공으로 바꾸지 않았다.

새로 실행한 파생 2개와 후속 기간 편집 8개는 두 프로젝트 모두 v1.1 정량 조건을 충족했다. 기존 104개 관측을 합쳐 다시 채점한 결과는 각각 **정량 충족·정성 검토 대기 113개, 실패 1개, 제외 6개**이다. 120개 전체의 신규 실행이나 정성 평가 완료를 의미하지 않는다.

후속 기간 편집 실행기는 패키지 정의에 따라 기대 기간으로 직접 편집 명령을 구성한다. 따라서 이 결과는 기간 편집 API 경로의 검증이며 자연어 후속 질문 이해 능력의 독립적인 점수가 아니다.

## 남은 실패

소비자심리지수의 고정 원자료 단위는 v1.1에서도 빈 값이며 `unit_status`는 `unconfirmed`이다. 제품은 원자료 단위를 임의로 만들어 계산하지 않고 `source_metadata_incomplete`로 차단한다. 그러나 평가 기대 결과는 여전히 계산 완료이므로 원본 v1.1 채점기에서는 실패로 남는다. 이 실패를 통과나 제외로 고치지 않았다.

공식 근거로 단위를 보완하거나, 해당 문항을 단위 확인 안내 시나리오로 정의하는 평가 결정이 필요하다. 이번 작업에서 실제 KOSIS 네트워크의 단위를 새로 확인한 것은 아니다.

## 관측기 보완

v1.1 `run_model.py`의 보고서 관측 함수는 출처 ID를 실제 출력에서 읽지 않고 `expected.series` 순서로 붙인다. 또한 현재 API의 보고서 본문인 `paragraphs`를 읽지 않아 실제 답변이 있어도 본문을 누락한다.

이를 보완하는 `eval/e2e-contract-review/observations.py`와 합성 회귀 테스트를 양쪽 프로젝트에 동일하게 추가했다. 이 함수는 정답을 인자로 받지 않고 실제 `sourceIdentity`와 본문·문단·주장을 읽는다. 출처나 본문이 없으면 관측 실패로 처리한다. 보존된 실제 보고서 응답에도 적용해 추가 모델 호출 없이 출처와 본문을 확인했다. 보고서 문장 품질에 대한 사람 검토는 남아 있다.

평가 ZIP의 원래 실행기를 덮어쓰지 않고 별도 호환 관측기를 사용했다. 유료 경로는 실제 인증 FastAPI TestClient와 고정 원자료를 사용했으며, 패키지의 Playwright 브라우저 로그인 경로와 라이브 KOSIS 호출은 이번 실행에 포함하지 않는다. 비용 상한 없는 사용자의 기존 승인을 별도 어댑터에서 사용했으며, 원본 승인 파일에 허위 비용 상한을 입력하지 않았다.

## 비공개 재현 기록

local1의 `.venv/cache/statbridge-e2e-v1.1-review-20261022`에 원본 압축 해제본과 차등 실행 기록을 보존했다. `selection.json`은 실행 대상, `*-reuse-ledger.json`은 재사용 원장, `*-combined.jsonl`은 원본 관측과 신규 관측의 결합본, `*-score.json`과 `delta-summary.json`은 v1.1 채점 결과다.
