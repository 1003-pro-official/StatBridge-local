# 이모티콘 클릭 이동 및 편집 후 사라짐 수정

`StatBridge-local1`만 수정했다. 기존 지표 해석·이모티콘 작업은 유지했다.

## 원인과 변경

1. `StickerEditor.tsx`의 빈 배치 영역 pointer down이 현재 선택한 이모티콘의 x/y를 클릭 위치로 바꿨다. 이 동작을 제거하고 선택 해제만 수행한다. 이동은 이모티콘 드래그 또는 방향키로만 한다.
2. 이모티콘 배치는 별도 컴포넌트의 미적용 상태에 있었고, 채팅 요청에는 포함되지 않았다. 텍스트 편집 후 새 그래프 버전이 오면 저장되지 않은 배치가 사라졌다. `ChartSketchEditor.tsx`에서 현재 버전의 배치 초안을 공유받아 텍스트 요청에 함께 전달한다.
3. 기존 API는 이모티콘 목록과 텍스트 편집의 동시 적용을 거부했다. `bridge_api.py`에서 같은 요청의 배치를 편집 기준 상태에 적용한 뒤 텍스트/그림 지시를 실행한다. 기간 변경 시에도 새 데이터의 기준 그래프에 배치를 반영한다. 중간 기준 상태를 세션에 저장하지 않으므로 실패하면 기존 저장 상태를 유지하고 성공하면 한 번의 되돌리기로 두 변경을 함께 취소한다.
4. 사이드바 닫기/재열기에 따른 컴포넌트 재생성에서도 최신 초안을 읽는다. React 자식 노드 생성 당시의 오래된 초안이 아니라 재열기 시점의 버전별 초안을 사용한다. 새 버전과 이전 버전의 초안을 섞지 않는다.

- 전체 Python 회귀: **705 passed, 355 subtests passed**, 303.87초.
- 프런트 좌표·드래그·회전 변환: **4 passed**.
- 최종 `pnpm build`: 성공. 기존 대형 번들 경고만 남아 있다.
- `git diff --check`: 통과.

실제 브라우저에서 합성 관측 데이터, 실제 Plotly 렌더러·편집 API 및 실제 수정 모델을 사용했다. 외부 통계 수치 재조회는 이번 UI 검증에 포함하지 않았다.

- 빨간 화살표 추가 후 드래그.
- 빈 그래프 영역 클릭 전/후 스타일 동일: `left:345.5px; top:239px; width:108.6px; height:108.6px`. 선택은 해제됐다.
- 채팅 입력란 클릭 후에도 위치가 유지됐다.
- 별도 이모티콘 적용 버튼을 누르지 않고 제목 수정 전송. 반환된 그래프에 이미지 화살표가 그대로 렌더링됐다.
- 수정이를 재열어 같은 좌표와 크기를 확인했다.
- 방향키로 위치를 `left:340.5px`로 바꾼 미적용 초안도 사이드바 닫기/재열기 후 `left:340.5px`로 유지됐다.
- 검증 화면: `.venv/cache/sticker-placement-fixed.png` (합성 데이터).

이번 변경은 배치·보존 흐름을 수정한다. 이미지 내용을 분석하는 모델 능력이나 이미지 안의 그림을 자연어로 다시 그리는 기능을 추가한 것은 아니다. 브라우저 새로고침·서버 재시작 시의 세션 저장 정책은 기존 정책을 따른다.
