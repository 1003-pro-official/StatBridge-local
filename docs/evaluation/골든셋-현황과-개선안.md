# 골든셋 현황과 개선안

> 기준: 2026-09-28 당시의 전체 흐름 v1(현재 `eval/end-to-end/v1/`)과 `tools/evaluate_golden_set.py`. 표 탐색 v3는 검토 범위에서 제외했다.

## 먼저 알아둘 점

골든셋은 **질문과 기대 결과를 미리 적어 둔 시험지**다. 현재 시험지에는 질문 150개가 있고, 그중 30개에는 그래프의 시점·값·단위를 확인할 고정 데이터가 있다. 한국은행 간행물 6종의 공개 자료를 질문 소재로 사용하지만, 정답 통계표 ID는 프로젝트가 지원하는 로컬 카탈로그에서 지정한다. 간행물의 전망치를 관측값 정답으로 쓰지는 않는다.

지금 평가 결과는 유용하다. 다만 일부 검사는 검색이나 그래프 생성의 **한 단계**만 확인한다. 높은 점수를 곧바로 “사용자가 질문하면 원하는 그래프까지 정확히 나온다”는 뜻으로 읽으면 안 된다.

## 현재 확인된 결과

| 검사 | 이번 실행 결과 | 정확히 확인한 것 |
| --- | ---: | --- |
| 검색 Recall@5 | 120/120, 100% | 필요한 통계표가 상위 5개 후보에 들어왔는가. 복수 지표는 필수 계열 그룹별로 계산한다. |
| 검색 Top-1 | 103/120, 85.83% | 첫 번째 후보가 허용 정답 표인가. 복수 지표 질문에서는 첫 표 하나만 맞아도 통과할 수 있다. |
| 역질문 | 15/15 | `need_clarification` 상태이고 필요한 통계표가 선택지에 포함됐는가. |
| 범위 밖 질문 | 15/15 | 검색기가 후보를 빈 목록으로 돌려줬는가. |
| 그래프 데이터 | 30/30 | **정답 계열을 미리 지정해** 로컬 CSV 분석 경로를 실행했을 때 시점·값·단위·주기가 고정 데이터와 일치하는가. |

위 수치는 프로젝트의 로컬 평가기를 다시 실행한 결과다. 개발 50개와 보류 평가 100개가 포함돼 있지만, 보류 평가 질문도 개발 중 검색 규칙 조정에 사용됐다. 따라서 이 점수는 **현재 자료에 대한 회고적 결과**이며, 새 질문에서의 성능을 예측하는 독립 평가 점수는 아니다.

## 무엇이 문제인가

| 문제 | 쉬운 설명 | 개선 방향 |
| --- | --- | --- |
| 보류 평가의 독립성 부족 | 시험 문제를 보고 연습한 뒤 같은 문제로 다시 점수를 낸 상태다. | 현재 150개는 회귀 검사에 유지하고, 새 미공개 질문을 별도 블라인드 평가로 수집한다. |
| 좋은 후보와 올바른 최종 결과가 다름 | 상위 5개에 정답이 있어도 실제 첫 선택이나 그래프 계열이 틀릴 수 있다. | 검색 점수와 최종 선택·실행 성공률을 별도 지표로 기록한다. |
| 복수 지표의 정확한 조합 미측정 | “대출금리와 수신금리를 비교해줘”에서 두 표가 후보에 있어도 둘 다 최종 결과에 나타나는지는 검사하지 않는다. | 기대 표 집합과 실제 최종 계열 집합의 완전 일치율을 추가한다. |
| 역질문 검사의 범위가 좁음 | 현재 15/15는 필요한 선택지가 보이는지 확인한다. 불필요한 질문을 했는지, 사용자의 답을 반영했는지는 이 수치에 없다. | 질문 필요 여부, 선택지 적절성, 답변 반영을 나눠 채점한다. 일반적인 표 선택과 의미가 모호해서 필요한 역질문도 구분한다. |
| 후속 질문 사례 없음 | “그럼 작년은?”처럼 앞선 질문을 이어받는 대화는 현재 150개에 없다. | 이전 질문·선택·기간을 포함한 다회차 사례를 추가한다. |
| 카탈로그 전용 표 사례 없음 | 로컬 수치 CSV가 없어도 검색 가능한 표를 골든셋에서 별도로 채점하지 않는다. 관련 기능은 단위 테스트에만 있다. | 카탈로그 검색 성공과 로컬 데이터가 없는 상태의 KOSIS 조회·오류 처리를 구분하는 사례를 추가한다. |
| 범위 밖 판정은 검색 단계 중심 | 15/15는 후보가 비는지 확인한 수치다. 실제 API 응답이 항상 안전하게 `no_match`가 되는지는 별도로 확인해야 한다. | 검색기와 실제 API의 무결과 판정을 같은 질문으로 각각 측정한다. |
| 그래프 30/30의 적용 범위가 제한됨 | 그래프 검사는 표·항목·분류 ID를 정답에서 직접 전달한다. 자연어 해석부터 계열 선택까지 통과했다는 증거는 아니다. 실제 KOSIS 호출과 SVG 가독성도 이 검사에 포함되지 않는다. | 자연어→선택→그래프 통합 사례를 추가하고, 고정 데이터 정확성·실시간 API·시각 품질을 각각 보고한다. |

## 어떤 순서로 개선할까

1. **점수 이름과 분모를 고정한다.** Recall@5, Top-1, 단일 표, 복수 지표 완전 일치, 역질문 판단, 후속 질문, 무결과, 카탈로그 전용 표를 각각 무엇으로 채점하는지 명시한다. 이전에 제시된 목표표는 평가 대상과 계산 방식이 같다고 확인될 때만 이번 수치와 비교한다.
2. **빠진 대화·실행 검사를 추가한다.** 복수 지표의 최종 계열, 불필요한 역질문, 답변 후 상태, 후속 질문, 카탈로그 전용 표, 실제 API의 무결과 처리를 사례로 만든다. 그래프 검사는 기존의 고정 데이터 검사와 자연어 전체 흐름 검사를 분리한다.
3. **새 블라인드 평가를 만든다.** 현재 150개는 버그 재발을 막는 용도로 쓰고, 규칙 조정에 사용하지 않을 새 질문을 별도로 모아 한 번에 평가한다. 한국은행 출처, 정답 표와 판정 근거는 계속 기록한다.
4. **실패 유형별로 제품을 고친다.** 정답이 후보에 없으면 검색어·별칭을, 후보에는 있지만 첫 선택이 틀리면 순위를, 선택 후 결과가 틀리면 대화 상태·계열 계획·차트 경로를 점검한다. 수정 후 기존 사례와 새 블라인드 사례를 모두 재평가한다.

## 보고할 때의 기준

`100%`라는 숫자만 쓰지 말고 **어느 단계에서 몇 건 중 몇 건인지** 함께 적는다. 예를 들어 “그래프 정확도 100%” 대신 “정답 계열을 지정한 로컬 CSV 그래프 데이터 검사 30/30”이라고 쓴다. 아직 평가하지 않은 Followup과 Catalog-only는 `미측정`으로 표시한다.

재현 명령은 프로젝트 루트에서 `.venv/bin/python tools/evaluate_golden_set.py`다. 골든셋의 구성·출처와 현재 평가 범위는 [골든셋 README](../../eval/end-to-end/v1/README.md), [manifest](../../eval/end-to-end/v1/manifest.json), [평가 코드](../../tools/evaluate_golden_set.py)에서 확인할 수 있다.
