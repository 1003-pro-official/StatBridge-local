### 핵심 결론 7가지

1. **검색·해석 엔진의 핵심은 실제로 동작한다.** HCX-003/007, 규칙 사전(347표), 하이브리드(벡터+리랭커), KOSIS·로컬 CSV 조회, 역질문, catalog_only 차단까지 실행으로 확인했다. v4.1 test R@1 0.889 / R@5 0.944.
2. **가장 큰 문서-실제 격차는 "실행기(launcher)"다.** `START_STATBRIDGE.cmd`는 **2개 프로세스만** 띄운다. `.venv_runtime` 생성, winget 설치, `.env` 키 검사, 포트 정리, `/api/health`·프런트 확인 후 브라우저 열기, MCP stdio 3번째 프로세스는 **코드에 없다**. `WORK_SUMMARY:51-55`·`ARCH:157-169`가 서술한 동작과 정면 불일치.
3. **UI/프런트엔드 계층은 자동 테스트가 0이다.** F영역 17항목 중 16개가 🟡. 테스트 러너 자체가 없고 CI는 `tsc --noEmit && vite build`만 돈다.
4. **평가 산출물 재현성이 깨져 있다.** 보고서가 인용하는 결과 JSON/trace/캐시(`golden_v41_*_results.json`, `v41_holdout_patch_trace.jsonl`, `embedding_cache.json`)가 저장소에 없고(gitignore), ablation 문서 수치는 현재 코드로 재현되지 않는다(문서 R@1 69.57~83.70% vs 실측 50.0~85.19%).
5. **dead code/이중 구현이 남아 있다.** `src/agent/statbridge_agent/{pipeline.py,nodes/*,tools.py,hcx.py}`는 UI 경로에서 호출되지 않는다(`__init__.py`는 `agent_runtime.StatBridgeAgent`만 재노출). HCX 클라이언트도 2개.
6. **`catalog_only`는 특정 표현에서만 발동한다.** `상세자금순환표 ...` 계열은 catalog_only로 수치 차단이 되지만, HCX 정규화를 거친 `"상세자금순환표 잔액 알려줘"`는 `no_match`로 떨어진다(경계 동작 불일치).
7. **문서 불일치가 다수 실재한다**(§8). 특히 표 수 347 vs 349, 역질문 그룹 11 vs 런타임 23, MCP 도구명 `query_data` vs `get_statistics`, env 위치/키 이름, 상태 enum.

### 환경 발견사항
- **`.venv`는 Windows venv(Python 3.11.9, `Scripts/`)** 다. `AGENTS.md`·`README.md`의 `.venv/bin/python` 명령은 이 환경에서 그대로 동작하지 않는다(로그로 확인).
- 프런트는 **OS별 TypeScript 네이티브 패키지**가 필요하다. Windows에서 설치한 `node_modules` 그대로는 Linux(WSL)에서 `tsc`가 실패(`@typescript/typescript-linux-x64` 부재) → `CI=true pnpm install --frozen-lockfile`로 해결. `package.json`이 의존성 버전을 `"latest"`로 고정해 재현 드리프트 위험이 있다(TypeScript 7.0.2 preview가 설치됨).
- pytest 수집은 `test_*.py`만 대상이라 `tests/TEST_AGENT_FLOW.py`, `tests/TEST_NCP_MODELS.py`(**대문자 `TEST_`**)는 CI에서 실행되지 않는다. HCX/역질문/MCP 인자 관련 핵심 단언이 이 파일들에만 있다.

1. **(P0) 런처 정합화**: `START_STATBRIDGE.cmd`를 문서대로 구현(3프로세스·health/프런트 확인·브라우저·포트 정리)하거나, 문서를 실제 2프로세스 동작에 맞게 수정. `WORK_SUMMARY:51-55`가 현재 사실과 반대다.
2. **(P0) 평가 산출물 커밋/재생성 경로 고정**: `finalize_golden_v41.py` 입력 파일과 결과를 재현 가능하게 만들고, ablation 문서 수치를 최신 실측으로 갱신.
3. **(P1) 프런트 테스트 도입**: 최소 smoke(vitest + React Testing Library)로 카탈로그·역질문 패널·차트 렌더를 고정.
4. **(P1) 문서 현행화**: §8의 1·3·4·5·6·8·12 항목과 N3/N4/N5를 일괄 수정.
5. **(P1) dead code 제거 또는 명시**: `statbridge_agent` 미사용 모듈과 중복 HCX 클라이언트.
6. **(P2) 기간 입력 견고화**: 비-ISO 포맷 처리 또는 400 메시지 정비, 완전범위 밖 동작을 문서에 반영.
7. **(P2) `catalog_only` 표현 견고화**: HCX 정규화 후에도 catalog_only 용어가 보존되도록 처리.
8. **(P2) `rerank_score` 의미 명확화**: 순위 파생값임을 문서화하거나 실제 점수 사용.
