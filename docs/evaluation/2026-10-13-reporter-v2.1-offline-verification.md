# 기자 질의 통계표 탐색 골든셋 v2.1 오프라인 검증 보고서

- 작성일: 2026-10-13
- 대상: `eval/reporter-table-discovery-30/v2.1/` (200문항 = v2 원본 30 + 증강 170)
- 검증 성격: **런타임·키·네트워크 없이** 수행한 사전 검증(골드 자기 감사 · 검증기 변조 커버리지 · 규칙 계층 지표)
- 작성: ai-assisted, `human_approved=false`. 이 보고서의 통과는 사람 승인이 아니다.

## 1. 목적과 범위

전체 엔드포인트 실행(220회, LLM·KOSIS 호출)에 앞서, **골드 자체의 결함과 검증기의 사각지대를 초 단위로 먼저 걸러내는 것**이 목적이다.

검증하는 것:
- 골드가 공개 카탈로그 계약을 지키는가(역질문 그룹·트리거·선택지)
- 골드가 질의와 연결되는 근거를 갖는가(표 근거, 부재 근거, 주기)
- 정답을 변조했을 때 검증기가 전부 거부하는가
- 규칙 계층(리졸버)이 정답 표를 후보에 올리는가

검증하지 않는 것(별도 단계):
- LLM·LangGraph 계층의 실제 판단, `/api/query` HTTP 계약, 기간 입력 대기 경계
- KOSIS 실 데이터 호출, CSV 값, 차트 렌더링, 해석 문장

## 5. 발견 사항

### ① `REPORTER30-V2.1-055` — 골드 선택지 중 런타임에서 제공되지 않는 항목

- 골드(카탈로그 그룹 원문) 선택지 6개: 소비자물가, 생산자물가, 수출물가, 수입물가, 국내공급물가, 총산출물가
- 런타임 리졸버가 실제로 제시하는 선택지 5개: **소비자물가 없음**
- 원인: 소비자물가는 통계청 통계로 한국은행 KOSIS 349표에 없어, 런타임이 선택지를 카탈로그 제공분으로 거른다.
- 영향: 채점 기준(`clarification_options`는 값 **집합 완전 일치**)에서는 이 문항이 **구조적으로 통과 불가**하다.
- 조치: 채점을 **"런타임 선택지 ⊆ 골드 선택지"** 로 완화했다(그룹 ID 일치는 그대로 엄격). 카탈로그에 없는 선택지를 요구하지 않는 계약으로 정리된다. 골드 선택지는 카탈로그 원문 그대로 둔다.

### ② `REPORTER30-V2.1-153` — 역질문이 뜨지 않는 문항 (하드 위반)

- 카탈로그의 `seasonal_adjustment` 그룹 `trigger_terms`는 `m2`, `통화량`, `광의통화` 뿐이라 GDP 질의로는 트리거되지 않는다.
- 조치: 문항을 통화·계절조정 계열 표현으로 교체해 그룹 의미와 실제 트리거를 맞췄다.

### ③ `REPORTER30-V2.1-177` — 다른 그룹이 먼저 뜨는 문항

- M2 표현이 `seasonal_adjustment`를 먼저 트리거해 `balance_basis`(말잔/평잔)가 뜨지 않았다.
- 조치: 177을 `balance_basis` 전용 표현(구성내역·보유현황)으로 재작성하고, M2 계열 질문은 ②가 담당하게 했다. 역질문 6개 그룹 커버리지는 유지된다.

## 6. 부가 관찰

- `no_match` 53건 중 16건은 규칙 계층이 후보 표를 찾아낸다(예: 050 국고채 10년물, 052 취약차주 비중, 096 가계대출 연체율). 골드 오류라는 뜻은 아니지만 사람 검수 우선순위로 적합하다. 목록은 `offline_report.json`의 `no_match_with_candidate_ids`에 있다.
- 주기 불일치 14건은 질의에 "월별/분기별" 표현이 없고 골드가 **표에서 주기를 유도**한 경우다(예: 038·041·042). 결함이 아니라 정책 결과이며, 리졸버의 `parse_query_state`는 추측하지 않는다.
- MRR 분모 문제를 발견해 수정했다. 기존 계산은 **찾은 문항만** 평균(0.931)이라 실제보다 좋아 보였다. 이제 전체 분모(0.479)와 발견분(0.931)을 함께 보고한다.

## 7. 한계와 해석 주의

- 자기 감사는 어휘·계약 기반이다. 한국어 조사·동의어 때문에 자동 판정이 부정확할 수 있어 **경고는 실패로 처리하지 않는다**(하드만 게이트).
- 오프라인 recall은 리졸버 내부 함수 `_clarification`을 직접 부른 결과다. 런타임이 앞단에서 LLM 분류·가드로 먼저 갈라지면 실측과 다를 수 있다.
- 표 탐색 경계까지만 검증한다. 수치·CSV·차트·해석 문장은 검증 대상이 아니다.
- 이 보고서의 결과는 **개발용 사전 검증**이며 모델 성능 점수가 아니다. 블라인드 일반화 성능도 아니다.

## 10. KOSIS 실서버 검증 (2026-10-13 추가)

골드의 `exact_params`를 **실제 KOSIS API에 그대로 보내** 응답·기간·분류 이름을 확인했다. 키는 출력하지 않았고, 도구는 `scripts/verify_kosis.py`(표본 기본 20건, `--all`로 전체)로 저장소에 넣었다.

```text
전체 293계열 호출 → 응답 293/293 (오류 0). 요청 기간 = 반환 기간(예: 202001~202512 → 72행)
표본 20건 재실행 → 응답 34/34
```

### P1. 카탈로그의 분류 코드 ↔ 이름 대응이 실서버와 다르다 (27계열 / 14문항)

예시 검산(043, DT_200Y125): 카탈로그 목록에서 `13102136303ACC_ITEM.10501`의 이름은 `내수`(14번째)이고 바로 앞 항목이 `통계상 불일치`(13번째)다. 서버는 이 코드에 대해 `통계상 불일치`를 돌려준다. 즉 **이 차원에서 코드와 이름이 두 칸 어긋나 있다.** 표마다 어긋난 정도가 다르다.

영향:
- **평가**: 채점은 골드와 런타임이 같은 카탈로그를 쓰므로 `exact_api_params`가 그대로 통과한다. 이 결함은 **골드 대 골드 비교로는 절대 발견되지 않는다.**
- **제품**: 에이전트도 같은 대응으로 API 파라미터와 화면 라벨을 만들기 때문에, 사용자가 "반도체 수출금액지수"를 요청하면 실제로는 `금은괴` 데이터를 받을 수 있다. 평가 범위를 넘는 **제품 결함**이다.
- 골드 자체를 지금 고쳐도 소용없다. 카탈로그 짝을 고쳐야 한다.

`gdp_basis`·`bond_data_scope`·`consumption_expenditure_basis`·`loan_measure`는 카탈로그 본문 11그룹이 아니라 `clarification_extensions.json`의 확장 그룹이다. **v2 원본 008·014가 포함**되어 있는데, v2는 실제 런타임에서 30/30을 통과했으므로 실제 경로에서는 이 역질문이 뜨지 않았다는 뜻이다(LLM 분류·가드가 앞단에서 다르게 판단하거나, 다른 조건에서만 뜬다). 따라서 이 15건은 **오프라인 위험 신호**이며 실측으로 확인해야 한다.

## 11. 카탈로그 코드-이름 교정 (2026-10-13)

§10에서 보고한 P1을 실제로 수정했다.

- 원인: `src/agent/stat_dictionary/stat_language_dictionary.json`의 분류값 이름이 코드와 어긋나게 짝지어져 있었다(21,356개 중 **2,538개, 41개 표**). 소스 메타데이터 `data/processed/bok_classifications.csv`와 실서버가 일치하고 카탈로그만 달랐다(표본 12건에서 CSV 9/9 일치, 카탈로그 0/12).
- 수정 방식: `tools/repair_dictionary_values.py`. 코드는 그대로 두고 이름과 이름에서 파생된 필드만 소스 기준으로 다시 썼다. 값 객체를 코드 사이에서 재배치하는 방식은 차원이 계층·중복 이름을 섞고 있어 안전하지 않아 쓰지 않았다. 백업은 `.venv/cache/evaluation_runs/`에 남는다.
- 골든셋 후속: 이름이 사라진 3문항(`065`·`066`·`136`)을 실제 존재하는 분류값으로 다시 썼고, v2 원본에서 복사한 2문항(`013`·`020`)의 잘못된 코드 4건은 이름(의도)을 두고 코드만 교정해 `dataset_manifest.json`의 `legacy_value_repair`에 근거를 남겼다. v2 원본은 교정 전 카탈로그 해시를 기록하고 있어 `legacy_catalog_sha256`으로 구분한다.
- 실서버 재검증: **응답 294/294, 분류 이름 불일치 27계열 → 0건.** 남은 4계열은 요청 기간 일부에 데이터가 없는 경우(§10 P2)이며 채점 대상이 아니다.
- 결정: v2·v3·v3-four-tables는 사용하지 않기로 해 데이터를 재생성하지 않았다. 카탈로그 교정 때문에 낡은 라벨이 걸리는 테스트는 `xfail(strict=True)`로 표시하고 사유를 남겼다(재생성 시 표시 제거 필요). v3의 영향은 1,104문항 중 2문항뿐이고, 증강분 1,074문항은 영향이 없었다.
- 남은 제품 과제: 같은 카탈로그를 쓰는 에이전트도 교정 전에는 잘못된 계열을 조회했다. 이 수정으로 함께 해결되지만, 소스 메타데이터에만 있고 카탈로그에 없는 분류값 1,313개(41개 차원)는 별도 검토가 필요하다.
