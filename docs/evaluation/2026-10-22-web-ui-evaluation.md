# 웹 UI 직접 평가 종합 — 2026-10-22

> ai-assisted · 사람 검토 전 초안. 실행 중인 로컬 웹 UI를 1~8차에 걸쳐 직접 조작한 관측 기록이다. 공식 성능, 블라인드 평가 또는 출시 승인 결과가 아니다.

## 1. 목적과 평가 범위

StatBridge의 사용자 작업을 **필요한 통계 찾기 → 조건 확인 → 조회·계산 → 근거 검증 → 그래프·표 편집 → 저장·내보내기**로 정의하고, 이 흐름을 실제 화면에서 완료할 수 있는지 평가했다.

근거 문서는 [프로젝트 README](../../README.md), [프런트엔드 안내](../../src/agent/frontend/README.md), [운영 규칙](../../CONTRIBUTING.md)이다. 기존 [평가 설계](평가-설계.md)와 [질의·탐색 평가기준](질의-탐색-평가-기준.md)은 참고하되, 이번 UI 관측을 기존 검색·E2E 평가 점수와 합산하지 않는다.

- 평가일: 2026-10-22, 한국 시간.
- 대상: `http://127.0.0.1:5183/`의 로그인된 로컬 애플리케이션.
- 방법: in-app browser의 화면·접근성 트리·사용자 조작과 실제 다운로드 파일 검사.
- 가정 사용자: 통계의 기본 의미는 알지만 KOSIS 표 구조와 제품에는 익숙하지 않은 분석·보고서 작성자.
- 계정: 하나의 평가 계정만 사용. 계정 간 격리는 검증하지 않았다.
- 화면: 평가 중 관측된 좁은 화면과 일부 넓은 화면. 고정 해상도 비교 실험이나 실제 모바일 평가는 아니다.
- 실행 버전: 실행 서버의 정확한 커밋·모델 설정·키·캐시 조건을 고정하거나 확인하지 않았다. 소스 원인 분석과 구분한다.
- 비공개 평가 자료, holdout 정답, 실제 회사·개인 자료는 사용하지 않았다.

관측 수치는 앱이 표시한 자료를 기준으로 검산했다. 외부 공식 원자료와 독립 대조한 결과가 아니다. 브라우저 도구의 긴 지연을 앱 자체의 처리 시간으로 계산하지 않았다.

## 2. 평가기준

아래 비중은 평가 설계 초안이다. 전체 항목을 동일 조건으로 측정하지 않았으므로 이번에는 가중 총점을 산출하지 않았다.

| 영역 | 제안 비중 | 판단 기준 |
|---|---:|---|
| 작업 완료 가능성 | 25% | 질문부터 결과 생성·활용까지 독립적으로 완료하는가 |
| 신뢰성과 검증 가능성 | 25% | 지표·분류·기간·주기·단위·출처·산식·결측을 확인하는가 |
| 흐름 이해·조작 편의 | 15% | 현재 단계와 다음 행동이 분명하고 선택·원문을 보존하는가 |
| 그래프·표 가독성과 편집 | 15% | 요청한 표현과 서식이 반영되고 취소·복원이 가능한가 |
| 대기·오류·복구 | 10% | 장애·자료 부재·입력 오류를 구분하고 작업을 보존하는가 |
| 일관성·접근성·화면 대응 | 10% | 키보드·보조기술·좁은 화면에서 핵심 기능에 접근하는가 |

정성 척도는 1점(작업 불가·중대한 오해), 2점(큰 도움·우회 필요), 3점(완료하나 마찰 있음), 4점(작은 불편), 5점(원활한 완료와 근거 이해)로 제안했다. 이번 보고서는 근거가 확보된 사례의 상태를 기록하며, 점수는 부여하지 않는다.

필수 통과 조건은 다음과 같다.

- 요청과 다른 지표·기간·분류를 사용자가 모르게 대체하지 않는다.
- 없는 관측값을 만들거나 실패를 성공으로 표시하지 않는다.
- API 장애와 실제 자료 부재를 구분한다.
- 편집·복원·내보내기에서 값과 의미가 조용히 바뀌지 않는다.
- 다른 계정의 작업·파일·기록을 노출하지 않는다. 이번에는 미측정이다.

`확인 범위 통과`, `부분 충족`, `작업 미완료`, `미측정`을 구분한다. 계산이 맞더라도 질문에 답하지 않았으면 질문 충족은 실패로 판정한다.

## 3. 종합 결과와 상태 갱신

**조회·편집·데이터 복원·파일 전달은 여러 사례에서 작동했다. 우선 개선할 부분은 보고서의 질문 충실성, 계산 근거의 표시기간, 오류 분류, 출력물의 근거 추적성이다.**

| 흐름 | 최종 관측 | 범위·제약 |
|---|---|---|
| 단일 조회 | 가계대출 금리 월별 24개 생성 | 특정 표·항목·기간 사례 |
| 복수 조회 | 가계·기업대출 각 24개, 총 48개 | 모든 복수 요청의 성공률은 아님 |
| 카탈로그 | 349개 목록·분류·메타데이터 확인 | 기본 계정항목 조회 실패 사례 있음 |
| 혼합 단위 | 금리·본원통화 좌우 단위와 48개 값 유지 | 명시한 선 그래프는 선·막대 혼합으로 변경 |
| 파생 계산 | 금리차 24개월 전수 검산 일치 | 초기 확인 대기 후 5차에서 완료 |
| 파생 산식 수정 | 반대 방향 24개월 검산 일치 | 이력 설명은 제목 변경으로 부정확 |
| 표시 기간·재조회 | 1년/전체, 3년 확장과 취소 성공 | 파생 계산 근거의 표시기간은 미갱신 |
| 전용 취소·다시 적용 | 차트 종류와 기간·자료 복원 성공 | 자연어 되돌리기 연결은 실패 사례 |
| 저장 | 저장·보관함 열기 성공 | 새로고침은 현재 작업을 자동 복원하지 않음 |
| 보고서 대화 | 답변 생성 가능하나 확인 반복·요청 이탈 | 최초 모델 응답 실패도 관측 |
| CSV | 다운로드·48행·양 끝 수치·단위 확인 | 48개 값 전부의 화면 대조는 미수행 |
| PNG | 실제 이미지·사용자 지정 800×500 확인 | 긴 범례 말줄임 |
| SVG·PDF | 폰트 오류로 생성 미완료 | 환경을 수정하거나 생성 파일을 검사하지 않음 |
| 표 편집 | 숫자 보호·표시명·Ctrl+Z·서식·병합/분할 확인 | 제한된 셀 범위 |
| XLSX | 12개 수치·색상·정밀도·테두리 구조 확인 | 실제 Excel 화면 렌더 미검증 |
| MD | 수집·중복 방지·미리보기·파일 일치 | 원자료·산식의 독립 추적 정보 부족 |
| 혼합 주기 | 탐색·확인 단계에서 미완료 | 실제 주기 변환·보간 동작은 미검증 |
| 지원 범위 밖 | 회사 매출액 거절·대체 예시·입력 보존 | 실자료 입력·업로드는 하지 않음 |

초기 라운드의 미완료를 최종 실패로 고정하지 않는다.

- 파생 계산: 2~4차 확인 대기 → 5차 완료·검산 통과. 대기 UX 문제는 남는다.
- 되돌리기: 2차 자연어 요청 미완료 → 3차 전용 버튼 성공 → 4차 기간·자료 동시 복원 성공.
- 내보내기: 1차 CSV 링크 → 2차 실제 CSV·PNG → 5차 지정 크기 PNG → 7차 MD → 8차 XLSX 검사.
- 보고서: 응답 실패와 내용 충실성 실패는 별개다. 이후 응답이 나왔다고 이전 요청 이탈이 해결된 것은 아니다.

### 4.1 보고서 요청 충실성 (UI-01)

1. 가계·기업대출 두 계열의 2023~2024년 자료를 연다.
2. 보고서에서 `2024년 12월 가계대출 금리와 기업대출 금리는 각각 얼마야?`라고 묻는다.
3. 대상을 다시 물어 `전체 지표`라고 답한다.
4. 관측 응답은 2023년 1월 대비 하락폭 0.75/0.85%p였다. 요청한 수준 4.72/4.62 연리%는 제시하지 않았다.

파생 1계열에서도 `현재 표시된 전체 지표의 마지막 관측값과 시점을 단위와 함께 알려줘.` → `전체 지표`에 같은 확인 질문이 반복됐다. 정확한 계열명과 최근 수준을 요청하자 11월 대비 12월 변화 -0.07%p를 답했으나 최신 수준 -0.10%p는 제시하지 않았다. 변화 계산 자체는 맞았다.

### 4.2 파생 표시기간 불일치 (UI-02)

1. 아래 파생 계산을 생성하고 방향을 반대로 바꾼다.
2. 빠른 표시 기간에서 `1년`을 선택한다.
3. 상단·그래프·데이터는 2024년·12개로 바뀐다.
4. 계산 근거는 `표시기간 202301–202412 · 원자료 조회기간 202301–202412`로 남는다.

원자료 조회기간이 넓게 남는 것은 오류로 판정하지 않는다. **표시기간이라는 라벨이 실제 화면과 다르다는 점**이 문제다.

### 4.3 카탈로그 기본 조회와 오류 분류 (UI-03)

`통계 탐색·계보 → 금융·통화 → 금리 → 예금은행 대출금리(신규취급액 기준)`에서 기본 대표값 `신규취급액 기준`을 유지하고 2023~2024년을 조회했다. KOSIS 실패가 나왔으며, 로그의 `source_api_error / KosisApiError`가 상위 상태에서는 자료 부족으로 표시됐다. 화면은 질문 수정을 안내했다.

같은 표의 가계대출을 명시한 자연어 조회는 성공했다. 따라서 모든 KOSIS 호출이 실패한 상황은 아니었다. 기본값·인증·네트워크·API 입력 중 어느 것이 원인인지는 미확정이다.

### 4.4 혼합 주기 요청과 표 연결 (UI-06)

최초 요청:

```text
2023년부터 2024년까지 예금은행 대출금리(신규취급액 기준)의 가계대출 금리는 월별로,
실질 국내총생산은 분기별로 같은 그래프에서 비교해줘. 원래 주기를 유지해줘.
```

GDP 대응 표를 찾지 못했다는 안내로 멈췄다. 카탈로그에는 `DT_200Y104`, 경제활동별 GDP 및 GNI(계절조정 실질 분기), Q, 십억원과 `국내총생산(시장가격 GDP)` 항목이 있었다. 원계열/계절조정 모호성이 있으므로 이 표를 자동 선택해야 한다는 뜻은 아니다.

두 표 ID `DT_121Y006`, `DT_200Y104`와 항목·주기를 명시해 다시 요청하면 금리 기준을 물었다. 새로 취급된 거래 기준을 선택하자 연결된 지원 통계표가 없다고 안내했다. 입력 파싱·다중 표·주기·분류 중 실제 원인은 미확정이다. 이 관측으로 자동 보간이나 주기 변환 오류를 주장하지 않는다.

## 5. 계산·복원·파일 검증의 근거

### 5.1 파생 금리차

```text
2023년 1월부터 2024년 12월까지 예금은행 대출금리(신규취급액 기준)의
가계대출 금리에서 기업대출 금리를 뺀 차이를 월별 퍼센트포인트로 계산해줘
```

화면의 `사용한 원자료 보기`에서 각각 24개 입력을 확인하고 `전체 데이터 더 보기`로 결과를 펼쳤다. 읽기 전용 DOM으로 표를 추출해 각 월의 차이를 소수 둘째 자리로 반올림한 뒤 비교했다. **24개 비교, 불일치 0개**였다. 결측·계산 불가 시점은 UI상 0건이며 결측 사례의 처리 자체는 미검증이다.

| 시점 | 가계대출 | 기업대출 | 가계−기업 (%p) |
|---|---:|---:|---:|
| 202301 | 5.47 | 5.47 | 0.00 |
| 202302 | 5.22 | 5.36 | -0.14 |
| 202407 | 4.06 | 4.78 | -0.72 |
| 202412 | 4.72 | 4.62 | 0.10 |

다음 자연어 입력으로 계산 방향을 변경했다.

```text
차이를 반대로 계산해줘. 기업대출 금리에서 가계대출 금리를 빼고
단위는 퍼센트포인트로 유지해줘.
```

`subtract(corporate_loan_rate, household_loan_rate)`로 산식·설명·계산 ID·해시가 바뀌었다. **24개가 모두 이전 값의 반대 부호와 일치**했다. 외부 공식 자료 검증이나 복잡한 산식의 일반 성능은 아니다.

### 5.2 기간과 계열 복원

- 빠른 1년/전체: 2024년 24개 값 ↔ 2023~2024년 48개 값. 두 계열 기준이다.
- 실제 기간 확장: 2022~2024년 각 36개, 총 72개. 표·항목·단위 유지.
- 확장 취소: 날짜 입력·상단 기간·그래프·데이터가 함께 기존 48개로 복원.
- 오른쪽 금리 제외/다시 표시: 48→24→48개, 마지막 값·축 단위 유지.
- 역전 기간: 시작 2025-01-01, 종료 2024-12-31을 거절하고 기존 자료 유지.
- 전용 차트 취소/다시 적용: 막대→선→막대, 24개 값·기간 유지.

### 5.3 실제 다운로드 검사

| 형식 | 검사 내용 | 확인 한계 |
|---|---|---|
| CSV | 데이터/시점/값/단위, 두 계열 각 24행, 시작·종료 값 일치 | 전체 48개 화면 대조·출처 열 없음 |
| PNG | 1400×660 출력, 지정 800×500 출력, 제목·축·단위·최근 값·표 ID 확인 | 긴 범례 말줄임, 픽셀 단위 검증 아님 |
| MD | 수집 1개·중복 방지·미리보기와 실제 파일 문장 일치 | 질문·표 ID·산식·기간·계산 ID 미포함 |
| XLSX | 2024년 12개 값 전수 대조, 숫자 셀·배경·소수점·3선형 구조 | Excel/LibreOffice 실제 렌더 미검증 |
| PDF/SVG | 한글 폰트 부재 오류 확인 | 생성 파일이 없어 내용·레이아웃 미검증 |

XLSX는 bundled Python의 `openpyxl`로 읽기 전용 검사했다. `표1`의 B4:M4를 `[.54,.54,.46,.40,.41,.62,.72,.59,.54,.16,-.03,-.10]`과 허용오차 `1e-9`로 비교해 불일치가 없었다. 화면 B2는 제목/여백 행 때문에 파일 B4에 대응한다.

- B4: numeric `0.54`, 형식 `#,##0.00`, 색 `00fff2cc`.
- C4: 기본 형식 `#,##0.000000` 유지.
- 머리글 상단 medium·하단 thin, 데이터 하단 medium, 좌우 선 없음.
- `계산근거` 시트: 최종 파생값 12개는 있지만 원래 두 금리 입력·산식·표 ID는 없다. `원자료 계열`이라는 열도 파생 결과 계열을 가리킨다.
- 부동소수점 내부 표현 차이는 지정 표시 형식과 구분하며 계산 오류로 판정하지 않았다.

## 8. 작업 영향과 문서 검증

평가 과정에서 분석 1개를 저장해 보관함이 2/5→3/5가 됐다. 기존 분석은 삭제하지 않았다. 이후의 편집과 MD 모음은 현재 세션에서 수행했으며 분석 저장을 다시 누르지 않았다. CSV·PNG·MD·XLSX는 로컬 Downloads로 내려받았고 저장소에 추가하지 않았다. 서버 설정·키·폰트·소스는 평가 중 변경하지 않았다.

문서 작성 시 실행한 검증은 다음과 같다. Windows 가상환경 경로와 `PYTHONPATH` 구분자를 사용했다. 앱의 UI 관측 결과와 저장소 테스트 결과는 서로 대체하지 않는다.

| 검증 | 관측 결과 |
|---|---|
| `git diff --check` 및 새 문서의 whitespace 검사 | 통과 |
| 문서의 상대 링크 존재 확인 | 5개 모두 존재 |
| `$env:PYTHONPATH='src/backend;src/agent'; .venv/Scripts/python.exe -m pytest -q tests eval/table-discovery/v4.1/tests` | 실행했으나 진행 표시 `..` 이후 완료 결과 없이 중단. 전체 성공 여부·통과 수 미확정 |
| `.venv/Scripts/python.exe eval/table-discovery/v4.1/scripts/validate_v41.py` | 종료 코드 0, `VALIDATION OK`, dev/test/holdout = 50/70/30 |
| 프런트엔드에서 `pnpm build` | 종료 코드 1. 로컬 `node_modules/typescript/bin/tsc`를 찾지 못해 빌드 미완료 |

문서 작업을 위해 패키지 설치나 실행 환경 변경은 하지 않았다. 테스트 미완료와 빌드 실패를 문서 내용 검증 통과로 대체하지 않으며, 제출 전 완전한 환경에서 다시 실행해야 한다.
