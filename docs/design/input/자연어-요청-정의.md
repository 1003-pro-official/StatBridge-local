자연어 질의 입력은 단순한 “검색창”이 아니라, 사용자의 분석 목적과 통계 조건을 수집하는 **요청 정의 단계**입니다. 이 프로젝트 범위에서는 KOSIS 내 **한국은행 소관 통계표**를 대상으로 합니다.

| 육하원칙 | 사용자 관점에서 정의할 내용 | 입력 예시 | 시스템이 해야 할 일 |
| --- | --- | --- | --- |
| 누가 (Who) | 누가, 어느 수준의 이해도로 쓰는가 | 일반 사용자, 금융 분석가, 연구자, 정책 담당자 | 통계 용어의 난이도와 결과 설명 깊이를 조절 |
| 무엇을 (What) | 보고 싶은 지표·현상·대상은 무엇인가 | “중소기업 대출 연체율”, “기준금리와 예금금리” | 자연어 표현을 후보 통계 개념·항목으로 확장 |
| 언제 (When) | 분석 기간·기준 시점·주기는 무엇인가 | “2020년 이후”, “최근 5년”, “월별” | 기간·주기를 해석하고, 누락 시 표의 가용 기간을 확인해 제안 |
| 어디서/어디를 (Where) | 공간·시장·기관·산업 등 비교 범위는 무엇인가 | “한국 전체”, “서울”, “은행권”, “중소기업” | 지역·기관·산업 등의 분류 차원으로 변환 |
| 왜 (Why) | 사용자가 이 수치를 보려는 분석 목적은 무엇인가 | 추세 파악, 전후 비교, 상관관계 탐색, 보고서 근거 | 필요한 지표 수와 비교 방식, 표/그래프 형식을 판단 |
| 어떻게 (How) | 원하는 비교·계산·표현 방식은 무엇인가 | “같이 보여줘”, “증감률로”, “선 그래프로” | 단일/복수 표 조회, 병합 규칙, 계산식, 시각화 계획 수립 |
| 얼마나 (How much) | 단위·정밀도·범위·비교 기준은 무엇인가 | “비율로”, “전년 동월 대비”, “억원 단위” | 원 단위와 가공 단위를 명시하고, 비교 가능성을 검증 |

이를 입력 단계의 내부 구조로 표현하면 다음과 같습니다.

```
NaturalLanguageQuery
├─ user_context
│  ├─ user_type: 일반 사용자 | 분석가 | 연구자 | 정책 담당자
│  └─ statistical_literacy: 낮음 | 보통 | 높음
├─ analysis_intent
│  ├─ purpose: 현황 | 추세 | 비교 | 관계 탐색 | 근거 확인
│  └─ question_type: 단일 지표 | 복수 지표 | 조건부 탐색
├─ statistical_target
│  ├─ metric: 지표·현상
│  ├─ population_or_sector: 대상 집단·산업·기관
│  └─ geography: 지역 범위
├─ time_scope
│  ├─ period: 시작~종료
│  ├─ reference_time: 기준 시점
│  └─ frequency: 월 | 분기 | 연 | 미지정
├─ comparison_and_processing
│  ├─ comparator: 비교 대상
│  ├─ operation: 수준 | 차이 | 증감률 | 비율 | 상관 탐색
│  └─ unit_preference: 원자료 단위 | 변환 단위 | 미지정
└─ output_preference
   ├─ format: 표 | 그래프 | 둘 다
   ├─ chart_type: 선 | 막대 | 산점도 | 자동 추천
   └─ explanation_level: 요약 | 상세
```

예를 들어, “최근 5년 기준금리와 중소기업 대출 연체율을 한 그래프로 보여줘”는 다음처럼 정규화됩니다.

- 무엇: 기준금리, 중소기업 대출 연체율
- 언제: 최근 5년
- 왜: 두 지표의 동시 추이 비교
- 어떻게: 복수 통계표 조회 후 시점 기준 병합, 선 그래프
- 결과: 원자료 단위와 주기가 다르면 병합 가능 여부·변환 방식·한계를 함께 안내

핵심은 모든 항목을 사용자에게 처음부터 입력받지 않는 것입니다. 사용자가 자연어로 말한 내용을 우선 추출하고, **결과를 바꿀 정도로 중요한 정보만 되묻는 방식**이 적합합니다. 예컨대 기간이 없으면 최신 가용 기간을 제안할 수 있지만, “대출금리”처럼 여러 통계 개념으로 해석될 수 있으면 후보를 제시해 확인받아야 합니다.
