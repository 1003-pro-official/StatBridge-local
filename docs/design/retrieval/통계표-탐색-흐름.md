## 통계표 탐색 · Retrieval

통계표 탐색 단계는 Query Planning에서 정리한 질의를 바탕으로 **요청에 맞는 한국은행 통계표 후보를 찾고, 각 후보가 실제로 요청 조건에 맞는지 검증하는 단계**입니다.

입력은 사용자의 원문 질의만이 아니라, 앞 단계가 만든 지표 후보·기간·비교 조건·모호성 답변·검색 계획입니다. 출력은 통계표 후보와 적합성 근거, 다음에 취할 동작입니다.

이 단계에서는 표를 찾고 메타정보를 확인합니다. 실제 수치 조회와 그래프 생성은 다음 단계에서 수행합니다.

```
Query Plan
   ↓
검색어·조건 구성
   ↓
통계표 카탈로그에서 후보 탐색
   ↓
후보 표의 메타정보 확인
   ↓
적합성·복수 표 필요성 판단
   ├─ 적합한 후보 없음 → 탐색 불가 또는 대안 제안
   ├─ 후보 선택이 모호함 → 사용자 확인
   └─ 적합 후보 확인 → 조회 파라미터 확정 단계로 전달
```

### 1. 검색 대상: 한국은행 표 카탈로그

제공된 카탈로그에는 한국은행 소관 통계표 349개가 있습니다. 현재 파일은 2026년 9월 14일 수집 스냅샷이며, 표 ID와 이름 외에도 분류 경로를 갖고 있습니다.

| 필드 | 탐색에서의 쓰임 |
| --- | --- |
| `tbl_id` | 후보 통계표의 고유 식별 |
| `tbl_nm` | 표 이름으로 검색·매칭 |
| `stat_id`, `org_id` | 통계와 제공 기관 식별 |
| `path` | 표가 속한 통계 주제·분류 경로로 후보 보강 |
| `depth` | 분류 트리상 위치를 파악 |
| `rec_tbl_se` | 추천 표 여부 참고 |

제공된 스냅샷에서는 `rec_tbl_se`가 349개 모두 `N`이므로, 현재 목록의 추천 여부 필드만으로 후보를 우선 선택하기는 어렵습니다. 따라서 표 이름과 경로, 그리고 후속 메타정보가 주요 판단 근거가 됩니다.

### 2. 세부 처리 단계

| 세부 단계 | 하는 일 | 산출물 |
| --- | --- | --- |
| 1. 탐색 요청 수신 | Query Plan에서 지표·조건·사용자 선택을 전달받음 | `retrieval_request` |
| 2. 검색어 구성 | 원래 표현과 정규화한 개념 후보를 검색어로 준비. 동의어와 표기 변형도 포함 | `search_terms`, `filters` |
| 3. 1차 후보 탐색 | 표 이름과 분류 경로를 검색해 관련 표 후보를 수집 | `table_candidates` |
| 4. 후보 순위화 | 명칭 일치, 경로 관련성, 요청한 대상·분류와의 일치 등으로 후보를 정렬 | `ranked_candidates`, `match_reasons` |
| 5. 메타정보 확인 | 상위 후보의 항목·분류·단위·주기·수록 기간·주석을 확인 | `candidate_metadata` |
| 6. 요청 조건과 대조 | 표가 의도한 지표와 범위를 제공하는지, 기간과 주기를 충족하는지 판단 | `suitability_checks` |
| 7. 후보 상태 결정 | 적합 표가 없거나, 하나 또는 여러 표가 적합한지 판단 | `retrieval_status` |
| 8. 다음 단계로 전달 | 확인된 후보와 필요한 조회 조건을 자료 조회 단계에 전달하거나 사용자 확인 요청 | `selected_candidates`, `next_action` |

초기 탐색에서는 카탈로그의 `tbl_nm`과 `path`를 사용할 수 있습니다. 다만 카탈로그만으로는 항목·단위·주기·수록 기간을 모두 알 수 없으므로, 후보가 실제 조건을 만족하는지 메타정보를 확인해야 합니다.

### 3. 후보 적합성 판단

후보는 이름이 비슷하다는 이유만으로 채택하지 않습니다. 요청의 핵심 조건과 표의 메타정보를 함께 비교합니다.

| 확인 기준 | 판단 질문 |
| --- | --- |
| 개념 | 이 표가 사용자가 말한 지표를 실제로 포함하는가? |
| 대상·분류 | 가계·기업, 중소기업·전체 등 요청한 집단을 구분할 수 있는가? |
| 기간 | 요청한 기간을 포함하는가? |
| 주기 | 월·분기·연 단위 요청에 맞는 자료가 있는가? |
| 계열·기준 | 원계열·계절조정계열, 말잔·평잔 등 차이가 요청에 맞는가? |
| 단위 | 표의 단위와 정의가 요청한 비교·계산에 적절한가? |
| 주석·제약 | 표에 해석에 영향을 줄 설명이나 유의점이 있는가? |

확인 결과는 “적합/부적합”만 남기기보다 어떤 조건이 맞고 어떤 조건이 남았는지를 기록해야 합니다. 예를 들면 표 이름은 지표와 일치하지만, 요청한 대상 집단을 구분하는 항목이 있는지는 메타정보 확인이 더 필요한 상태일 수 있습니다.

### 4. 탐색 결과에 따른 분기

| 결과 | 동작 |
| --- | --- |
| 적합한 표를 찾지 못함 | 탐색 범위와 불일치 이유를 안내하고, 유사 지표나 조건 완화 같은 대안을 제안 |
| 후보 하나가 조건과 잘 맞음 | 적합성 근거와 메타정보를 자료 조회 단계로 전달 |
| 서로 다른 후보가 모두 가능함 | 표나 지표 정의의 차이를 설명하고 사용자 선택 요청 |
| 여러 표를 함께 써야 함 | 각 표의 메타정보를 전달하고, 주기·기간·단위 정합성 검토를 계획 |
| 카탈로그만으로 판단하기 어려움 | 추가 메타정보 조회를 수행하거나, 필요한 내용을 사용자에게 확인 |

여러 표가 필요해 보인다는 판단은 탐색 결과와 메타정보를 바탕으로 내립니다. Query Planning의 예상만으로 병합을 확정하지 않습니다.

### 5. 예시: “최근 5년 기준금리와 M2 추이를 비교해줘”

탐색 단계에서는 기준금리와 M2를 각각 찾아 후보를 구성합니다. 카탈로그의 표 이름과 분류 경로를 이용해 관련 후보를 찾고, 이후 각 후보 메타정보에서 다음을 검증합니다.

- 표에 요청한 지표와 세부 항목이 있는가?
- M2의 계열 구분이 요청에 적절한가?
- 최근 5년 기간이 수록되어 있는가?
- 두 자료의 주기와 기간을 함께 비교할 수 있는가?
- 단위가 다를 때 한 그래프에서 비교하는 것이 적절한가?

이 단계의 결과는 “이 ID의 수치가 답이다”가 아니라, **어떤 표가 어떤 이유로 후보가 되었으며 조회 전에 무엇을 확인했는지**입니다. 적합성 검증이 끝나면 선택된 표와 조회 조건을 통계자료 조회 단계로 넘깁니다.

### 6. 통계표 탐색 산출물 예시

```
{
  "retrieval_status": "CANDIDATES_FOUND",
  "query_concepts": ["기준금리", "M2"],
  "candidates": [
    {
      "table_id": null,
      "table_name": null,
      "catalog_path": [],
      "match_reasons": [],
      "metadata_status": "pending",
      "checks": {
        "concept_match": "pending",
        "requested_period": "pending",
        "frequency": "pending",
        "unit": "pending",
        "classification": "pending"
      }
    }
  ],
  "next_action": "GET_METADATA"
}
```

실제 탐색 결과에는 카탈로그에서 찾은 표 ID·표 이름·경로와 메타정보 확인 결과가 채워집니다. 위 예시는 구조만 나타내며 특정 표가 해당 질의에 적합하다는 뜻은 아닙니다.

### 7. 단계 간 경계

- **Query Planning**은 무엇을 찾아야 하는지와 어떤 순서로 확인할지를 정합니다.
- **통계표 탐색**은 카탈로그와 메타정보를 이용해 실제 표 후보를 찾고 적합성을 검증합니다.
- **통계자료 조회**는 검증된 표와 조건으로 수치 자료를 가져옵니다.

따라서 통계표 탐색의 핵심 결과는 후보 목록뿐 아니라, **후보별 근거·검증 상태·다음 동작**까지 포함해야 합니다.
