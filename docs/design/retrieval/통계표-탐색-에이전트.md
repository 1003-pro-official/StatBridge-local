## 통계표 탐색 · Retrieval 단계의 에이전트

통계표 탐색 단계에서 에이전트는 Query Planning이 만든 **통계 개념 후보와 검색 계획**을 받아, 한국은행 카탈로그에서 관련 표를 찾고 후보가 요청에 맞는지 확인합니다.

사용자의 표현과 비슷한 표 이름을 찾는 데서 멈추지 않고, **후보 표의 메타정보를 확인해 적합성 근거를 만든 뒤**, 적합한 표가 있는지와 사용자 확인이 필요한지를 판단합니다. 실제 수치 자료를 가져오는 작업은 통계자료 조회 단계에서 합니다.

```
통계 개념 후보와 검색 계획
        ↓
카탈로그에서 표 후보 탐색
        ↓
후보 표 메타정보 확인
        ↓
요청 조건과 후보 적합성 대조
   ├─ 적합한 후보 없음 → 대안 탐색 또는 불가 안내
   ├─ 해석에 따라 후보가 달라짐 → 사용자에게 역질문
   └─ 후보 확인 → 자료 조회 단계로 전달
```

### 에이전트의 처리 단계

| 세부 단계 | 에이전트가 하는 일 | 산출물 |
| --- | --- | --- |
| 1. 탐색 조건 수신 | 지표·기간·대상·비교 조건과 사용자의 역질문 답변을 받음 | `retrieval_request` |
| 2. 검색어 확장 | 원문 표현, 정규화된 개념 후보, 용어 사전 별칭을 검색어로 준비 | `search_terms` |
| 3. 카탈로그 검색 | 표 이름과 분류 경로를 대상으로 관련 표 후보 검색 | `table_candidates` |
| 4. 후보 순위화 | 명칭 일치, 분류 경로, 대상·조건과의 관련성을 근거로 후보 정렬 | `ranked_candidates`, `match_reasons` |
| 5. 메타정보 조회 | 상위 후보의 항목·분류·단위·주기·수록 기간·주석을 확인 | `candidate_metadata` |
| 6. 적합성 판단 | 요청한 개념과 범위를 제공하는지, 중요한 조건이 맞는지 점검 | `suitability_checks` |
| 7. 다음 동작 선택 | 적합 표 없음, 후보 확정 가능, 복수 후보 중 선택 필요 등을 구분 | `retrieval_status`, `next_action` |

### 후보 검색과 적합성 확인

제공된 한국은행 카탈로그는 349개 통계표의 ID, 이름, 분류 경로 등을 담고 있습니다. 이 카탈로그를 1차 검색 대상으로 활용합니다. 제공된 스냅샷에서 추천 표 여부는 모두 `N`이므로 추천 플래그에 기대기보다 표 이름과 분류 경로, 메타정보를 근거로 후보를 살펴봐야 합니다.

후보 적합성을 판단할 때는 다음을 확인합니다.

- 표가 요청한 지표를 제공하는가?
- 요청한 대상이나 분류를 표의 항목에서 선택할 수 있는가?
- 표의 주기와 수록 기간이 요청에 맞는가?
- 계열 구분, 단위, 주석이 요청한 해석과 충돌하지 않는가?
- 복수 지표를 함께 조회할 경우 서로 정합할 가능성이 있는가?

표 이름이 질의와 비슷하다는 사실만으로 적합 표라고 확정하지 않습니다. 카탈로그에 없는 항목 정보 등은 메타정보 조회로 확인합니다.

### 역질문이 필요한 경우

탐색 결과에 따라 해석이 갈리고, 선택에 따라 사용할 표나 결과가 달라질 때 에이전트는 사용자에게 확인할 수 있습니다. 이때 앞서 정의한 선택형 역질문 기능을 사용해 **질문, 선택지, 선택 이유, 직접 입력**을 제시합니다.

예를 들어 “대출금리”에 관련된 후보가 여러 개 나오고 메타정보상 기준 차이가 중요한 경우, 에이전트는 후보 간 차이를 설명하고 선택을 요청합니다. 반면 후보가 충분히 좁혀지지 않은 경우에는 우선 관련 표 후보를 더 탐색한 후 질문할 수 있습니다.

역질문 이후에는 사용자의 응답을 탐색 조건에 반영하고, 관련 후보의 적합성을 다시 확인합니다.

### 탐색 결과별 분기

| 결과 상태 | 에이전트의 동작 |
| --- | --- |
| `FOUND` | 요청에 적합한 후보를 확인하고 근거와 함께 다음 단계로 전달 |
| `AMBIGUOUS` | 후보별 차이를 제시하고 사용자에게 선택 요청 |
| `NO_MATCH` | 관련 후보가 없음을 알리고 표현 또는 범위를 바꾼 대안 제안 |
| `METADATA_INSUFFICIENT` | 후보 적합성을 판단하는 데 필요한 메타정보를 추가 확인 |
| `MULTIPLE_TABLES` | 지표별 표 후보를 전달하고 자료 조회·정합 단계에서 다룰 점을 표시 |

### 탐색 단계의 산출물

자료 조회 단계가 이어질 수 있도록 후보마다 식별자와 판단 근거를 함께 넘깁니다.

```
{
  "retrieval_status": "FOUND",
  "candidates": [
    {
      "tbl_id": "카탈로그에서 확인한 표 ID",
      "tbl_nm": "카탈로그에서 확인한 표 이름",
      "path": ["통계 분류 경로"],
      "match_reasons": ["지표 표현 일치", "분류 경로 관련"],
      "metadata_checks": {
        "concept": "확인됨",
        "classification": "추가 확인 필요",
        "frequency": "확인됨",
        "period_coverage": "확인됨",
        "unit": "확인됨"
      },
      "status": "candidate"
    }
  ],
  "next_action": "CONFIRM_QUERY_PARAMETERS"
}
```

### 탐색 단계의 경계

통계표 탐색 단계는 적합한 표 후보와 그 근거를 확인해 다음 단계로 넘깁니다. 표 안에서 어느 항목이나 분류를 선택하고, 어떤 기간 조건을 API에 넣을지는 `조회 파라미터 확정`에서 결정합니다. 통계값 자체는 `통계자료 조회` 단계에서 가져옵니다.

따라서 Retrieval의 핵심 산출물은 **표 ID·이름·분류 경로·메타정보·적합성 근거·다음 동작**입니다. 표 후보가 없거나 여러 개로 남으면 그 상태도 명시해, 에이전트가 잘못된 표를 확정한 채 진행하지 않도록 합니다.
