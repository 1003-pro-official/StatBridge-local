### 역질문 흐름

```
질의 접수
  ↓
에이전트가 의도와 조건을 우선 해석
  ↓
해석에 따라 결과가 달라질 모호성이 있는가?
  ├─ 없음 → 계획을 확정하고 통계표 탐색으로 전달
  └─ 있음 → 선택지와 추천안을 제시
                ↓
             사용자 선택 또는 직접 입력
                ↓
             조건 갱신 후 계획 재작성
```

에이전트는 질문부터 던지는 대신, 먼저 질의를 해석해봅니다. 그리고 지표·기간·비교 기준처럼 답에 큰 영향을 주는 항목이 불분명할 때만 사용자에게 역질문합니다.

### 역질문 화면에 담을 내용

각 역질문은 아래 요소를 갖도록 합니다.

| 요소 | 역할 |
| --- | --- |
| 확인 질문 | 무엇을 정해야 하는지 한 문장으로 표현 |
| 질문 이유 | 이 선택이 결과를 어떻게 바꾸는지 짧게 설명 |
| 선택지 | 사용자가 바로 고를 수 있는 구체적인 해석 후보 |
| 추천 선택 | 추천안과 추천 이유 표시 |
| 직접 입력 | 선택지에 없는 답도 사용자가 작성할 수 있게 허용 |

스크린샷처럼 선택지를 고른 뒤 확인하는 흐름을 제공하되, **추천안이 기본으로 선택된 것처럼 오해되지 않도록** 추천 표시와 사용자 선택을 구별하는 편이 좋습니다.

### 프로젝트 질의 예시

사용자 질의:

> 금리 추이를 보여줘.
> 

에이전트가 지표를 특정할 수 없어 결과가 달라질 수 있다면 다음처럼 묻습니다.

> 어떤 금리의 추이를 볼까요? 통계표와 수치가 달라지는 구분이라 먼저 확인할게요.
> 
1. 한국은행 기준금리
2. 예금은행 대출금리
3. 예금은행 예금금리
4. 관련 금리 표를 먼저 찾아 후보를 보여줘
5. 직접 입력

이 경우에는 특정 금리를 임의로 고르지 않고, 사용자의 선택을 받은 뒤 해당 조건을 Query Plan에 반영합니다.

### 역질문을 띄울 기준

- 지표 표현에 서로 다른 통계 개념이 포함될 때
- 비교 대상이나 비교 기준에 따라 계산 결과가 달라질 때
- 기간 표현을 여러 방식으로 해석할 수 있고, 기본값을 정하기 어려울 때
- 요청한 가공 방식에 필요한 조건이 빠져 있을 때

반대로 그래프 종류처럼 쉽게 바꿀 수 있는 선택은 기본안을 제안하고 진행할 수 있습니다. 질문이 필요하더라도 한꺼번에 여러 개를 묻기보다, **현재 계획을 막는 가장 중요한 질문 하나씩** 제시하는 방식이 적절합니다.

### Query Planning과 연결

역질문이 발생하면 계획은 잠시 대기 상태가 됩니다. 사용자의 답이 들어오면 관련 조건만 갱신하고 계획을 다시 검증합니다.

```
PLANNING
   ↓ 모호성 발견
NEEDS_CLARIFICATION
   ↓ 질문 제시
WAITING_FOR_USER
   ↓ 답변 수신
REPLANNING
   ├─ 추가 확인 필요 → NEEDS_CLARIFICATION
   └─ 계획 준비 완료 → READY_FOR_RETRIEVAL
```

계획에는 원래 질의와 함께 질문·선택지·사용자 답변을 기록합니다. 그러면 나중에 결과를 설명할 때도 어떤 해석을 사용자가 선택했는지 추적할 수 있습니다.

```
{
  "original_query": "금리 추이를 보여줘",
  "slots": {
    "metric": null,
    "time_range": null
  },
  "clarification": {
    "status": "waiting_for_user",
    "question": "어떤 금리의 추이를 볼까요?",
    "reason": "금리 종류에 따라 연결되는 통계표와 수치가 달라집니다.",
    "options": [
      "한국은행 기준금리",
      "예금은행 대출금리",
      "예금은행 예금금리",
      "관련 금리 표 후보 먼저 보기",
      "직접 입력"
    ],
    "recommended_option": null
  },
  "planning_status": "NEEDS_CLARIFICATION"
}
```

핵심은 에이전트가 모호성을 발견했을 때 긴 자유 서술형 질문을 던지기보다, **질문 이유와 선택지를 보여주고, 직접 입력도 허용하는 확인 단계**를 두는 것입니다. 사용자가 답하면 그 선택을 질의 조건에 반영해 통계표 탐색 계획을 이어갑니다.
