## 1. 목적과 범위

`질의 해석 · Query Planning`은 사용자의 자연어 요청을 통계 탐색과 자료 조회에 필요한 **구조화된 요청 및 실행계획**으로 바꾸는 단계입니다.

이 단계에서 답해야 할 질문은 세 가지입니다.

1. 사용자는 어떤 지표를 어떤 기간과 조건으로 알고 싶어 하는가?
2. 해석이 여러 가지라면 사용자에게 확인해야 하는가?
3. 어떤 도구를 어떤 순서로 사용해 요청을 처리할 것인가?

이 단계의 결과는 아직 확정된 통계표나 수치가 아닙니다. 사용자가 원하는 조건과 그 조건을 찾고 검증할 방법을 정리한 계획입니다. 실제 통계표와 조회 파라미터는 다음 단계의 통계표 탐색과 메타정보 확인을 거쳐 확정합니다.

```mermaid
flowchart LR
    A["자연어 질의와 대화 맥락"] --> B["의도·조건 추출"]
    B --> C["통계 개념 정규화"]
    C --> D["모호성·충돌 점검"]
    D -->|확인 필요| E["사용자 확인"]
    D -->|진행 가능| F["데이터 전략 수립"]
    E --> F
    F --> G["도구 실행계획 작성"]
    G --> H["계획 검증"]
    H --> I["통계표 탐색으로 전달"]
```

## 2. 처리할 입력과 참고 정보

입력은 현재 질의만이 아닙니다. 앞선 대화에서 정해진 조건도 함께 고려해야 합니다.

| 입력 | 사용 목적 |
| --- | --- |
| 현재 자연어 질의 | 이번 요청에서 알고 싶은 내용과 조건을 추출 |
| 대화 맥락 | 앞서 지정한 지표·기간·비교 기준·표현 형식 등을 이어받음 |
| 통계 범위 | 현재 프로젝트의 대상인 KOSIS 한국은행 소관 통계표에 맞춰 해석 |
| 통계표 카탈로그 | 표 이름과 분류 경로를 사용해 탐색할 용어와 후보를 구성 |

제공된 카탈로그 스냅샷에는 한국은행 통계표 349개가 있으며, 표 ID, 표 이름, 통계 ID, 기관 ID, 분류 경로 등이 들어 있습니다. 이 목록은 **표를 찾기 위한 색인**으로 활용합니다. 표 이름에 드러나는 ‘원계열·계절조정계열’, ‘말잔·평잔’ 등의 표현은 후보를 구분하는 단서가 될 수 있지만, 단위·주기·항목·수록 기간은 메타정보 조회에서 확인해야 합니다.

## 3. 세 컴포넌트

### 3.1 의도·조건 추출

자연어에서 분석 목적과 조회 조건을 뽑아 구조화합니다. 사용자가 말하지 않은 조건은 임의로 채우지 않고 미지정 상태로 둡니다.

| 추출 항목 | 내용 | 예시 |
| --- | --- | --- |
| 분석 의도 | 현황, 추세, 비교, 변화, 관계 탐색 등 | “최근 추이를 보여줘” → 추세 |
| 지표 | 알고 싶은 통계 개념 | 기준금리, M2, 대출 연체율 |
| 대상·분류 | 대상 집단, 산업, 기관, 상품 등의 범위 | 중소기업, 가계, 은행 |
| 지역 | 지역 또는 국가 범위 | 대한민국, 서울 |
| 기간 | 시작·종료 시점 또는 상대 기간 | 2020년 이후, 최근 5년 |
| 주기 | 월·분기·연 등 | 월별, 분기별 |
| 비교 대상 | 서로 비교할 지표나 집단 | 기준금리와 대출금리 |
| 계산·가공 | 증감, 증감률, 비율 등 | 전년 동월 대비 증감률 |
| 결과 형식 | 표·그래프 및 설명 선호 | 선 그래프와 간단한 설명 |

**산출물:** 원문 질의, 추출한 조건, 미지정 필드, 분석 의도.

### 3.2 통계 개념 정규화와 모호성 관리

사용자의 표현을 카탈로그 검색에 쓸 수 있는 통계 개념 후보로 바꾸고, 중요한 해석 차이가 있으면 확인이 필요한지 판단합니다. 원래 표현은 후보와 함께 보존합니다.

예를 들어 “대출금리”는 신규취급액 기준인지 잔액 기준인지, “물가”는 소비자물가지수인지 물가상승률인지에 따라 다른 자료를 가리킬 수 있습니다. 이 경우 후보 간 차이를 설명하고 확인을 요청할 수 있습니다.

모호성을 다음 원칙으로 처리합니다.

| 상황 | 처리 |
| --- | --- |
| 해석이 결과를 크게 바꿈 | 사용자에게 후보와 차이를 제시해 확인 |
| 합리적인 기본값이 있고 결과 영향이 작음 | 가정을 기록하고 진행 |
| 카탈로그에서 관련 표를 찾을 수 있을지 불확실함 | 후보 탐색을 계획하고 메타정보로 확인 |
| 프로젝트의 데이터 범위를 벗어남 | 범위를 안내하고 가능한 대체 질의를 제안 |
| 조건이 서로 충돌함 | 충돌을 설명하고 우선할 조건을 확인 |

**산출물:** 정규화된 개념 후보, 후보를 선택한 근거, 모호성 목록, 확인 질문 또는 적용할 가정.

### 3.3 실행계획 생성

정리된 의도와 조건을 바탕으로 사용할 도구, 순서, 분기, 확인 항목을 계획합니다. 실제 통계표 개수나 병합 가능 여부는 탐색 및 메타정보 확인 후 확정하므로 여기서는 **예상 또는 가설**로 둡니다.

| 요청 유형 | 기본 실행계획 |
| --- | --- |
| 단일 지표 현황 | 표 탐색 → 메타정보 확인 → 시점·항목 확정 → 자료 조회 → 결과 생성 |
| 단일 지표 추세 | 표 탐색 → 메타정보 확인 → 기간·주기 확인 → 시계열 조회 → 표 또는 그래프 생성 |
| 복수 지표 비교 | 지표별 표 탐색 → 각 표의 메타정보 확인 → 조회 파라미터 확정 → 자료 조회 → 정합 가능성 검증 → 병합 및 결과 생성 |
| 증감·증감률 요청 | 필요한 기준 시점 확인 → 자료 조회 → 계산식·비교 기준 적용 → 결과와 산식 제시 |
| 관계 탐색 | 지표별 자료 탐색 → 공통 기간·주기 확인 → 자료 정합 → 분석 수행 → 해석 한계 표시 |

복수 표 요청에서는 주기, 수록 기간, 단위, 결측값을 정합성 확인 항목으로 둡니다. 조회 결과를 살펴보지 않은 채 병합 방식을 미리 확정하지 않습니다.

**산출물:** 예상 데이터 전략, 도구 호출 계획, 확인할 메타정보, 분기 조건, 실패 시 대안.

## 4. 상세 처리 단계와 산출물

| 세부 단계 | 하는 일 | 산출물 |
| --- | --- | --- |
| 1. 원문·맥락 정리 | 질의 원문을 보존하고, 앞선 대화에서 정해진 조건을 연결 | `original_query`, `conversation_context` |
| 2. 분석 의도 분류 | 현황·추세·비교·변화·관계 탐색 등 요청 목적을 분류 | `intent`, `analysis_operation` |
| 3. 조건 추출 | 지표·대상·지역·기간·주기·비교 대상·계산·출력 조건 추출 | `query_slots`, `unspecified_fields` |
| 4. 개념 정규화 | 사용자 표현을 통계 탐색용 개념 후보로 변환하고 원문을 보존 | `raw_terms`, `normalized_candidates`, `normalization_evidence` |
| 5. 카탈로그 검색어 구성 | 표 이름과 분류 경로를 참고해 탐색 검색어·후보 가설 구성 | `table_search_terms`, `candidate_hypotheses` |
| 6. 모호성·충돌 점검 | 여러 해석, 중요 조건 누락, 조건 간 충돌을 확인 | `ambiguities`, `constraint_conflicts` |
| 7. 확인·가정 결정 | 질문할 항목과 기록 후 진행할 기본값을 구분 | `clarification_status`, `clarification_question`, `assumptions` |
| 8. 데이터 전략 수립 | 단일·복수 지표 가능성과 메타정보·정합성 검증 항목 설정 | `data_strategy`, `metadata_checks` |
| 9. 도구 계획 작성 | 탐색·메타 확인·조회·정합·결과 생성의 순서와 분기를 기술 | `tool_plan`, `branch_conditions`, `fallbacks` |
| 10. 계획 검증·전달 | 사용자 의도와 계획의 일치 여부를 확인하고 다음 단계로 전달 | `plan_validation`, `planning_status` |

## 5. 표준 산출물

Query Planning은 다음과 같은 구조화된 계획을 만듭니다. 통계표 ID나 조회 파라미터는 이 단계에서 확정하지 않고 후속 탐색 결과로 채웁니다.

  "intent": {

  },
  "entities": {
    "metrics": [
      {
        "raw_term": "기준금리",

    },

## 6. 사용자 확인과 진행 상태

계획 생성 후에는 다음 세 상태 중 하나로 정합니다.

| 상태 | 의미 | 다음 동작 |
| --- | --- | --- |
| `READY_FOR_RETRIEVAL` | 탐색을 시작할 조건이 충분함 | 통계표 탐색으로 전달 |
| `NEEDS_CLARIFICATION` | 해석에 따라 표나 결과가 달라질 수 있음 | 짧은 확인 질문 제시 |
| `UNSUPPORTED_OR_UNCLEAR` | 요청이 데이터 범위 밖이거나 현재 표현만으로 처리하기 어려움 | 한계를 설명하고 대체 질의 제안 |

예를 들어 “최근 5년 기준금리와 M2 추이를 비교해줘”라면 두 지표, 기간, 비교 의도, 그래프 선호를 추출해 탐색 계획을 만듭니다. 카탈로그의 표 이름과 경로는 후보를 찾는 데 쓰고, 계열·주기·단위·수록 기간을 실제로 확인한 뒤 조회 및 병합 가능성을 결정합니다.

## 7. 평가 기준

세 컴포넌트별로 다음을 측정하면 오류가 어느 단계에서 생겼는지 구분할 수 있습니다.

| 컴포넌트 | 평가 항목 |
| --- | --- |
| 의도·조건 추출 | 의도 분류 정확도, 지표·기간·비교 대상 추출 정확도 |
| 개념 정규화·모호성 관리 | 적절한 후보 포함률, 필요한 확인 질문 비율, 불필요한 질문 비율, 잘못된 가정 비율 |
| 실행계획 생성 | 도구 순서의 적절성, 필요한 메타정보 확인률, 조회·병합 계획의 적합성 |

이 구성에서 Query Planning의 완료 지점은 **검증할 조건과 도구 순서가 명시된 계획을 통계표 탐색에 넘기는 시점**입니다. 통계표 선택과 실제 파라미터 확정은 탐색·메타정보 단계에서 이어집니다.
