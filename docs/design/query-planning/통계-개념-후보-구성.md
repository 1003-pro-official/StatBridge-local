`통계 개념 후보 구성`은 사용자가 쓴 표현을 통계표 탐색에 활용할 수 있는 **하나 이상의 개념 후보**로 바꾸는 과정입니다.

예를 들어 “금리”를 바로 특정 통계표로 연결하지 않습니다. 사용자의 표현은 유지한 채 가능한 개념을 구성하고, 표 카탈로그와 메타정보에서 후보가 실제로 제공되는지 확인하도록 다음 단계에 전달합니다.

### 입력과 출력

| 구분 | 내용 |
| --- | --- |
| 입력 | 질의 원문, 의도·조건 추출 결과, 앞선 대화에서 사용자가 확정한 조건 |
| 출력 | 원문 표현과 연결된 개념 후보, 후보를 만든 근거, 후보별 미확정 조건, 탐색에 사용할 검색어 |

**개념 후보와 통계표 후보는 다릅니다.** 개념 후보 구성은 “무엇을 찾을지”를 정리하고, 통계표 탐색은 그 개념을 제공하는 실제 표를 찾습니다.

### 처리 흐름

```
원문에서 지표 표현 추출
    ↓
관리 용어 사전에서 표기·별칭 검색
    ↓
한국은행 카탈로그의 표 이름·경로와 대조
    ↓
필요하면 추가 표현 후보 생성
    ↓
후보별 근거와 모호성 정리
    ↓
개념 후보와 검색어를 통계표 탐색에 전달
```

| 세부 단계 | 하는 일 | 산출물 |
| --- | --- | --- |
| 1. 지표 표현 분리 | 질의에서 지표를 나타내는 구절을 추출하고 나머지 조건과 분리 | `raw_term`, 주변 문맥 |
| 2. 용어 사전 대조 | 공식 용어, 별칭, 약어, 자주 쓰이는 사용자 표현과 연결 | 기존에 검토된 개념 후보 |
| 3. 카탈로그 대조 | 표 이름과 분류 경로에서 일치하거나 관련된 표현을 찾음 | 카탈로그 기반 검색 후보 |
| 4. 표현 확장 | 사전·카탈로그에 정확히 없을 때 동의 표현이나 풀어쓴 표현을 제안 | 임시 검색어 후보 |
| 5. 후보 관계 정리 | 후보가 같은 개념의 표기 차이인지, 서로 다른 통계 개념인지 구분 | 동의어·상하위·경쟁 후보 관계 |
| 6. 근거·불확실성 부여 | 후보가 생긴 이유와 추가로 확인할 구분을 기록 | 후보별 근거와 확인 조건 |
| 7. 탐색 단계로 전달 | 후보와 검색어를 묶어 실제 표 탐색에 전달 | `concept_candidates`, `search_terms` |

### 후보를 만드는 정보원

후보는 한 곳에서만 만들지 않고, 근거가 분명한 순서로 구성합니다.

1. **관리 용어 사전**
    
    사람이 검토한 공식 명칭, 사용자 표현, 약어, 별칭, 혼동 가능성을 활용합니다.
    
2. **한국은행 통계표 카탈로그**
    
    제공된 349개 표 목록의 `tbl_nm`과 `path`를 대조합니다. 표 제목과 분류 경로에 나타난 표현을 통해 실제 탐색 대상에 가까운 후보를 찾습니다.
    
3. **질의 시점의 표현 확장**
    
    위 두 정보원으로 후보가 부족하면 LLM이 관련 표현을 제안할 수 있습니다. 이 후보는 임시 검색어로만 취급하고, 실제 카탈로그나 메타정보에서 확인될 때까지 확정 용어로 저장하지 않습니다.
    

후보가 나온 출처를 기록하면, 시스템이 왜 특정 표현을 찾아보려 했는지 설명할 수 있습니다.

### 용어 사전 항목

초기 사전은 모든 한국어 통계 표현을 포괄할 필요가 없습니다. 탐색에 도움이 되는 연결을 점진적으로 저장하면 됩니다.

| 필드 | 의미 |
| --- | --- |
| `concept_id` | 내부에서 사용할 개념 식별자 |
| `canonical_label` | 대표 통계 개념 이름 |
| `aliases` | 사용자가 자주 쓰는 표현, 약어, 표기 변형 |
| `catalog_anchors` | 연결된 표 이름·분류 경로 또는 검토된 표 ID |
| `related_concepts` | 상위·하위 개념 또는 혼동 가능한 다른 개념 |
| `disambiguation_note` | 개념을 구분할 때 확인해야 하는 기준 |
| `source` | 사전, 카탈로그, 검토된 질의 등 후보 근거 |
| `review_status` | 자동 제안, 검토 대기, 검토 완료 여부 |

검토 상태를 두면 자동 생성된 후보가 사람의 검토 없이 사전에 정착되는 것을 막을 수 있습니다.

### 후보 순위와 모호성 처리

후보의 순위는 단순히 문장 의미가 비슷한 순서만으로 정하지 않습니다. 다음 근거를 함께 사용합니다.

- 검토된 공식 명칭 또는 별칭과 정확히 일치하는가
- 실제 표 이름에 해당 표현이 있는가
- 표의 분류 경로가 요청의 주제와 맞는가
- 질의의 대상·지역·기간 등 다른 조건과 충돌하지 않는가
- 후보가 요청한 계산이나 비교에 필요한 개념인가

정확한 일치가 없으면 후보를 여러 개 남길 수 있습니다. 예를 들어 `대출금리`라는 표현은 대상과 기준에 따라 여러 개념으로 이어질 수 있으므로, 시스템이 하나를 조용히 선택하면 안 됩니다. 후보를 표 탐색에 넘겨 메타정보로 좁힐 수 있는지 확인하고, 결과가 달라질 선택이 남으면 사용자에게 역질문합니다.

### 예시

질의:

> 최근 5년 기준금리와 M2 추이를 비교해줘.
> 

| 원문 표현 | 개념 후보 구성 | 탐색에 전달할 내용 |
| --- | --- | --- |
| `기준금리` | 검토된 용어 사전과 카탈로그를 대조해 기준금리 관련 개념 후보 구성 | `기준금리`, 공식 명칭 후보, 관련 표 이름·경로 검색 |
| `M2` | 카탈로그의 M2 관련 표 이름·경로를 기준으로 후보 구성 | `M2`, `광의통화` 등 검색 표현 |
| `최근 5년` | 지표 개념 후보가 아닌 기간 조건으로 유지 | 기간 조건을 각 표의 수록 기간과 대조하도록 전달 |
| `비교` | 지표를 묶어 추세 비교 의도로 전달 | 후보 표의 주기·단위·기간 정합성 확인 요청 |

M2 후보에 표 이름상 계열 구분이 여럿 보이더라도 이 단계에서 어느 계열을 쓸지 확정하지 않습니다. 표 메타정보를 확인한 뒤 요청에 맞는지 판단합니다.

### 산출물 예시

```
{
  "mentions": [
    {
      "raw_term": "기준금리",
      "concept_candidates": [
        {
          "label": "한국은행 기준금리 관련 개념",
          "source": ["curated_lexicon", "table_catalog"],
          "evidence": ["사용자 표현과 검토된 별칭 연결"],
          "unresolved_dimensions": []
        }
      ],
      "search_terms": ["기준금리"]
    },
    {
      "raw_term": "M2",
      "concept_candidates": [
        {
          "label": "M2(광의통화) 관련 개념",
          "source": ["table_catalog"],
          "evidence": ["표 이름 또는 분류 경로에 관련 표현 존재"],
          "unresolved_dimensions": ["표의 계열 구분", "항목"]
        }
      ],
      "search_terms": ["M2", "광의통화"]
    }
  ],
  "status": "READY_FOR_TABLE_RETRIEVAL"
}
```

여기서 후보 이름은 탐색을 위한 가설입니다. 실제 표 ID나 최종 선택 결과는 통계표 탐색과 메타정보 확인에서 채워집니다.

### 운영 원칙

- **원문을 보존합니다.** 정규화된 후보가 원래 사용자의 표현을 덮어쓰지 않게 합니다.
- **여러 후보를 허용합니다.** 모호한 표현을 하나의 답으로 억지로 축소하지 않습니다.
- **근거를 함께 저장합니다.** 후보가 사전, 카탈로그, 자동 확장 중 어디서 왔는지 남깁니다.
- **자동 후보는 검증 대상으로 취급합니다.** 실제 표나 메타정보와 연결되지 않은 후보를 정답처럼 제시하지 않습니다.
- **실패 사례를 사전에 반영합니다.** 골든셋과 탐색 기록에서 반복되는 별칭·혼동 사례를 검토해 용어 사전을 보완합니다.

따라서 처음부터 대규모 통계용어 사전을 완성하는 것이 목표는 아닙니다. 카탈로그를 기반으로 검색 후보를 만들고, 반복적으로 중요해지는 사용자 표현과 모호성만 검토된 용어 사전에 축적하는 방식이 적합합니다.
