## 질의 해석 · Query Planning 단계의 에이전트

이 단계는 사용자가 제출한 질의를 받아 **사용자가 원하는 분석을 구조화하고, 이를 수행할 절차를 계획하는 단계**입니다. 사용자가 입력한 원문은 그대로 보존하면서 지표·기간·비교 조건을 뽑고, 해석이 불확실한 부분은 표시합니다.

이때 에이전트는 실제 통계값을 답하거나 통계표를 최종 확정하지 않습니다. 산출한 계획을 다음 `통계표 탐색 (Retrieval)` 단계로 넘깁니다.

```
제출된 질의
    ↓
의도·조건 추출
    ↓
통계 개념 후보 구성
    ↓
모호성·누락·조건 충돌 판단
    ├─ 중요한 선택이 필요함 → 사용자에게 확인
    └─ 진행 가능 → 가정과 미확정 조건을 기록
    ↓
도구 실행계획 작성
    ↓
통계표 탐색으로 전달
```

### 에이전트가 처리하는 내용

| 처리 항목 | 에이전트가 하는 일 | 예시 |
| --- | --- | --- |
| 분석 의도 | 현황, 추세, 비교, 변화, 관계 탐색 등 요청 목적을 식별 | “추이를 비교해줘” → 추세 비교 |
| 지표와 대상 | 알고 싶은 지표와 집단·지역·기관 조건을 추출 | “중소기업 대출 연체율” → 연체율 지표와 중소기업 조건 |
| 기간과 주기 | 기간 표현을 추출하고, 월·분기·연 주기가 지정됐는지 기록 | “최근 5년” → 기간 조건, 주기 미지정 |
| 비교와 가공 | 비교 대상과 증감률 등 계산 요구를 정리 | “작년보다 얼마나 늘었어?” → 전년 비교 및 변화량/변화율 해석 |
| 통계 용어 후보 | 사용자의 표현을 통계표 탐색에 쓸 표현 후보로 정리 | “M2” → M2 관련 통계표 후보 검색어 |
| 모호성 판단 | 여러 해석이 결과를 바꾸는지 판단 | “대출금리” → 신규취급액 기준인지 잔액 기준인지 검토 |
| 툴 계획 | 탐색·메타 확인·조회·정합·표현에 필요한 절차를 정리 | 복수 지표면 지표별 탐색 후 주기·단위 확인 계획 |

### 한국은행 통계표 카탈로그의 활용

제공된 한국은행 표 카탈로그의 표 이름과 분류 경로는 통계표 탐색을 위한 **검색 단서**로 사용합니다. 표 이름에 드러난 계열이나 기준의 구분도 후보를 찾는 데 도움이 됩니다.

예를 들어 M2를 요청한 경우 M2 관련 표 이름과 경로를 이용해 탐색 검색어와 후보 가설을 만들 수 있습니다. 다만 해당 표의 항목, 계열, 단위, 주기, 수록 기간을 확인한 뒤에야 실제 조회 계획을 구체화할 수 있습니다. 카탈로그만으로 특정 표가 요청에 맞는다고 확정하지 않습니다.

### 확인 질문과 자동 진행의 기준

에이전트는 결과를 바꿀 수 있는 모호성에 집중해 확인합니다.

- **결과가 달라지는 해석:** 확인 질문을 합니다.예: “대출금리”가 신규취급액 기준인지 잔액 기준인지에 따라 수치가 달라질 때.
- **탐색 후 좁힐 수 있는 사항:** 후보 탐색 단계로 넘깁니다.예: “물가”처럼 관련 통계 개념이 여럿 있지만 표의 설명과 항목을 보면 후보를 좁힐 수 있을 때.
- **표현 방식처럼 쉽게 바꿀 수 있는 사항:** 기본안을 제안하고 가정으로 기록합니다.예: 시계열 비교에 선 그래프를 우선 제안할 때.

확인 질문이 필요한 경우에는 선택의 차이를 함께 설명합니다. 사용자가 답하기 전까지 결과에 영향을 주는 조건을 임의로 정하지 않습니다.

### 툴 실행계획

계획에는 도구 이름만 나열하지 않고, **각 호출의 목적과 다음 단계로 넘어가는 조건**을 포함합니다.

| 순서 | 계획할 작업 | 확인할 내용 |
| --- | --- | --- |
| 1 | `search_tables` — 관련 통계표 후보 탐색 | 표 이름·분류 경로가 요청한 개념과 맞는지 |
| 2 | `get_table_metadata` — 후보 표의 메타정보 확인 | 항목, 단위, 주기, 계열, 수록 기간 |
| 3 | 표·항목·조회 조건 확정 | 후보가 복수로 남거나 해석이 달라지면 사용자 확인 |
| 4 | `query_data` — 확정된 조건으로 자료 조회 | 요청 기간과 조건에 맞는 원자료 확보 |
| 5 | 복수 표인 경우 정합·병합 계획 수행 | 공통 기간·주기, 단위, 결측 처리 가능성 |
| 6 | `render_result` — 결과 표현 | 질의 의도에 맞는 표·그래프와 설명 구성 |

Query Planning 단계에서 실제 API를 호출하거나 표 ID를 최종 선택할지는 구현 구조에 따라 달라질 수 있습니다. 기본 흐름에서는 이 단계가 계획을 만들고, 통계표 탐색 단계가 실제 후보 검색을 수행합니다.

### 예시

질의: “최근 5년 기준금리와 M2 추이를 비교해줘”

에이전트가 만드는 초안은 다음과 같습니다.

| 항목 | 해석 |
| --- | --- |
| 의도 | 두 지표의 시계열 비교 |
| 지표 | 기준금리, M2 |
| 기간 | 최근 5년 |
| 비교 방식 | 두 지표의 추이 비교 |
| 출력 | 시계열 그래프 제안 |
| 미확정 조건 | 실제 표·항목, 주기, 단위, 계열 |
| 다음 작업 | 지표별 표 후보 탐색 → 메타정보 확인 → 조회 조건 확정 → 자료 조회 |
| 정합성 확인 | 공통 기간·주기, 단위, M2 계열 구분 |

주기나 단위가 실제로 서로 맞지 않는다면, 조회 이후 병합 방식을 결정하거나 별도 그래프를 제안하는 계획으로 분기합니다.

### 이 단계의 산출물

```
{
  "original_query": "최근 5년 기준금리와 M2 추이를 비교해줘",
  "intent": ["trend", "comparison"],
  "slots": {
    "metrics": ["기준금리", "M2"],
    "time_range": "최근 5년",
    "comparison": "두 지표의 추이 비교",
    "frequency": null,
    "output": "시계열 그래프 제안"
  },
  "concept_candidates": [
    "한국은행 기준금리 관련 표",
    "M2 관련 표"
  ],
  "ambiguities": [],
  "metadata_checks": [
    "항목",
    "계열",
    "단위",
    "주기",
    "수록 기간"
  ],
  "tool_plan": [
    "search_tables",
    "get_table_metadata",
    "confirm_table_and_parameters",
    "query_data",
    "check_harmonization",
    "render_result"
  ],
  "status": "READY_FOR_RETRIEVAL"
}
```

상태는 보통 세 가지로 정리합니다.

| 상태 | 의미 |
| --- | --- |
| `READY_FOR_RETRIEVAL` | 탐색 계획이 준비되어 통계표 탐색으로 진행 |
| `NEEDS_CLARIFICATION` | 사용자 선택에 따라 표나 결과가 달라져 확인이 필요 |
| `UNSUPPORTED_OR_UNCLEAR` | 현재 데이터 범위에서 처리하기 어렵거나 요청의 뜻을 좁힐 수 없음 |

정리하면, 이 단계에서 에이전트는 **질의를 구조화하고, 필요한 확인을 판단하고, 통계표 탐색부터 결과 생성까지의 절차를 계획**합니다. 통계표 후보와 조회 조건은 다음 단계에서 메타정보를 확인하며 확정합니다.
