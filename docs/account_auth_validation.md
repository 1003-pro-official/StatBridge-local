# 로그인·계정별 그래프 저장 검증

2026-10-12 · ai-assisted · 작업 대상 StatBridge-local1.

## 구현

StatBridge1의 `StatBridge-official/src`와 런타임 코드를 읽기 전용으로 확인했으나 로그인 화면·인증 API를 찾지 못했다. 기존 코드를 이식했다고 주장하지 않고 local1에 새로 구현했다. StatBridge1은 수정하지 않았다.

테스트 계정은 `test1`, `test2`, `test3`, 비밀번호는 사용자 지정 로컬 테스트 설정을 사용한다. 일반 회원가입은 아이디·이름·이메일·비밀번호·비밀번호 확인을 받는다. 아이디 3~32자, 일반 가입 비밀번호 8~128자, 이메일 형식과 중복을 서버에서 검사한다. 이메일 발송·소유 확인, 비밀번호 재설정, 외부 소셜 로그인은 구현 범위에 포함하지 않았다.

비밀번호는 사용자별 무작위 salt와 scrypt로 저장한다. 세션은 무작위 토큰이고 DB에는 토큰의 SHA-256만 저장한다. 쿠키는 HttpOnly, SameSite=Lax, Max-Age=43200이다. HTTPS 요청에서는 Secure도 설정한다. 만료는 로그인 시점부터 12시간이며 작업 중이라고 연장하지 않는다. 서버가 모든 보호 API에서 만료를 검사하고 브라우저도 만료 시 로그인 화면으로 돌아간다. 로그아웃은 서버 세션을 폐기한다. 실패 로그인 횟수를 제한하며 허용되지 않은 Origin의 변경 요청을 거절한다.

사용자·세션·소유권·저장 목록은 `.venv/cache/accounts.sqlite3`, 그래프 파일은 `.venv/cache/chart_workspaces/user-{id}/`에 보관한다. Git에 게시하지 않는다. 재시작 후 계정·유효한 로그인·저장 목록과 그래프가 유지된다. 데모 계정은 최초 생성만 하고 재시작 때 덮어쓰지 않는다.

## 계정 분리와 최대 5개

조회 세션과 편집 세션의 소유자를 서버에서 기록한다. 다른 사용자의 ID를 요청 본문이나 URL에 넣어도 조회·수정·기존 조회 결합·추천·내보내기·저장 요청을 거절한다. 계정별 저장 목록은 해당 사용자 데이터만 조회한다. 파일 경로도 사용자별로 분리하고 저장 내용 해시를 검증한다.

설정 저장은 해당 계정 목록에 그래프를 추가한다. 같은 그래프의 재저장은 기존 슬롯을 갱신한다. 새로운 여섯 번째 그래프는 409로 거절한다. 목록에서 삭제하면 슬롯을 비우고 저장 파일도 삭제한다. SQLite 쓰기 트랜잭션으로 동시 저장에서도 5개 제한을 유지한다. 파일 커밋 실패 시 새 슬롯이 생성되지 않는 것도 확인했다.

브라우저 저장 키와 history 상태에도 계정 구분을 추가했다. 로그아웃·만료 시 현재 URL의 이전 질의를 지우고 앱을 내린다. 다른 계정의 기록 또는 계정 정보가 없는 이전 기록은 복원하지 않는다. 이전 익명 저장 그래프를 임의 계정에 자동 연결하지 않는다. 사용자가 보관한 JSON을 가져오려면 자기 계정에서 같은 자료의 그래프를 생성한 뒤 가져온다.

## 함께 수정한 편집 오류

기존 `.plotly-chart`의 최소 높이 360px이 작은 중앙 영역을 넘어 대화를 덮었다. 워크스페이스 안에서는 최소 높이를 해제하고 그래프를 실제 중앙 영역에 맞춰 제한했다. 인쇄용 큰 여백은 짧은 화면에서 축소한다. 대화를 펼친 상태에서 그래프 297px, 중앙 영역 297px, 겹침 false를 확인했다. 오류 메시지도 그래프 위에 가려지지 않는 별도 영역이다.

실행 중인 이전 API는 디자인 경로가 없어 404를 반환했다. 확인된 local1 서비스만 최신 코드로 재시작해 6개 디자인을 복구했고 실패 이유와 재시도 버튼도 추가했다. 선 두께·글자 크기는 입력 중 숫자를 즉시 전송하지 않고 Enter/blur 때 범위를 확인한다. 빈 값·99 등의 잘못된 두께는 요청 없이 이전 값으로 돌아간다. `관측점 표시`를 끄면 점이 없는 선으로 표시하며 디자인 변경 후에도 해당 선택을 유지한다.

## 한계

로컬 서비스는 127.0.0.1에 바인딩한다. 인터넷 배포, HTTPS 프록시 환경과 사람 대상 사용성·보안 감사는 별도 검증하지 않았다. 호스트 관리자나 같은 OS 계정이 개발자 도구·로컬 파일을 직접 읽는 상황까지 웹 계정 인증으로 차단하는 것은 이 구현의 범위가 아니다. 화면과 서버 API의 계정 간 접근을 검사했다.
