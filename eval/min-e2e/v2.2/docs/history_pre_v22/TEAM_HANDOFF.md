# 팀원 평가·패치 전달 안내

현재 정본은 이 폴더입니다. 기존 Reviewed_vNext와 실제평가 ZIP은 변경하지 않았습니다. 제품 소스도 변경하지 않았습니다. 새 제품 실행 없이 기존 실제 120문항 증거를 사람 판정과 결합해 재채점했습니다.

## 최신 검증 상태

| 범위 | 결과 |
|---|---|
| 평가셋 정합성·계산·평가기 회귀 검사 | 1,015 / 1,015 통과 (제품 성공률 아님) |
| 실제 실행 | 120개 고유 문항; 선정 명세·원시 실행 보존 |
| 사람 검토자 PNG/PDF 검토 | 18건, 일치 16·불일치 2; 파일·화면·기준 해시 모두 확인 |
| F유형 최종 규칙 결과 | 17건 충족·3건 실패: F22, F27, F34 |
| DA 추가 표 대조 | 20건 일치; API와 별도 UI 실행임을 표시 |
| RAGAS | 기존 실제 채점 58건 평균 0.952586, 22건 NA; 이번 사람 검토로 재호출·재채점하지 않음 |
| 남은 사람 검토 | CQ 의미 적절성 20건, 120문항 정답 계약 승인 |

## 불일치 기준

- 요구사항 충족과 화면↔다운로드 일관성을 따로 평가합니다. 둘 다 잘못된 동일 화면이면 통과가 아닙니다.
- F27: 관측점 하나 편집과 set_point_style이 구현돼 있습니다. B계열 2025년 6월의 #E53935 점이 해당 좌표에 실제 보이고, 기간 변경 뒤에도 남으며, PNG/SVG에도 보여야 합니다. 색상 JSON만 있거나 점 크기 0이면 실패입니다. 전체 계열 색 변경은 대체 정답이 아닙니다. 새 크기·모양의 임의 정답은 추가하지 않았습니다.
- F22: 사람 검토자가 PDF 범례 순서 불일치를 판정했습니다. 화면의 계열 읽기 순서를 가로 범례에서도 보존해야 합니다. 픽셀 위치 자체를 동일하게 요구하는 기준은 아닙니다. PNG는 일치, PDF는 불일치입니다.
- F34: PNG 일치 판정은 수용하되 그래프 숨김이 표 선택을 바꾸는 별도 실패를 취소하지 않습니다.
- E37: 같은 기간의 색·점선 설정을 유효 스타일로 합산해야 합니다. 앞선 실패는 평가 도구 오탐으로 정정했습니다.
- D23: 평균 지표를 당월 지표로 바꾼 Judge 분해 오류 후보입니다. 원점수 보존, 사람 판정 전 확정 제품 결함으로 사용하지 않습니다.

## 실행·패치 순서

1. runner/questions.jsonl와 runner 시나리오만 프로그램 입력으로 사용합니다. oracle는 실행 뒤 비교용이며 모델 프롬프트·검색 문서·RAGAS factual context에 넣지 않습니다.
2. 대상 커밋·환경·모델·시각·원자료를 기록하고 각 사례를 독립 실행합니다. 초기 질의 상태와 평가용 준비 상태를 각각 캡처합니다. E40/F34의 ‘처음’은 질의 직후 캡처입니다.
3. 답변·실제 계산계획/입력값·화면·동일 편집 버전의 다운로드를 수집합니다. CSV/XLSX는 파싱한 값, SVG는 스타일과 좌표, PNG/PDF는 실제 이미지로 판정합니다.
4. provider/할당량/메타데이터 확인 실패는 제품 실패와 분리합니다. 유효 초기 준비가 실패하면 사유를 남기고 전체 사례를 재실행하며 가장 좋은 점수만 고르지 않습니다.
5. 실패별 실제 근거와 원인을 확인한 뒤 제품을 패치하고 새 run_id로 회귀 실행합니다. 정답을 제품 출력에 맞춰 고치지 않습니다. 정답 오류 발견 시 독립 근거·변경 이유·사람 승인을 받고 별도 버전으로 만듭니다.
6. 변경 전후 결과를 같은 기준으로 비교합니다. 파일 시각 승인과 정답 계약 승인, 자동 규칙 충족을 분리해서 보고합니다.

## 기존 증거 재채점 명령

증거 ZIP을 evidence 폴더에 푼 뒤 실행합니다. 새 제품 평가가 아닌 기존 캡처 재채점입니다. Python은 제품 의존성이 설치된 환경을 사용합니다.

```powershell
python -B scripts/score_live_bundle.py --evidence-root evidence/StatBridge_live_verification --output results/replay_new.json
```

120개 기존 증거의 재채점 결과가 전달 결과와 동일한지 확인했습니다. 새 평가 시에는 새 관측 파일과 --observations 옵션을 사용하며 run_id별 실제 근거 폴더를 제공해야 합니다.
