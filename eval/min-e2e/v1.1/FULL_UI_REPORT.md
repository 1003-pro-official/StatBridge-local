## 실행 범위와 입력 분리

- 실제 in-app Chromium 브라우저 → 테스트 계정 로그인 → 새 채팅 → 원문 질의 입력 → 실제 `/api/query` → 필요한 경우 자동 `/api/output` → 결과 또는 역질문 UI 확인.
- 실제 KOSIS API 및 현재 local1의 실제 모델 사용. 고정 응답 replay, 정답 계획 주입, 브라우저 API 응답 mock, 편집 세션 직접 주입은 사용하지 않았습니다. 일부 경로는 제품의 규칙 기반 해석을 사용하므로 모든 문항이 동일한 모델 호출 수를 갖지는 않습니다.
- 평가 전용 localhost:18110과 독립 계정 DB·쿠키·실행 디렉터리 사용. 기존 사용자 계정·저장 분석·.env는 복사하거나 덮어쓰지 않았습니다.
- 실행 입력은 evaluation_runs/min-e2e-v1.1/input/questions.jsonl의 id/query만 사용. 정답과 최신월 근거는 scorer-only에 분리. 제품 코드에는 평가 ID·정답·질의 파일을 넣지 않았습니다. 프로세스 수준의 완전한 OS 접근 차단을 검증한 실행은 아닙니다.
- 최신월은 평가 전 별도 공식 요청으로 202609를 확인. 원본 역질문 라벨·질의는 변경하지 않았습니다.

## 패치 내용

1. 예금은행이라는 기관명을 예금·수신 통계 요청으로 잘못 해석하지 않도록 구분하고, 신규취급액/잔액이라는 표 기준을 별도 상위 계열로 중복 선택하지 않도록 수정.
2. 명시된 지역 분류, 원계열/비계절조정 조건, 시장가격 GDP와 연간 주기를 메타데이터에 맞게 선택.
3. 인접 두 연도의 연간 값 요청을 닫힌 기간으로 처리. SNA 기준연도·통계표 수록 시작연도를 관측 기간과 구분.
4. 통계 항목명·분류명의 합계를 새 산술 연산으로 오인하지 않도록 분기. 명확한 월별 산술평균은 계산 경로로 처리하고 종료월 한 점 출력과 필요한 과거 입력을 분리.
5. M2의 잔액/조정 기준, 경제심리지수의 계열, 물가지수의 통화 기준, 모호한 연간 대표값은 필요한 조건만 확인.
6. ‘이 자료’가 ‘이자’로 이어 붙어 금리 요청이 되는 부분문자열 오인과, 가격지수의 통화 기준이 통화량 지표로 오인되는 문제 수정.
7. 최신 제공 관측월을 실제 요청 계열에서 조회하고 이후 오래된 카탈로그 종료월로 다시 자르지 않도록 수정.
8. 이번 요청의 명시적 통화 변경이 이전 합의를 대체하도록 처리. 과거 원화와 새 달러를 두 계열 요청으로 합치지 않음.
9. 반복 메타데이터 제목 정규식 컴파일을 캐시하고 중복 제목 집계를 선형 처리하여 반복 탐색 비용 축소.

변경 파일은 query_conditions.py, semantic_catalog_planner.py, catalog_request_planner.py, canonical_request_planner.py, request_match_guard.py, request_period.py, agent_runtime.py, derived_indicator_planner.py, derived_request_period.py, bridge_api.py입니다. 각 파일에는 이번 작업 이전의 변경도 있으므로 전체 Git diff를 이번 패치만의 변경량으로 해석하지 않습니다.

## 회귀 검증

- 집중 회귀 20개 통과. 추가 호환성 회귀 42개도 통과했습니다. 기존 기간/실행 오류/네트워크 비설정 관련 9개 검사는 검사 대상이 아닌 계열 모호성을 제거하도록 원계열을 명시했으며 기존 검증 조건은 유지했습니다.
- 전체 pytest: `2332 passed, 355 subtests passed; 실패/오류/건너뜀 0; 4개 묶음 종료코드 모두 0`
- 전체 pytest는 123개 파일을 중복 없는 네 묶음으로 실행했습니다. 합산 고유 기본 검사 2,332개는 진단 전수 실행의 고유 검사 집합과 정확히 일치하며 누락·중복이 없습니다. JUnit 합계 2,687개에는 하위 검사 355개가 포함됩니다. 타입 검사·프런트엔드 빌드·공개 v4.1 검증기 모두 종료코드 0입니다. 최종 완료 기록은 completion.json, 묶음별 로그/XML은 regression-shard-1~4입니다.

## 증거와 주의점

- 최종 문항별 DOM·전체 화면 PNG: `evaluation_runs/min-e2e-v1.1/release2/ui/`
- 실제 query/output 응답: `evaluation_runs/min-e2e-v1.1/release2/responses.jsonl`
- 독립 채점: `evaluation_runs/min-e2e-v1.1/release2/scores.json`
- 공식 최신월 사전 확인: `evaluation_runs/min-e2e-v1.1/scorer-only/latest-official.json`, `preparation.json`
- 최종 소스 해시: `evaluation_runs/min-e2e-v1.1/release2/source-manifest.json`
- 초기 API 응답은 baseline/responses.jsonl에 보존. 중간 화면 캡처 도우미의 경로 참조 문제로 최초 스크린샷 일부가 뒤 실행 화면으로 덮어써졌습니다. 따라서 최초 점수는 보존된 첫 API 응답으로 재채점했으며 모든 최초/최종 화면쌍이 독립 보존됐다고 주장하지 않습니다. release2는 저장 경로와 기존 호환성 수정 후 동일 코드로 40문항을 새로 캡처했습니다.
- 최초 임시 22/40 집계는 의미 검토에서 구 M2 제외 및 필수 조건의 실제 확인을 적용해 21/40으로 정정했습니다. 라벨을 바꾼 것이 아니라 최초 응답을 같은 기준으로 다시 판독한 것입니다.
- CQ1-16은 전체 페이지 캡처 오류로 뷰포트 PNG를 보존했습니다. 해당 이미지에 실제 표시 종료일 2026-09-30이 보이며 전체 DOM도 함께 보존했습니다. 나머지 최종 문항은 전체 페이지 PNG입니다. CQ1-17의 응답 전 조기 캡처는 incomplete-capture로 분리하고 새 채팅의 완료된 실제 응답과 화면으로 교체했습니다. 최종 결과는 개발 회귀이며 무재시도 최초 시도 성능으로 주장하지 않습니다.
- 원본 Agent 실행기의 모델 요청 최소 15초 간격은 이번 UI 실행에 추가 적용하지 않았습니다. 실제 제품 클라이언트의 제한·시간 예산을 유지했습니다. 원본 Agent 점수와 직접 같은 실행 조건으로 비교하지 않습니다.
- 후속 답변에 대한 다중 턴 재개, 다운로드 파일, 편집 기능, StatBridge1의 이번 패치 동기화·실행은 이 40문항 평가에 포함하지 않았습니다.

## 관측된 실제 호출

HCX-007: 2회, gpt-6.1-sol: 7회. 실제 KOSIS HTTP span 38개, 그중 HTTP 200 38개. 이는 앱 관측 span의 고유 ID로 중복 제거한 수이며 준비 단계의 별도 최신월 요청은 포함하지 않습니다.

평가용 18110 서버는 종료했습니다. 기존 8000 서버 PID 24120은 유지했습니다. 기존 실행 프로세스에서 새 백엔드 코드를 사용하려면 서버를 재시작해야 합니다.
