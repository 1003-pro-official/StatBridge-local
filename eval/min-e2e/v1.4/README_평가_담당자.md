# StatBridge v1.4 평가셋 — 담당자 전달 안내

이 자료는 공개 개발 회귀 평가용 50문항이며 블라인드 평가가 아닙니다. 2026-10-27 사용자가 v1.4 참고 정답·그래프·채점 기준을 승인했습니다. 정확한 승인 범위와 해시는 `승인_기록.md`를 확인하세요. 원본 문서의 “사람 검수 전”, “검증 대기”, manifest의 `provisional_unapproved`는 승인 전 작성 당시 표기입니다. 승인 이후 원본 내용을 소급 수정하지 않아 남아 있습니다. 원자료의 독립 원천 교차 검증이나 제품 평가 통과를 뜻하지 않습니다.

## 구성

- `questions.md` / `질문_50문항.md`: 동일한 실행용 질문 50개. 채점 기준의 기존 링크는 후자를 가리킵니다.
- `answers.md`: 각 문항의 계열·산식·표·그래프 정답 사양. 수치 전 기간은 HTML과 관측값에서 확인합니다.
- `rubric.md`: 승인된 평가 지표와 채점 기준. 원래 제목과 과거 상태 표기는 원본 보존을 위해 유지합니다.
- `reference.html`: 50문항의 전체 기간 참고 표와 그래프. 압축 해제 후 브라우저에서 엽니다.
- `observations.json`: 2026-10-27 조회 원자료 스냅샷.
- `채점_기록_50문항.md`: 문항별 기록용 빈 양식. 채점 시 별도로 사본을 만들어 사용합니다.
- `manifest.json`, `승인_기록.md`: 스냅샷의 해시와 후속 승인 기록.
- `render.py`, `fetch.py`: 당시 참고 출력 생성 및 원천 조회 코드. 아래 재현 안내를 확인하세요.

## 실행·채점 절차

1. 평가 대상 제품의 버전, 실행 시각, 모델과 설정, 데이터 기준일, 환경 및 평가자를 기록합니다. 작동하는 StatBridge와 KOSIS 접근 설정은 별도로 준비합니다. 이 파일에는 API 키와 제품 배포본이 없습니다.
2. 문항마다 새 대화를 시작하고 **질문 파일의 원문만** 제품에 입력합니다. 정답·관측값·표·그래프를 제품이나 모델에 주입하지 않습니다. 제품 실행자와 채점자가 동일한 환경에서 정답에 접근할 수 있으므로 블라인드 평가라고 주장하지 않습니다.
3. 최초 응답의 표·그래프, 계열·출처, 계산식·선행기간과 증거를 기록합니다. 요청이 중단되거나 추가 질문이 나와도 최초 상태를 보존합니다. 재시도·제품 수정 후 실행은 최초 결과와 구분하고, 가장 좋은 결과만 고르지 않습니다.
4. `answers.md`, `reference.html`, `rubric.md`를 사용해 계열·출처(A), 기간·주기(B), 원자료·계산(C), 표(D), 그래프(E)를 문항별로 평가합니다. 원자료와 계산값의 동시 표 표시 요구, 그래프 유형·계열·시점·축·단위·출처, 시점별 값을 확인합니다. 버튼이 존재하거나 숫자 열 하나가 우연히 일치한 것만으로 통과 처리하지 않습니다.
5. 승인된 기준대로 부분점수는 100%, 50%, 0% 또는 미판정으로 표시합니다. 다섯 항목이 모두 판정된 문항만 총점을 계산하고, 80점 이상과 필수 조건을 모두 충족할 때 통과입니다. 외부 장애·미관측·오라클 결함을 0점으로 바꾸지 않습니다. 최종 정성·치명 오류 판정은 사람이 확인합니다.
6. 최종 통과율은 확정 통과 / (확정 통과 + 확정 실패)입니다. 분모가 0이면 산출 불가이며, 대기·환경 장애·미실행·제외 수와 실행률을 같이 보고합니다. 평가 대상·버전이 다른 결과를 합산하지 않습니다.

## 문항별 확인 사항

- 17번: 승인된 기준은 잔액과 거래를 별도 패널로 표시하도록 합니다. 질문에 별도 패널이라는 표현이 명시되지 않아 문항·기준 간 정합성 검토 사항으로 기록하되, 평가 중 임의로 승인 기준을 바꾸지 않습니다.
- 23·24·25·30·31번: 뺄셈 계산의 결측 설명에 증가율의 분모 0 문구가 함께 있지만, 뺄셈에는 분모가 없습니다. 원자료의 0은 유효하며 필요한 당기·전기 값의 결측을 확인합니다. 이는 설명상 주의사항이며 수치 정답 오류로 단정하지 않습니다.
- 39·40번: 질문이 0 기준선을 요구하지 않았으므로 승인된 공통 기준에 따라 0 기준선은 권고입니다. 전월 차이는 같은 표 또는 별도 계산 근거에서 확인할 수 있습니다.
- 41번: 질문은 부산/서울 비율을 요구하고 정답은 %·%p를 제시합니다. 배율과 퍼센트의 정확한 환산 표현을 어떻게 취급할지 검토가 필요한 항목이므로 판정 근거와 이견을 남깁니다.
- 49·50번: 기준시점=100은 질의에 명시됐지만 별도 수평 기준선은 명시되지 않았습니다. 기준 값 표시와 수평선의 해석을 검토하고 판정 근거를 남깁니다.
- 6쌍은 동일 계열·기간·계산에 출력 요구를 달리한 회귀 사례입니다. 50개를 각각 실행하되 독립된 주제 50개로 해석하지 않습니다.

## 참고 자료 재현

`render.py`는 같은 폴더의 `answers.md`와 `observations.json`을 읽어 `reference.regenerated.html`을 생성합니다. Python·matplotlib 및 한글 글꼴이 필요하며 API 키나 네트워크는 필요하지 않습니다. 라이브러리·글꼴·운영체제가 다르면 시각적 출력이나 바이트 해시가 달라질 수 있습니다.

`fetch.py`는 당시 조회 이력을 보여주는 코드로, 이 ZIP 단독으로 실행되지 않습니다. StatBridge 프로젝트의 KOSIS 클라이언트, 실행 경로 및 별도 인증 설정이 필요합니다. 새 조회는 공식 통계의 개정값을 가져올 수 있으므로 승인 당시 스냅샷과 비교하고 기준일을 기록해야 합니다. 스크립트에 키를 넣거나 결과·키를 공개 Git에 커밋하지 않습니다.

`manifest.json`에 나열된 7개 파일은 승인 당시 스냅샷의 해시와 동일합니다. 한국어 파일명 사본과 이 안내문·빈 기록 양식은 전달 편의를 위한 추가 파일입니다. 평가 실행 결과·비밀·환경 설정은 포함하지 않습니다.
