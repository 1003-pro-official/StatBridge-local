# 349개 표 단수·복수 증강 골든셋 v3

기자 질의 v2의 단계별 정답 구조를 유지하고, 공개 한국은행 KOSIS 카탈로그 349개 표 전체를 다루는 **개발 회귀용 1,104문항**을 추가 구성했다. 기존 v2 파일과 정답은 수정하지 않는다. 생성 정답은 런타임 예측이 아니라 카탈로그 코드와 v2에 명시된 기본 조회 정책을 근거로 한다.

| 유형 | 문항 | 검증 의도 |
|---|---:|---|
| v2_original | 30 | v2 질문과 workflow_gold 그대로 보존 |
| single_table | 349 | 각 표의 정식 이름으로 한 표·한 계열 요청 |
| multi_table | 349 | 각 표가 포함되는 두 표·두 계열 요청 |
| multi_classification | 348 | 같은 표의 같은 항목에서 두 분류값 비교 |
| duplicate_title_clarification | 28 | 동명 표를 임의 선택하지 않고 실제 ID 선택지 확인 |

단수와 표 간 복수는 각각 **349/349개 표**를 포함한다. 같은 표 내 분류 비교는 348개 표를 포함한다. `DT_404Y017 생산자물가지수-총지수(1910~1964)`는 분류값이 하나뿐이므로 같은 표의 두 분류 비교를 만들 수 없다. 이 예외도 두 표 비교에는 포함한다. 예외 목록과 표별 커버리지는 manifest에 기록한다.

## 문항과 정답 설계

- 단수 문항은 분류를 지정하지 않았을 때의 대표값 정책을 사용한다. 카탈로그에 유효한 `representative_value_id`가 있으면 그 값, 없으면 첫 분류값이다. 이 기본값은 사용자의 임의 선택을 뜻하지 않으며 골드의 정책으로 명시한다.
- 분류 비교 문항은 두 개의 서로 다른, 이름이 중복되지 않는 값을 사용한다. 어느 분류를 바꾸는지 `1번째 분류`처럼 명시하고 나머지 분류는 이름으로 고정한다. 이름만으로 구분되지 않는 고정 값에는 코드를 보조로 적는다.
- 이름이 완전히 같은 28쌍(56개 표)은 선택 문항에서 표 ID를 보조로 쓴다. ID를 사용하지 않은 별도 28문항은 두 실제 표 ID를 선택지로 반환해야 한다. 이는 ID 없이 자연어로 모두 구별한 정확도로 해석할 수 없다.
- 두 표 비교는 관측 기간이 겹치는 서로 다른 표를 짝지으며 같은 주기를 우선한다. 단 하나인 S(반기) 표는 다른 주기와 짝지어 각 계열의 주기를 따로 기록한다. global `frequency`는 혼합일 때 null이고 `frequencies`와 계열별 frequency를 추가한다.
- `DT_284Y001 잔액표`, `DT_284Y002 거래표`는 카탈로그 주기가 A이고 저장된 API 주기 코드가 Y다. 연간 관측 구간은 같으며 exact API 파라미터 골드에는 API 설정의 Y를 사용한다. 검증기는 두 주기 필드를 함께 비교하고 이 표기 차이를 manifest와 감사 결과에 명시한다. 다른 주기 차이는 오류다. 외부 KOSIS 수치 조회로 주기를 검증한 것은 아니다.
- 증강 선택 문항은 사용자 조회 기간을 지정하지 않는다. **표 제목의 역사 연도는 표 이름의 일부**이며 사용자 기간으로 취급하지 않는다. 월 12관측·분기 8관측·연 5관측(관측 시작일 하한), S는 카탈로그 관측 구간을 골드로 기록하고 API의 기간 입력 대기를 기대한다.
- 30개 v2 원본의 질문·workflow_gold는 그대로 복사한다. 새 문항 ID와 증강 출처만 붙인다. 새 스키마는 `reporter349-discovery-3`이며 v2 검증기를 바꾸지 않는다.

## 전수 점검과 실행 경계

검증기는 1,104문항을 각각 검사하고 전체 ID·질문·동등 계열 조합 중복, 표 커버리지, 분류 코드/이름, 항목, 기관, 주기, 기간, 정확한 API 파라미터, 문구와 지정 분류의 대응, v2 보존, manifest·SHA256를 확인한다. 제목에 연도가 포함된 문항은 오류가 아닌 주의 표시로 별도 기록한다. 이 자동 감사는 사람이 의미를 검수한 승인을 대신하지 않는다.

실행기는 현재 체크아웃의 실제 `POST /api/query(query, execute=false)`를 TestClient로 호출하고 HTTP 반환 직후 문항 JSON과 종료 로그를 저장한다. 수치 조회와 출력 생성은 실패 가드로 막는다. 모든 추론이 끝난 후 정답을 읽어 상태·표·항목·분류·기간·주기·API 파라미터·역질문/기간 대기 응답을 정확히 비교한다. 각 문항은 모든 적용 체크가 통과해야 PASS다.

실제 관측 수치, CSV, 그래프, 수정이 편집과 해석 문장은 검증하지 않는다. 공개 dev / ai-assisted / human_approved=false인 **카탈로그 명칭과 분류 기반 구조적 회귀셋**이며, 블라인드 자유 자연어 일반화 성능이 아니다. 기존 v2 30문항, v4.1 및 다른 평가 계열 점수와 혼용하지 않는다. 실패 실행은 진단 JSON과 종료 로그만 보존한다. 전체 1,104/1,104 통과 시에만 수정 내용과 전체 질문·기대·실제 결과를 담은 최종 REPORT.md를 저장한다. 골드와 채점 기준은 패치 중에도 변경하지 않는다. v2의 30/30 결과 저장 조건도 유지한다.

```powershell
.\.venv\Scripts\python.exe eval/reporter-table-discovery-30/v3/scripts/build.py
.\.venv\Scripts\python.exe eval/reporter-table-discovery-30/v3/scripts/validate.py --output evaluation_runs/reporter349_audit/audit.json
.\.venv\Scripts\python.exe -m pytest -q eval/reporter-table-discovery-30/v3/tests
.\.venv\Scripts\python.exe eval/reporter-table-discovery-30/v3/scripts/evaluate_runtime.py
```

생성 정답 JSONL·manifest·문항 요약은 이 폴더에, 실행 결과·로그·보고서는 Git에서 제외된 `evaluation_runs/`의 실행별 폴더에 둔다. 생성기와 검증기는 키 없이 동작한다. API 실행의 기존 모델/검색 fallback 경로에는 설정된 NCP 연결이 사용될 수 있다. 키와 비공개 holdout은 파일·로그·정답에 포함하지 않는다.
