# PM 전용 비공개 18건 제작 규격

이 문서는 제작 절차만 공개합니다. 비공개 질문·정답·파일 경로는 포함하지 않습니다.
비공개 저장소와 기존 holdout 정답을 개발 작업·검색·테스트·프롬프트에 사용하지 않습니다.

목표는 discovery 6, e2e 8, output 3, edit 1입니다.
세부 구성은 discovery 선택 3·역질문 2·미지원 1, e2e 단일 6·복수 2,
output 선그래프·막대그래프·복수 계열 분리 각 1, edit 제목 변경 1건입니다.
식별자는 SBV2-H0001~H0018, split은 holdout입니다.
공개 환경에서 준비하는 도구와 비공개 작업 명령은 [인계 안내](holdout_support/README.md)를 따릅니다.
실제 비공개 사례 제작·검수·실행은 그 저장소를 연 별도 작업에서만 수행합니다.
PM은 별도 비공개 작업 환경에서 공개 v2 schema의 의미 계약을 따릅니다.
공개 스키마는 유지하고 비공개 어댑터가 ID 정규식과 split을 확장합니다.
공개 dev/test와 합치지 않습니다.

1. 공개 source_inventory와 공개 그룹 목록만 비교해 새로운 원본 그림·계열·기간을 선정합니다.
2. 원본 제목·자료 출처·정확한 셀/페이지·단위·주기를 직접 확인하고 해시와 추출 규칙을 기록합니다.
3. 근거가 확보된 뒤 질문을 작성합니다. 공개 질문의 숫자나 표현만 변경하지 않습니다.
4. 명확한 요청, 불충분한 요청의 역질문, 미지원 요청을 구분합니다.
5. 현재 제품 평가의 output/edit는 실제 지원 계열 조회에서 시작합니다. 파일 업로드나 이전 대화 자동 유지를 가정하지 않습니다. 외부 첨부 과제를 따로 제작한다면 내부 컴포넌트 평가로 분리하고 attachment series_id를 사용하며, 제품 점수와 합치지 않습니다. KOSIS 표·항목·분류 ID를 추측하지 않습니다.
6. 원본 독립 재계산, 그룹 누출 검사, 잘못된 값·ID를 넣는 부정 테스트를 수행합니다.
7. 최소 두 역할이 참여해 제작자와 승인자를 분리합니다. 승인 전에는 pending 상태입니다.
8. 비공개 러너·원본·정답·관측 결과는 비공개 저장소에서만 관리합니다.

관측값이 없는 환경은 미실행으로 기록합니다. 공개 개발 결과를 비공개 공식 점수로 보고하지 않습니다.
공개 저장소에는 비공개 원본·질문·정답·검수 의견을 되돌려 쓰지 않습니다.
