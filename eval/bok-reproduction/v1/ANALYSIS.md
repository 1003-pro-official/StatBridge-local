# v1.1 평가 설계 분석 제안

이 문서는 구현 승인 범위 밖이었던 P5–P9의 영향과 권고안입니다. 여기에 적은 변경은 코드와 데이터에 반영하지 않았습니다.

| 항목 | 비용·영향 추정 | 권고안 |
|---|---|---|
| P5 두 시점 판별력 | 기준 파일럿 골든 셀 24개에서 BOK-06-T의 동일값(3.21→3.21), BOK-15-G1의 급변(14→0)은 두 점만으로 직전 움직임·이상치를 구분하기 어렵습니다. 지정 두 사례에 중간 시점 하나씩 추가하면 +2셀, 총 26셀(+8.3%), 원천 조회·독립 검수도 각각 2건 추가입니다. | 전체 표본 확대 대신 두 진단 사례만 3시점으로 시험하고 버전 변경 시 2셀·2건만 추가 검수합니다. 범위를 늘리기 전 작은 표본에서 파싱·정렬 오류가 실제로 줄어드는지 확인합니다. |
| P6 사례 상관 | 기존 보완 24건 중 22건은 같은 출처 그룹, 18건은 같은 초기 질의입니다. 24건을 독립 표본처럼 계산하면 통과율의 불확실성을 과소평가합니다. | 후속 버전은 여섯 기능 범주를 출처 그룹에 분산하고 초기 질의를 재사용하지 않습니다. 범주별 사례 수와 출처 그룹별 평균을 함께 제시하고, 전체 평균은 그룹 동일 가중치로 계산합니다. 신뢰구간은 그룹 단위 재표집을 사용하며 사례 단위 독립 표본 신뢰구간은 쓰지 않습니다. |
| P7 자연어 현실성 | 기존 기준 파일럿은 “원자료”와 차트 형식을 직접 말해 카탈로그 탐색·출력 계획을 쉽게 합니다. | v4.1의 `language_style`·`difficulty` 구조를 참고해 `variant_of`, `language_style`, `difficulty`를 가진 구어체·간접 표현·축약·오타/영어 혼용 변형을 설계합니다. 변형은 같은 정답 사례의 반복이므로 공식 집계는 기준 사례 단위로 한 번만 반영하고, 스타일별 결과는 진단으로만 표시합니다. |
| P8 단위 표기 | 기존 12건 중 5건은 원천 단위가 없어 blocker이며, 연%/연리%, %p 표기, 지수 기준연도 표기 차이가 문자열 비교의 오탐 원인이 될 수 있습니다. | 정규화 후보표: `연%`↔`연리%`(금리 단위에 한해), `%p`↔`퍼센트포인트`, `2020=100`의 공백·전각 등 서식 정리. 원천 단위와 의미가 확인된 표기만 매핑에 추가하고, blocker 해제는 공식 원천 표기와 독립 검수 1회 후 승인·버전 기록으로 수행합니다. 지수 기준연도는 일반 단위 별칭으로 합치지 않습니다. |
| P9 스냅샷 갱신 | 현재 기대 기간과 “최신” 해석은 2026-10-19 자료 스냅샷, 상대 기간 기준일은 2026-10-20에 묶여 있습니다. 자료 개정은 오답 판정과 골든 해시를 바꿀 수 있습니다. | 새 자료를 별도 스냅샷 버전으로 저장하고 provider SHA·오라클 SHA·메타데이터 SHA를 비교합니다. 변경 계열과 기간에 닿는 사례만 재계산하되 예상 계약이 바뀐 사례의 기존 승인·점수는 승계하지 않습니다. 이전 버전은 보존하고 영향 목록과 재검수 승인을 남긴 뒤 manifest를 갱신합니다. |

P8 정규화 후보는 표기만 통일하며 의미가 다른 측정 단위를 합치지 않습니다.

| 관측 단위 표기 | 정규화 후보 | 적용 범위 |
|---|---|---|
| 연%, 연리% | 연% | 금리 계열에 한정하고 원천 메타데이터가 금리를 확인할 때 |
| %p, 퍼센트포인트 | %p | 차이·변화량을 표시하는 계산 결과에 한정 |
| `2020 = 100`, `2020=100` 및 전각 등 | 공백·문자 폭만 정리 | 지수의 기준연도 값은 보존하고 다른 기준연도와 동치 처리하지 않음 |

Blocker는 공식 표/항목 단위 확인 → 독립 검수자 확인 → 별칭 규칙과 근거를 버전 기록 → 관련 사례 재채점 순서로만 해제합니다. 단위가 자료에서 확인되지 않으면 blocker를 유지합니다.

## 기간 끝 시점 불일치 조사

2026년 7~8월 요청의 고정 제공자에는 202608 관측값이 있지만 공개 `data/processed/bok_periods.csv`의 관련 월간 표 기간 끝은 2026.07입니다. 당시 앱의 `need_period.availablePeriod.max`도 2026-07-31로 반환되어 확인 후 조회가 7월 한 달로 축소됐습니다. 따라서 확인 가능한 직접 원인은 표 기간 메타데이터가 제공자 스냅샷보다 한 달 뒤처져 요청 기간을 제한한 것입니다. 현재 관측만으로는 앱 기간 필터의 독립 버그를 입증하지 않습니다. 메타데이터를 2026.08로 교체한 A/B 재생이나 실제 KOSIS 호출은 금지 조건상 실행하지 않았으므로, 메타데이터 수정 후 API 경로의 기간 필터 동작은 미확정입니다.

`components-20261021-score01.json`은 `core.py` 수정 전 산출물이므로 제외했습니다. 현행 근거는 `components-20261021-score02.json`과 `components-20261021-verify01.json`입니다.
