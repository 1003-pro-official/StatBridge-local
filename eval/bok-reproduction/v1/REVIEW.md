# 골든 정답과 응답 검수

ai-assisted · 모든 승인·검수자는 실제 수행 후 사람이 기록합니다. 작성자는 자기 PR을 머지하지 않습니다.

## 골든 정답 승인

원본 URL·발표일·PDF 물리 페이지/셀·해시를 확인합니다. 질문의 계열·주기·단위·기간과 독립 계산을 확인하고, 부분 응용형을 원본 전체 재현으로 승인하지 않습니다. 승인한 사례의 `review`에 실제 `reviewer`, `human_approved=true`, 정규화된 `input_sha256`, `expected_sha256`을 기록합니다. 해시는 `core.digest_value`로 생성합니다. 값·질문·산식이 바뀌면 재검수합니다. 캐시 원자료와 결과를 공개 파일에 붙이지 않습니다.

실제 승인 반영 후 `python eval/bok-reproduction/v1/scripts/evaluate.py manifest`로 해시를 갱신하고 검증합니다. 이 명령은 승인 상태를 대신 바꾸지 않습니다. 승인된 사례를 `build.py`로 덮어쓰는 것은 차단합니다.

## 응답 검수

실행별 새 review packet을 생성해 실제 응답과 숫자 근거를 확인합니다. 모델명·프로필은 별도 mapping 파일에만 두며 검수자에게 제공하지 않습니다. 응답 본문이 모델을 자칭하는 등 신원이 노출된 경우 검수자가 표시하고 필요하면 재배정합니다.

파생 계산은 `response.calculated_points`, `output_unit`, `output_frequency`, `statistics_requests`를 확인합니다. 컴포넌트 검사에서는 `calculation_evidence.issues`와 `calendar_grid`로 결측·0 분모·빠진 달을 확인합니다. 근거가 없는 항목은 검수 완료로 표시하지 않습니다. 기존 검수 파일이나 mapping 파일을 재사용하지 말고 새 출력 이름을 사용합니다.

| 항목 | 2점 | 1점 | 0점 |
|---|---|---|---|
| facts | 수치·시점·방향·해석이 모두 근거와 일치 | 사실은 맞고 표현만 모호 | 수치·해석 오류 또는 근거 없는 주장 |
| completeness | 핵심 요구·제약을 모두 설명 | 부가 설명 일부 부족 | 핵심 요구 누락·다른 답변 |
| clarity | 단위·기준·용어가 명확 | 장황·일부 불명확 | 이해를 막거나 오도 |
| source_limits | 출처·자료 버전·산식·한계가 확인 가능 | 근거를 찾기 어려움 | 허위 출처·한계 은폐 |
| visual | 읽기 쉽고 비교 목적·편집 요구 충족 | 가독성 일부 개선 필요 | 축·범례·종류가 의미 왜곡 |
| conversation_recovery | 맥락 유지·필요한 확인·복구 안내 | 불필요한 왕복·안내 부족 | 맥락 상실·잘못된 유도·복구 불가 |

적용하지 않는 항목만 `not_applicable`에 넣고 해당 점수는 null로 둡니다. 사실성은 N/A로 제외하지 않습니다. `evidence_notes`에 각 점수의 응답 문장 또는 화면 위치와 근거를 기록합니다. 미검수는 null이며 0점과 다릅니다. 실제 수행한 후에만 reviewer와 human_approved를 채웁니다. 틀린 응답도 검수 완료일 수 있습니다.

모든 치명 오류 의심·0점 사례와 나머지 원본 그룹별 20%(올림)는 이중 검수합니다. 자동 packet의 second_review_required는 기본 표본입니다. 0점·치명 오류는 표본 밖이어도 추가 검수합니다. second_review에 다른 사람의 동일 해시·점수·치명 오류 판정을 기록합니다. 불일치는 해결 전 보류하며 점수를 평균내서 숨기지 않습니다.

응답·질문·정답 해시 중 하나라도 바뀌면 이전 승인은 적용하지 않습니다. 데이터 검사 실패는 사람이 문장 검수를 승인해도 자동 통과로 바뀌지 않습니다. 공식 승인·제품 채택은 모델의 정성 의견이나 자동 도구의 판정만으로 대체하지 않습니다.
